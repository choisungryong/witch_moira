## 0. 요약

**사용자 결정**
- (2.16절 원문) "스킬 트리는 한 번 찍으면 못 돌리는데, 특정 챕터를 깨면 악마가 1회에 한해 리셋의 축복을 주는 걸로 하자."
- (덧붙임, 디렉터 전달) "스킬 되돌리기는 옵션으로 두고, 지금은 테스트를 해야 하니 가능하게 열어 두는 게 좋겠다."

**이 명세의 답**
1. 되돌릴 수 없음과 리셋의 축복은 **규칙 스위치 하나**로 묶는다. 자리는 `chapter1/data/character_progression.json`의 `respec` 묶음, 키 `locked`. **기본값 `false`(꺼짐)**. 꺼진 동안은 지금과 똑같이 준비 화면에서 언제든 무료 전체 초기화가 된다(1절).
2. 스위치를 켜면: 확정한 투자는 되돌릴 수 없다. 확정 전 "예정"은 지금처럼 무료로 빼고 버릴 수 있다. 확정할 때 "되돌릴 수 없습니다" 확인 창을 띄운다(2절).
3. 리셋의 축복 권고안: **마녀마다 한 번, 그 마녀로 제1장 우두머리를 처음 쓰러뜨리면 받고, 갖고 있다가 원할 때 쓴다. 쓰면 그 마녀의 트리 전체가 비고 포인트가 모두 돌아온다. 다시 얻는 길은 없다**(3절).
4. 주는 이 권고: **그 마녀의 서약 상대(어머니인 계약 악마)**. 확정은 `narrative-lead` 검수 뒤. 화면 이름에는 "축복"을 쓰지 않기를 권한다. 은총과 뜻이 겹친다(4절).
5. 트리 데이터 개정과 투자 위반 때의 무료 반환(D7-9, T5-D2)은 스위치와 무관하게 그대로다. 축복을 쓰지 않는다(5절).
6. 켜기 전에 갖출 것 다섯: 갈래마다 L6 바닥 통과, 확정 확인 창, 축복 지급·사용과 저장 필드, 기존 저장 옮김, 화면 이름·주는 이 확정(6절).
7. 스키마 4에는 **축복 필드의 자리만 지금 잡아 두기**를 권한다(`characters.<id>.tree_reset = {"granted":[], "used":[]}`). T5의 원칙 6("스키마 4 안에서는 키를 더하지 않는다")에 따라 나중에 넣으려면 스키마 5가 필요하다(7절).
8. 지금 스위치를 켤 수 없는 이유가 하나 확인돼 있다: 냉기 지대 갈래는 L6에서 빈 빌드보다 나쁘다(D7 1.2절 [확인]). 되돌릴 수 없는 규칙 아래에서는 "포인트를 쓰고 약해지는" 선택이 영구가 된다.

## 1. 규칙 스위치

### 1.1 자리 [확인한 사실 위에 제안]

| 후보 | 지금 무엇을 담나 | 누가 읽나 | 판정 |
|---|---|---|---|
| **`character_progression.json`의 `respec` 묶음**(권고) | `{"essence_per_point": 0}` 하나 [확인, 15행] | 프로필(`chapter_profile.gd` `respec_cost`, 587행 [확인])과 검증기(`character_progression.gd` 70~72행 [확인]) | 같은 일(초기화 규칙)을 이미 맡은 자리다. 영구 성장 규칙만 있는 파일이다 |
| `combat_tuning.json` | 적·구역·생성·물약·경험치·주력 보정과 전투 규칙 스위치(`secondary`, `heavy_hit` 등) [확인, 키 목록] | 실행 코어와 골든 | 맞지 않는다. 판 안의 전투 규칙 파일이고 T2-V까지 동결이다(D7 6.1). 프로필 규칙을 섞으면 골든과 무관한 변경이 동결 파일을 건드린다 |

검증기는 지금 `respec` 묶음의 다른 키를 거부하지 않는다(`essence_per_point`만 본다 [확인, 71행]). 그래도 키를 더할 때는 검증을 함께 넓힌다(8.2절 R1).

### 1.2 데이터 형식

```json
"respec": {
  "essence_per_point": 0,
  "locked": false,
  "grants": {"d1": "boss"}
}
```

| 키 | 형 | 기본 | 뜻 | 검증 |
|---|---|---|---|---|
| `essence_per_point` | int | 0 | 꺼진 동안의 초기화 비용(지금 그대로) | 0~1000(지금 그대로) |
| `locked` | bool | `false` | 켜면 확정한 투자를 되돌릴 수 없고 축복만이 되돌리는 길이다 | bool |
| `grants` | 사전 `{축복 id: 첫 처치 보상 id}` | `{"d1": "boss"}` | 어떤 첫 처치가 어떤 축복을 주는가. 축복 id는 저장에 남는 영구 id(`d1` = 제1장 던전의 축복) | 8개 이하. 키는 `^[a-z][a-z0-9_]{0,15}$`. 값은 같은 파일 `first_rewards`의 키 |

- `grants`는 스위치가 꺼져 있어도 읽고 검증한다. 축복 **기록**은 스위치와 무관하게 쌓이고(3.6절), **쓰임**만 스위치를 따른다.
- 뒤의 장(막)마다 축복을 하나씩 줄지(3.5절 질문)는 이 사전에 줄을 더하는 것으로 된다. 저장 형식은 바뀌지 않는다.
- 이 파일은 코어도 불러온다(`chapter_core.gd` 12행 preload [확인]). 다만 `respec` 묶음은 코어가 쓰지 않는다 [추정: 코어에서 `respec`을 쓰는 곳을 Grep으로 찾지 못했다]. 그래서 이 키들은 골든과 무관하다. R1 구현자가 골든으로 확인한다.

### 1.3 꺼짐과 켜짐

| | 꺼짐(`locked: false`, 기본) | 켜짐(`locked: true`) |
|---|---|---|
| 예정 투자 빼기·버리기 | 무료 | 무료(같음) |
| 확정 | 바로 저장(지금 그대로) | 확인 창 뒤 저장(2.2절) |
| 확정 뒤 전체 초기화 | 언제든, 비용 `essence_per_point × 쓴 포인트`(지금 0) | 축복이 있을 때만, 비용 없음 |
| 축복 기록(받음) | 쌓인다 | 쌓인다 |
| 축복 쓰임 | 쓰지 않는다(무료 초기화가 축복을 줄이지 않는다) | 초기화 한 번에 하나 |
| 트리 개정·투자 위반의 무료 반환 | 그대로 | 그대로, 축복과 무관(5절) |
| 화면 아래 단추 | "전체 초기화 (R)" | "다시 배우기 (R) · n" 또는 비활성(2.3절) |

## 2. 스위치를 켰을 때의 되돌리기 규칙

### 2.1 규칙

1. **예정 상태는 언제나 자유다.** 트리 화면에서 +로 올린 것은 저장하지 않은 예정이다. 빼기(Backspace·우클릭)와 버리기(Esc → 버리고 닫기)는 무료다. 지금 화면이 이미 그렇다 [확인: `skill_tree_panel.gd` `undo_selected`는 `can_refund_staged`로 확정한 랭크 아래로는 내리지 못하게 막고(173·210행), Esc는 예정이 있으면 "확정하지 않은 투자가 있습니다" 확인을 띄운다(187~190·826~829행). 검사 `skill_tree_preview.gd` 168~193행].
2. **확정한 투자는 되돌릴 수 없다.** 노드 하나를 빼는 기능은 지금도 없다 [확인: `commit_tree`가 확정 랭크보다 낮은 값을 "확정한 투자는 전체 초기화로만 되돌립니다"로 거부, `chapter_profile.gd` 576~577행]. 켜짐에서는 전체 초기화(`respec`)도 축복 없이는 거부한다.
3. **되돌리는 유일한 길은 리셋의 축복**(3절)이고, 그것은 전체 초기화다.
4. 판 중에는 열지 않는다(지금 그대로 [확인: `_open_skill_tree`는 `menu`·`victory`·`defeat`에서만, `chapter_one.gd` 520행]).

### 2.2 지금 화면에서 바꿔야 하는 것 [확인]

| 지금 | 켜짐에서 필요한 것 |
|---|---|
| F(확정)를 누르면 **확인 없이** 바로 `commit_requested`를 보낸다(`request_commit`, 182~185행. 검사 "F emits commit_requested once", `skill_tree_preview.gd` 185행) | 확인 창을 띄운다. 꺼짐에서는 지금처럼 바로 |
| 확인 창은 "버리기"와 "전체 초기화" 두 종류(`_draw_confirm`, 826~833행) | 세 번째 종류 "확정"을 더한다 |
| 아래 줄 "재 n · 초기화 비용 n"(804행) | 켜짐: "확정한 투자는 되돌릴 수 없습니다 · 다시 배우기 n회" |
| 단추 "전체 초기화 (R)", 투자가 있으면 켜짐(401·815행) | 켜짐: 축복이 있으면 "다시 배우기 (R) · n", 없으면 비활성 + 이유(받는 조건) |
| 예정 빼기의 이름이 "되돌리기"(818행 키 안내, G1 8.2 그림의 "[− 되돌리기]") | "빼기"로 바꾸기를 권한다. "되돌릴 수 없습니다"와 같은 낱말이 다른 일을 가리키지 않게 [추정: 혼동 위험은 사람 평가] |
| 노드 설명에 "지금/다음 랭크" 수치 미리보기가 있다(752~762행) | 그대로. 켜기 전 조건 6.4 |

**확정 확인 창(요지, 대사 아님)**
- 제목: 투자 확정
- 본문 요지: 이번에 확정할 노드와 랭크 목록(예: "얼음 바늘 2 → 3, 겹창 0 → 1"), 그리고 "확정한 투자는 되돌릴 수 없습니다." 축복이 있으면 "다시 배우기를 n회 가지고 있습니다", 없으면 "다시 배우기는 우두머리를 처음 쓰러뜨리면 한 번 받습니다".
- 단추: [확정] / [더 보기 (Esc)]. **기본 초점은 [더 보기]**. 지금 버리기 창이 기본 초점을 "계속 편집"에 두는 것과 같은 방식이다 [확인, 189·197행 `confirm_focus = 1`]. 열린 직후 Enter 막기(`OPEN_GUARD_MS`)를 확인 창에도 적용한다.
- 글은 T3 규칙대로 `ko.po` 키로 둔다(`tree.confirm_commit.*`). 지금 패널 글은 코드에 박혀 있다 [확인]. 옮기는 일은 A4 U5와 T3의 몫이다.

**다시 배우기 확인 창(요지)**: "확정한 n포인트를 모두 돌려받습니다. 다시 배우기는 이 마녀에게 한 번뿐이고, 쓰면 다시 얻을 수 없습니다." 단추 [다시 배우기] / [취소 (Esc)], 기본 초점 [취소].

### 2.3 스킬 트리 화면의 경고

- 켜짐에서는 아래 줄에 늘 "확정한 투자는 되돌릴 수 없습니다"를 둔다. 처음 한 번만 보이는 안내 대신 늘 보이게 하는 이유: 한 번 보이는 안내는 "봤는가"를 저장해야 하고(키가 하나 는다), 다시 켜고 끄는 경우를 따로 다뤄야 한다.
- 결과 화면과 메뉴의 "스킬 트리 ◆n" 표시는 그대로다.

## 3. 리셋의 축복

### 3.1 (가) 무엇이 주는가 — "그 챕터"

제품 범위는 제1장(던전 D1) 하나다. 뒤의 막은 `ACT-STRUCTURE`에만 있다 [확인].

레벨 시점은 G1 2.2절의 승리만 기준: Lv 4 = 1판, Lv 6 = 2~3판(2단), Lv 12 = 8판(3단), Lv 20 = 25판 [확인, G1 곡선. 실제 판 수는 시뮬레이션 가설].

| 안 | 주는 일 | 지금 제품에서 처음 받는 때 | 플레이어가 처음 실수를 고칠 수 있는 때 | 장점 | 약점 |
|---|---|---|---|---|---|
| **A(권고)** 제1장 우두머리 첫 처치(마녀별) | 첫 처치 보상 `boss`를 처음 받는 판 | 그 마녀의 첫 승리. 보통 1~3판 [추정] | 받은 직후부터 언제든. 실수가 실제로 드러나는 2단(Lv 6)·3단(Lv 12) 뒤에 쓸 수 있도록 갖고 있게 한다(3.3) | 지금 제품 안에서 성립한다. 서사의 박자 "D1 첫 완료, 어머니의 뜻을 알 수 없는 반응 하나"(`ACT-STRUCTURE` 3.2 박자 1)에 붙는다. 영수증 `boss`가 이미 마녀별로 있다 [확인, G1 2.1, T5 5.2] | 받는 때가 일러서 "한 번 찍으면 못 돌린다"의 무게가 첫 몇 판 동안만 크다 |
| B 1막의 마침표 D2 첫 처치 | D2 우두머리 | 지금 제품에서는 **없다** | 제1장만 있는 동안 영영 없다 | 1막이 끝나는 사건(N27)과 맞는다 | 제1장만으로 Lv 20(22포인트)을 다 쓰는데 그동안 고칠 길이 없다 |
| C 4막 결전 뒤(계승) | 어머니와의 결전 승리 | 없다 | 시즌 거의 끝 | 이어받은 권능을 "다시 고른다"는 뜻이 서사와 맞는다(법 9.3 "계승 단이 열린다") | 1~3막 동안 고칠 길이 없다. 축복이 아니라 계승의 일부가 된다 |
| D 제1장 반복 깊이(균열 깊이 2 등, D6-E) | 깊이 2 첫 승리 | 깊이 기능이 생긴 뒤 | 수십 판 뒤 [추정] | 파밍 목표가 하나 는다 | "챕터를 깨면"과 다르다. 깊이 기능이 아직 없다 |

권고 A. 데이터 `grants: {"d1": "boss"}`로 둔다. 뒤에 던전이 늘어 "그 챕터"를 옮기더라도 이미 받은 축복 기록(`granted`)은 남는다(받은 것은 빼앗지 않는다).

### 3.2 (나) 마녀마다 한 번인가, 계정에 한 번인가

| 안 | 장점 | 약점 |
|---|---|---|
| **마녀마다 한 번(권고)** | 트리·랭크·첫 처치 영수증이 모두 마녀별이다 [확인: `characters.<id>`의 `ranks`, `first_rewards`]. 세 어머니가 각자의 딸에게 주는 것이라 설정과 맞는다(4절). 세 번째 마녀를 시작할 때도 같은 안전판이 있다 | 계정 전체로 보면 세 번 |
| 계정에 한 번 | "1회"를 글자 그대로 지킨다 | 어느 마녀가 쓸지 고르는 일이 생기고, 세 세계의 다른 어머니가 한 사람에게 주는 셈이 되어 설정과 어긋난다. 두 번째 마녀부터는 안전판이 없다 |

"1회에 한해"는 마녀 한 사람 기준으로 읽는다. 사용자 확인이 필요하다(9절 표 3번).

### 3.3 (다) 받으면 바로 쓰이는가, 갖고 있는가

**권고: 갖고 있다가 원할 때 쓴다.** 바로 쓰이면(받는 순간 자동 초기화) 첫 승리 때 Lv 4·6포인트를 돌려받는 것뿐이라 쓸모가 거의 없다. 실수는 2단(Lv 6)이나 3단(Lv 12)을 열어 본 뒤에야 드러난다 [추정]. 기한은 두지 않는다(기한이 있으면 "써야 하나" 하는 압박이 새로 생긴다).

위험: 끝까지 아껴 두고 안 쓰는 사람이 생긴다. 그래도 손해는 없다(안전판이 남아 있다는 안심이 그 몫이다). 사람 평가 질문으로 남긴다(6.6절).

### 3.4 (라) 전체인가 갈래 하나인가

**권고: 전체 초기화.** 지금 `respec`이 이미 전체 초기화다 [확인, 591~602행]. 갈래 하나만 빼면 (1) 4단 "깊은 서약"의 `min_spent: 15`가 깨질 수 있고 [확인, `skill_trees.json`], (2) 공용 갈래의 선행(`ward`는 `vigor` 2 필요)처럼 연쇄 반환 규칙을 새로 만들어야 하고, (3) 확인 창이 "무엇이 함께 빠지는가"를 설명해야 한다. 한 번뿐인 기회에 전체가 더 단순하고 더 관대하다.

### 3.5 (마) 다시 얻는 길

사용자 결정 "1회에 한해"를 그대로 따른다. 마녀마다 쓰면 끝이고, 다시 얻는 길은 없다. 재(`essence`)로 사는 길도 두지 않는다.

**질문으로만 올린다**: 뒤의 장(막)이 생길 때 장마다 한 번씩 줄 여지를 둘 것인가. 데이터 `grants`에 줄을 더하면 되므로 지금 정하지 않아도 저장 형식은 그대로다. 4막 결전 뒤에 레벨 상한이 오른다면(`ACT-STRUCTURE` 3.5 "레벨 상한 상승") 그때 새 포인트를 어떻게 다룰지와 함께 정하기를 권한다.

### 3.6 받는 때와 쓰는 때의 세부

- **받기**: 판이 끝나 `record_run`이 첫 처치 `boss`를 그 마녀의 `first_rewards`에 처음 넣는 **같은 한 번의 쓰기**에서 `tree_reset.granted`에 `"d1"`을 더한다. 영수증이 같으면 아무것도 하지 않는 지금 규칙 [확인, G1 6.5]과 "id가 이미 있으면 더하지 않음"이 겹으로 중복을 막는다.
- **채워 읽기**: 읽을 때 `grants`의 각 줄에 대해 `first_rewards`에 그 보상 id가 있고 `granted`에 축복 id가 없으면 더한다(메모리만, 다음 정상 저장 때 파일에 쓰인다. T5 원칙 4). 그래서 스위치가 꺼진 동안 받기 코드가 아직 없더라도, 나중에 켜는 날 이미 우두머리를 잡은 마녀는 축복을 갖고 있다. 받기가 어떤 경로로 일어나든 결과가 같다.
- **가진 수** = `granted` 가운데 `used`에 없는 것의 수. 저장하지 않고 계산한다(T5 원칙 2).
- **쓰기**(`use_tree_reset`, 켜짐에서만): 투자가 있고 가진 수 ≥ 1이면 한 번의 `_persist`로 `ranks = {}`, `respecs += 1`, `used`에 가장 먼저 받은 축복 id 하나를 더하고, `tree_revision`을 지금 값으로. 재는 건드리지 않는다.
- 꺼진 동안의 무료 초기화(`respec`)는 `tree_reset`을 건드리지 않는다.
- `respecs`(옛 키)는 "전체 초기화를 한 횟수"의 통계로만 남는다. 꺼진 동안의 초기화와 축복 사용을 모두 센다. **가진 축복을 계산하는 데 쓰지 않는다.** 지금 사용자 저장에 이미 `respecs` > 0이 있을 수 있다 [추정: 옛 저장 고정 묶음 `v3_full.json`에 `respecs: 1`이 있다, 확인].

### 3.7 화면에 뜨는 것(요지, 대사 아님)

- 받는 순간: 결과 화면(승리)의 성장 칸에 한 줄 "다시 배우기를 받았습니다 · 스킬 트리에서 한 번 쓸 수 있습니다". 켜짐에서만 보인다. 꺼짐에서는 기록만 하고 알리지 않는다(쓸 데가 없는 것을 알리지 않는다).
- 서사 쪽 한 줄(어머니의 반응)을 같은 순간에 붙일지는 `narrative-lead`가 D1 첫 완료 사건 화면과 함께 정한다. 번개의 어머니는 목소리가 없다(법 4.1). 그 마녀에게는 소리·빛의 신호로만.

## 6. 켜기 전에 갖춰야 할 것(되돌릴 수 없음이 만드는 설계 요구)

### 6.1 갈래마다 최소한의 쓸모 — 켜는 관문

- D7 7.2절의 내부 기준 **"L6의 바닥: 모든 갈래 L6이 세 지표(처치 시간, 수호자 교전, 받은 피해) 모두 L1 이하"**를 세 마녀·모든 갈래에서 통과해야 켠다. 지금 냉기 지대 L6은 처치 시간 1.11, 수호자 1.10, 받은 피해 1.15로 **위반**이다 [확인, D7 1.2절 표. 지대 L6을 내가 다시 돌리지는 않았다].

### 6.5 포인트 총량 — 선택이 순서의 문제가 되는가

[확인] Lv 20의 총 포인트는 19 + 첫 처치 3 = **22**(G1 2.1, `character_progression.json`). 냉기 트리의 랭크 합은 **42**(13노드, `skill_trees.json`을 직접 합산). 화염·번개 초안은 44(D7 4.0, 데이터 없음).

- 제1장에서 채울 수 있는 것은 트리의 약 52%다. 한 갈래를 끝까지(냉기 관통 5+3+3 = 11) 채우면 나머지 11로 두 번째 갈래를 채우거나 공용과 4단(15포인트 이상 투자 뒤 1)을 고른다. **선택은 순서가 아니라 진짜 선택이다.** 되돌릴 수 없음이 실제 무게를 갖는다.
- 막히는 길은 없다 [확인, 데이터]: 선행은 모두 "앞 노드 랭크 2"이고 4단은 어느 갈래든 합 15면 열린다. 어떤 순서로 찍어도 다음에 찍을 수 있는 노드가 남는다(22 < 42).
- 뒤의 장에서 레벨 상한이 오르면(4막) 트리 전체에 가까워질 수 있다. 그때는 선택이 순서의 문제가 되어 이 규칙의 무게가 준다. 3.5절 질문과 함께 정한다.

- **선택이 하나뿐인 지점**: 되돌릴 수 없으면 사람은 안전한 갈래(공용 생존, 수호자 담당 집중)로 몰린다(D7 9절의 위험이 커진다). 사람 평가.
- **보상이 없는 긴 구간**: 해당 없음(이 규칙은 보상을 줄이지 않는다).
- 첫 승리 전(패배 판으로 Lv 2~3) 찍은 1~2포인트는 축복을 받기 전이라 고칠 수 없다. 작다 [추정].
- 꺼진 빌드(옛 실행본)로 같은 저장을 열면 무료 초기화가 된다(7.4절). 혼자 하는 오프라인 게임이라 막지 않는다.

## 7. 저장

### 7.1 스키마 4에 자리를 미리 잡을 것인가 — 의견: **잡는다**

- T5 원칙 6 "스키마 4 안에서는 키를 더하지 않는다. 키가 바뀌면 스키마 5다. 그래서 필요한 자리를 이번에 한 번에 연다" [확인, T5 2절]. 마녀 항목의 키 집합은 정확히 맞춰 검사한다(T5 4.4, 6.1 "마녀 항목 키 집합이 다름 → 거부").
- 지금 넣지 않으면 스위치를 켜는 날 스키마 5가 필요하다. 넣는 비용은 기본값 하나와 형식 검사, 옮김 기본값, 왕복 검사 하나다.
- S1은 **자리와 검증만** 넣는다. 받기·채워 읽기·쓰기 함수는 R1(8.2절)에서 한다. 자리만 있는 동안 값은 언제나 기본값이고 화면은 읽지 않는다(T5 4.4의 `depth_cleared`·`story` 자리와 같은 대우).

### 7.2 필드

`characters.<id>.tree_reset`

| 키 | 형 | 기본 | 쓰는 곳 | 검증(읽기 너그럽게 / 쓰기 엄격하게) |
|---|---|---|---|---|
| `granted` | 문자열 배열 | `[]` | `record_run`(첫 처치와 같은 쓰기), 읽을 때 채우기(3.6) | id 형식(`^[a-z][a-z0-9_]{0,15}$`), 16개 이하. 중복은 고쳐 읽기(하나만). 모르는 id는 보존(T5 원칙 5) |
| `used` | 문자열 배열 | `[]` | `use_tree_reset` | 같은 형식·개수. **`used`에 있고 `granted`에 없는 id는 고쳐 읽기로 `granted`에 더한다**(축복이 늘지 않는 쪽으로 고친다). 쓸 때는 `used ⊆ granted`가 아니면 거부 |

- 보고 키(`read_report`): `tree_reset_fixed`.
- 영수증 방식: 축복은 id로 기록되므로 같은 id는 두 번 들어가지 않는다. 판 영수증(`receipts`)이 같은 판의 두 번 기록을 막고, 축복 id 집합이 서로 다른 판의 두 번 지급을 막는다.
- 레벨·포인트처럼 "가진 수"는 저장하지 않는다(T5 원칙 2).

### 7.3 기존 저장 옮김

| 원본 | `tree_reset` | 결과 |
|---|---|---|
| v3, 그 마녀의 `first_rewards`에 `boss` 있음 | 기본값 → 읽을 때 채우기로 `granted: ["d1"]` | 스위치를 켜면 축복 하나를 가진 채 시작. 그 마녀가 우두머리를 또 잡아도 더 받지 않는다 |
| v3, `boss` 없음(투자가 있어도) | 기본값 | 우두머리를 처음 잡으면 받는다 |
| v2·v1 | 기본값(첫 처치 영수증은 옮기지 않는다, G1 6.2 [확인]) | 다음 우두머리 처치가 "처음"으로 세어져 받는다 |
| `respecs` | 그대로(통계) | 축복 수와 무관 |

다른 안(권하지 않음): 옮길 때 투자가 있는 모든 마녀에게 축복을 준다. "꺼짐 시절에 찍은 것"을 한 번 고칠 기회라는 뜻은 좋지만, `boss` 없는 마녀가 뒤에 우두머리를 잡으면 두 번째가 생긴다(1회 규칙 위반). 이를 막으려면 그 지급을 `d1`로 기록해야 하고, 그러면 위 권고안과 같은 결과가 된다. 투자가 있는데 `boss`가 없는 마녀는 드물다 [추정: 포인트 대부분이 레벨에서 오고 첫 승리 전 레벨은 2~3이다].

### 7.4 스위치를 오갈 때

| 바뀜 | 처리 |
|---|---|
| 꺼짐 → 켜짐(데이터 개정을 받은 첫 실행) | 지금의 투자가 그대로 확정 상태가 된다. 무료 반환은 없다. `boss`를 가진 마녀는 축복 하나를 가진다(채워 읽기). 트리 화면 아래 줄의 경고가 늘 보인다 |
| 켜짐 → 꺼짐 | 다시 언제든 무료 초기화. `granted`·`used`는 그대로 남는다. 무료 초기화는 축복을 쓰지 않는다 |
| 켜짐 → 꺼짐 → 켜짐 | 축복 id 집합 때문에 새로 생기지 않는다. 이미 쓴 축복은 쓴 채로 남는다. 꺼진 동안 찍은 투자는 다시 켤 때 확정 상태다 |
| 켜짐 저장을 꺼짐의 옛 실행본(같은 스키마 4)으로 열기 | 옛 실행본은 `tree_reset`을 읽기만 하고 무료 초기화를 허용한다. 막지 않는다(오프라인 단일 플레이어) |
| 스키마 4 이전 실행본 | v4 파일을 읽지 않는다(T5 3절, 파일이 다르다) |

스위치는 데이터 값이고 저장에 기록하지 않는다. 그래서 "언제 켜졌는가"에 기대는 규칙(켜진 순간의 일회 지급, 일회 안내)을 두지 않았다. 위 표의 모든 처리가 그 원칙에서 나온다.

### 8.3 검사(이름과 경우)

프로필(격리 경로만):
- **P1** 스키마 4 왕복: 기본값 `tree_reset`이 쓰기 검사를 통과하고 다시 읽어 같다.
- **P2** 고쳐 읽기: `granted` 중복 → 하나만. `used`에만 있는 id → `granted`에 더해져 가진 수 0. `tree_reset` 키가 없거나 형이 다름 → 거부(마녀 항목 키 집합). 모르는 id → 보존. 읽은 결과가 엄격 쓰기 검사를 통과(T5 불변식).
- **P3** 꺼짐: 지금의 G1 6.6 검사 10번(재 비용·거부·0 비용)이 그대로 통과. 무료 초기화 뒤 `tree_reset` 불변.
- **P4** 켜짐, **확정 뒤 환불 거부**: `commit_tree`로 낮춘 랭크 거부(지금 그대로), 축복 없이 `respec`·`use_tree_reset` 거부, 파일 바이트 그대로.
- **P5** 켜짐, **축복 한 번만 지급**: 같은 영수증으로 `record_run` 두 번 → `granted` 하나. 서로 다른 두 판에서 우두머리 처치 → `granted` 하나.
- **P6** 켜짐, 사용: 축복 1 → 쓰면 `ranks` 빔, `used: ["d1"]`, `respecs` +1, 재 그대로. 두 번째 사용 거부.
- **P7** **재실행 중복 없음**: 사용 뒤 새 인스턴스로 다시 읽어 가진 수 0. 받기 뒤 다시 읽어 가진 수 1(채워 읽기가 둘로 만들지 않음).
- **P8** **손상 저장 중복 없음**: `granted`를 늘리는 쪽의 손상(중복 id, 형식이 틀린 id, `used`에만 있는 id)이 가진 수를 늘리지 않는다. 손으로 `used`를 지운 파일은 축복이 되살아나지만 막지 않는다(9절 13번). 이 검사는 그 경우를 다루지 않는다.
- **P9** 다른 실행이 먼저 저장한 뒤 `use_tree_reset` 거부(지금 "다른 실행" 검사와 같은 방식). 거부 뒤 파일은 사용 전 상태.
- **P10** 켜짐 + 트리 개정: 투자 무료 반환, 알림, `tree_reset` 불변.
- **P11** 켜짐 + 투자 위반(T5-D2): 반환, `tree_reset` 불변.
- **P12** 옮김: `v3_full` 고정 묶음(S0)에서 `boss`가 있는 마녀는 가진 수 1, 없는 마녀 0. 읽기만으로 파일이 생기지 않음. 꺼짐 → 켜짐 → 꺼짐 → 켜짐을 데이터 시험 훅으로 돌려 `granted`가 늘지 않음.

화면(`skill_tree_preview.gd`):

- **U2** 켜짐: F가 확인 창을 연다. 기본 초점 [더 보기]. 열린 직후 Enter는 아무것도 안 함.
