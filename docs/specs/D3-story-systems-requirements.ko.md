# D3 스토리가 시스템에 요구하는 것 — 요구 목록과 크기 어림

2026-11-16 · 작성: 기획 책임자(design-lead) · 읽을 사람: 총괄 디렉터, `narrative-lead`, `tech-lead`
**이 문서는 명세가 아니다.** 서사 결정이 시스템에 무엇을 요구하는지 항목별로 적고, 지금 구현에서 "이미 있는 것 / 조금 고치면 되는 것 / 새로 필요한 것"으로 나누고, 크기를 어림했다. 서사의 뜻은 정하지 않았다. 구현 지시는 항목마다 따로 명세를 쓴 뒤 디렉터가 낸다.

## 1. 저장에 관해 먼저 알아야 할 두 가지

이 둘이 아래 여러 항목의 크기를 정한다.

### 1.1 캐릭터 항목의 키가 정확히 다섯 개로 묶여 있다

`chapter_profile.gd` `normalize_v3`(197~235행)는 `characters[id]`의 키가 정확히 `xp, tree_revision, ranks, first_rewards, respecs`인지 검사하고(`keys_match`), 하나라도 다르면 **파일 전체를 거부**한다. 수집품·본 장면·결전 완료 같은 새 기록을 이 항목에 더하면, 새 키가 없는 지금의 v3 파일을 읽을 수 없게 된다.

선택지는 둘이다.
- **(가) 스키마 4.** 새 파일(`chapter-one-profile-v4.json`)에 쓰고, v3은 읽기만 한다. 지금 v2·v1을 다루는 방식과 같다. 깔끔하지만 이관 경로가 하나 더 생긴다.
- **(나) v3 안에서 선택 키.** 읽을 때 새 키가 없으면 빈 값으로 채우고, 쓸 때는 항상 넣는다. 파일 이름이 그대로다. 대신 "v3 파일인데 키 집합이 둘"이 된다.

서사 기록을 처음 더할 때 한 번에 묶는 것을 권한다. 기록이 생길 때마다 스키마를 올리면 이관 경로가 계속 는다. 아래 2·3·7·8절의 저장 요구를 한 번에 설계한다(11절 결정 1).

### 1.2 장비의 이름과 설명이 저장 검증에 들어간다

`loot.gd` `validate`(242~287행)는 저장된 장비의 이름을 데이터의 이름과 맞춰 본다. 고유 장비는 이름·설명이 정확히 같아야 하고(259행), 희귀·마법은 접두·접미·기본 이름으로 다시 조합한 이름과 같아야 한다(283~287행). 그리고 `chapter_profile.gd` `normalize`는 장비 하나라도 검증에 실패하면 **프로필 전체를 거부**한다(179행).

즉 `loot.json`의 이름을 하나만 바꿔도(예: 고유 반지 "갈림길의 서약", 접미 "이삭", 기본 "재의 두건", 희귀 이름표의 "서약") **사용자의 저장 파일 전체를 읽을 수 없게 된다.** 용어 정리(6절)가 장비 이름에 닿는 순간 이 문제가 된다. 해결은 둘 중 하나다.
- 저장된 장비에서 이름·설명을 검증 대상에서 빼고, 화면에 보일 때마다 id(`base_id`, 접사 `id`, `legendary_id`)로 다시 짓는다. 코어 검사와 프로필 검사를 함께 고쳐야 한다(M).
- 옛 이름 → 새 이름 표를 두고 읽을 때 바꿔 쓴다(S~M. 표가 계속 자란다).

`chapter_items.gd`(장비 v1)의 "갈림길의 서약"은 옛 저장 검증용이라 건드리지 않는다.

## 5. 본래의 속성 악마(U16·U17)와 지금의 보조 기술 규칙

결정: 판 안에서 다른 속성 기술을 쓰는 것은 그 세계의 **본래의 속성 악마**가 빌려준 힘이다. 서약이 아니라 그 판에 한한 거래다(U16). 본래 악마는 세 세계에 걸쳐 같은 셋이고, 각 세계에서는 그 세계의 속성 자리를 어머니가 차지한다(U17).

### 5.1 대응표

| 서사 | 지금의 규칙 | 맞는가 |
|---|---|---|
| 마녀의 속성 = 어머니의 속성 | 주력 기술(`_primary_id`). 영구 트리는 주력에만 걸린다(`_apply_build_skill`, 615행) | 맞다 |
| 다른 두 속성 = 그 세계에 나오는 본래 악마 둘 | 보조는 언제나 주력이 아닌 두 기술이다(`_mark_owners`, 131~134행). 최대 동시 기술 3 | **구조가 그대로 맞는다.** 세계마다 나오는 본래 악마 둘 = 주력 아닌 두 속성 |
| 거래를 맺음(판마다 새로) | 은총 카드 `unlock:<다른 기술>` | 맞다. 판이 끝나면 사라진다(판 안 성장) |
| 거래가 깊어짐 | `rank:`·`evolve:` 카드(다른 기술) | 맞다 |
| 어머니의 은총 | 주력의 `rank`·`evolve`·`passive` 카드 | 맞다. 은총 화면 한 장에 두 출처가 섞여 나온다 → 4절의 "말하는 이" 구분이 필요하다 |
| 남의 힘은 다 쓸 수 없다 | 보조 감쇠(`secondary`), 보조 기여율 상한 0.30(`QUALITY-TARGETS` 2절), 주력 보정은 주력에만 | 맞다. CONTRACT-LAW 1.4가 이 제한에 설정상의 이유를 붙였다 |
| 보조의 역할 | 표식 공명: 보조가 표식을 남기고 주력이 그것을 터뜨린다 | 설정과 충돌하지 않는다. "남의 불이 표시하고 어머니의 불이 끝낸다"로 읽힌다(뜻은 narrative-lead) |
| 거래의 값(그 판에 쌓인 힘의 몫) | 없다 | CONTRACT-LAW 결정 ⑦(잠정), "화면에 보일지는 기획 담당이 정한다" |
| 결전 뒤에도 거래는 계속 | 판 규칙은 결전과 무관 | 맞다 |
| 결전 중 거래 허용 | — | 정해지지 않았다(CONTRACT-LAW 6.1, 9절) |

### 5.2 기획 책임자 의견: 거래의 값을 규칙으로 만들지 않는다

- 지금 보조 카드는 약하다. 번개 판의 보조 기여율이 목표 하한에 걸려 있고(`D1-arc-secondary-spec.ko.md`), 보조를 고르는 이유를 만드는 것이 진행 중인 과제다. 값(예: 거래 중 경험치 획득 −n%, 판 끝 경험치 차감)을 붙이면 보조를 고를 이유가 다시 줄어든다. 선택이 사실상 "주력만 올린다" 하나가 된다.
- 권고: 값은 **글로만** 보인다(거래 카드의 한 줄, 판 끝 결과 창의 한 줄). 수치는 붙이지 않는다. 11절 결정 4.

## 8. 악마신 결전의 입장 조건

결정(U5): 한 캐릭터가 어머니와의 결전을 끝내면 입장, 세 캐릭터 모두 끝내면 진 엔딩.
