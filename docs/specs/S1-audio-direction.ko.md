# S1 — 소리 방향 문서

2판 · 2026-11-17 · 작성: 소리 책임자(`audio-lead`) · 대상: `sound-designer`(제작·연결), `tech-lead`(구조 검수), `manager-tools`(관리 툴), `art-lead`(A5 순서표), `design-lead`(전투 리듬·득템), `narrative-lead`(목소리·마녀 층) · 판정: 총괄 디렉터 · 청취 판정: 사용자

기준 문서: `docs/AUDIO-PLAN.ko.md`. 후보 조사: `docs/reviews/AUDIO-SOURCES-20261117.ko.md`.

**이 문서를 쓴 쪽은 소리를 들을 수 없다.** 사실은 잰 것과 읽은 것뿐이다. 팩의 질은 "좋다"고 적지 않고 사양과 근거만 적는다. 귀로만 아는 것은 "미평가"다.

표기: [잼] 직접 잰 값 · [읽음] 코드·문서를 읽어 확인 · [모형] 실제 코어 + 재생 규칙을 옮긴 모형으로 셈 · [요구] 이 문서가 정하는 값.

## 0. 디렉터용 요약

1. **재료**: 지금 22개는 버린다(사용자 판정). 권하는 1안은 **Epic Stock Media "Fantasy Game 2"(유료, $54~$99) + Sonniss GDC 2026 묶음(무료)** 두 벌, 음악은 사람이 만든 itch.io 다크 판타지 팩 하나. 2안은 0원(Sonniss GDC 2026·2024 + Freesound CC0). 두 안 모두 사람 녹음이라 스팀 AI 공개가 필요 없다. 판단 근거와 모자란 점은 2.3절. 구매 전에 EULA 원문을 사람이 읽어야 한다(조사 문서가 본문을 읽지 못함).
2. **타격감 사양**(3절): 명중·처치·큰 한 방·폭발·주인공 피격·큰 순간을 4~5층으로 쌓는다. 공통: 소리 시작부터 가장 큰 표본까지 **5ms 이하**(옛 화염 시전은 315ms였다), 첫 층은 1~8kHz 짧은 어택 5~20ms, 무게 층은 40~150Hz에 배음을 300Hz까지. 군중에서는 같은 틱을 한 번으로 묶되 **맞힌 수가 두 배가 될 때마다 무게 층 +2dB(최대 +8dB)와 길이 +10%**.
3. **배치표**(4절): 타이틀부터 결과 화면까지 순간 **69개**(줄 하나에 하나). 소리를 거는 것 62, 일부러 소리를 내지 않는 "무음" 10곳(조건부 1 더). 음악 상태 8과 환경음 상태 3이 같은 표에 있다. 코어 이벤트 38종이 모두 표에 있다. 코어에 이벤트가 없어 지금 걸 수 없는 것은 "보류" 3줄.
4. **한 곳에서 조절**(5절): `chapter1/data/audio_map.json` 하나. 코드 안의 대응표(`chapter_one.gd`의 `match` 두 곳, `combat_audio.gd`의 상수 셋)를 없앤다. 관리 툴에서 표 보기·듣기·고치기(`manager-tools` 요구 M-A1~M-A6).
5. **다음 지시**: SD1 = 데이터 표와 재생기 정리(옛 22개를 임시로 꽂아 지금과 같은 재생 수가 나오는지로 검증). SD2 = 팩이 승인·도착하면 타격 묶음 하나(열두 개 + 군중 10초).
6. **사용자가 승인할 것**: 팩(1안 또는 2안)의 내려받기·결제, Freesound 가입(2안·보충용), 음악 팩 결제. 목록은 11.3절.

## 3. 타격감 사양 [요구]

### 3.1 층 쌓기 — 공통 문법

타격 소리는 아래 층을 쌓아 만든다. "층 = 파일 하나". 층의 파일은 팩의 같은 범주에서 고른다(2.2절).

| 층 | 역할 | 대역(에너지 70% 이상이 이 안) | 길이 | 어택 | 시작 시각 | 음량(어택 층의 최대 기준) |
|---|---|---|---|---|---|---|
| A 어택 | 맞는 순간의 날 | 1~8kHz | 5~20ms | ≤1ms | 0ms | 0dB(기준) |
| B 몸통 | 무엇이 맞았는지(살·뼈·돌·갑옷) | 200Hz~2kHz | 60~150ms | ≤5ms | 0~5ms | −3~0dB |
| C 무게 | 묵직함 | 40~150Hz, 배음을 150~300Hz에 둠(노트북·휴대폰 스피커는 100Hz 아래를 거의 못 냄) | 80~200ms | ≤10ms | 0~10ms | −6dB(1마리) → 3.4절로 커짐 |
| D 계열 꼬리 | 화염·냉기·번개가 갈리는 곳 | 3.2절 | 80~300ms | — | 10~30ms | −9~−6dB |
| E 부서짐(처치·큰 한 방) | 몸이 깨짐 | 300Hz~3kHz | 100~250ms | ≤5ms | 20~40ms | −6~−3dB |

완성본에 대한 측정 기준:
- 소리 시작(첫 표본)부터 가장 큰 표본까지 **≤ 5ms**. 앞 무음 ≤ 1ms.
- 최대 대 RMS 비(크레스트) **≥ 12dB**(어택이 뭉개지지 않았는지). 
- 150Hz 아래 에너지 **15~40%**(무게가 있되 다른 대역을 덮지 않게). 1kHz 위 **25% 이상**(작은 스피커에서도 들림).
- 잘림 0, 참 최대 ≤ −1dBTP(파일 단계).
- 가져오기: 타격 묶음은 Godot 가져오기 압축을 끈 판과 QOA 판을 둘 다 재서 어택 첫 5ms의 최대값 차가 1dB를 넘으면 압축을 끈다(확인 필요, 11.1 D-S11).

미리 섞기와 실행 때 쌓기:
- **자주 나는 소리(명중·처치·시전)**: A+B+D(+E)는 미리 섞은 파일 하나, **C(무게)만 따로** 둬서 실행 때 맞힌 수로 키운다 → 한 번에 목소리 2개.
- **드문 소리(큰 한 방·폭발·주인공 피격·큰 순간)**: 층을 데이터 표에서 실행 때 쌓는다(층마다 음량·시간 차를 표에서 고침) → 목소리 3~5개.

### 3.2 세 계열의 꼬리(D층)와 시전

세 잣대(스펙트럼 중심·어택·꼬리 모양)가 동시에 달라야 한다. 1판 5.1절의 값을 그대로 쓰고 D층과 시전에 적용한다.

| | 화염 | 냉기 | 번개 |
|---|---|---|---|
| D층 대역 | 1~5kHz 타닥 낱알(3~10ms) 초당 8~20개 + 150~600Hz 불길 숨 | 3~8kHz 유리·얼음 울림(정수배가 아닌 배음 2~3개) | 2~10kHz 지직거림 + 짧은 리버브(−20dB에서 시작) |
| D층 길이 | 150~300ms | 100~250ms | 80~200ms |
| 시전 | 불붙음·휙: 어택 10~30ms, 중심 500~1,200Hz, 0.25~0.4s | 얼음 결정 맺힘: 어택 ≤5ms, 중심 2.5~5kHz, 0.2~0.35s | 방전 크랙: 어택 ≤2ms, 첫 30ms 중심 1.5~4kHz, 0.15~0.3s |
| 명중 B층 | 살·천이 타는 몸통(200Hz~1.5kHz) | 얼음이 박히는 몸통(500Hz~3kHz) | 짧은 몸통(300Hz~2kHz) + 근육 경련 같은 떨림은 쓰지 않음 |
| 폭발 | 3.3절 | 파쇄: 깨짐 낱알 여러 개가 20~40ms 안 | 연쇄: 크랙이 30~60ms 간격으로 반복 |

시전은 명중보다 작게(6.2절). 시전은 판 내내 초당 3~6번 나므로[모형] 타격의 자리를 뺏지 않는다.

### 3.3 순간별 층

| 순간 | 걸이 | 층 | 길이 | 목표 M최대(6.2 기준) | 화면과의 맞춤(A5) |
|---|---|---|---|---|---|
| **명중** | `hit`(계열별, 3.4절 묶음) | A+B+D 미리 섞음 + C | 0.1~0.25s | 1마리 −27~−24, 묶음 최대 −21 | 일반 명중은 멈춤·흔들림 없음(A5 5.1). 피해 숫자와 같은 프레임 |
| **처치** | `death`(묶음) | A+B+C+E(+D 짧게) | 0.2~0.4s | 1마리 −26~−23, 묶음 최대 −20 | 처치 입자와 같은 프레임 |
| **정예 처치** | `death`(`elite`) | 처치 + C +3dB, 길이 +50% | 0.4~0.6s | −22~−19 | 바닥 자국과 같은 프레임 |
| **큰 한 방**(치명 대신, 3.5절) | 표현 쪽 판정 | A+B+C(+3dB)+D+E + 서브 낙하(50~80Hz, 250~400ms, 음높이 −3~−5반음) | 0.3~0.5s | −21~−18 | 큰 숫자(`HEAVY`)와 같은 프레임. 초당 4번 이하 |

| **냉기 파쇄** | `shatter` | A(2~8kHz) + 깨짐 낱알 5~10개(20~40ms 안) + C −9dB | 0.3~0.5s | −23~−20 | 지금 파쇄에 카메라 흔들림 `.22`가 있다(`combat_juice.gd`) — 흔들림 첫 프레임 |
| **주인공 피격** | `hero_hit` | A(2~5kHz, 10~20ms) + B(400Hz~2kHz 살·천·가죽 80~150ms) + C −6dB + 목소리 V2(2초에 1번 이하). 150Hz 아래 ≤ 25% | 0.15~0.3s | −21~−18 | 흔들림 3px(A5 5.1)의 첫 프레임 |
| **주인공 스침** | `hero_hit`(`graze`) | 피격의 A+B만, −6dB | 0.1~0.2s | −27~−24 | 회색 섬광과 같은 프레임 |

멈춤(히트스톱)의 방식은 A5 9절 D-3에서 아직 정하지 않았다. 어느 쪽이든 **소리는 멈춤 동안 멈추지 않는다**. 멈춤의 시작 프레임에 한 방이 온다.

### 3.4 군중 묶음 — 묶인 한 번을 더 무겁게

| 규칙 | 값 |
|---|---|
| 같은 틱 | 같은 틱의 `hit`는 계열별로 **한 번**. `death`는 일반 한 번(정예는 따로). `explosion`·`shatter`는 계열별 한 번. 같은 틱은 모두 이미 알고 있으므로 지연 없이 그 프레임에 낸다 |
| 최소 간격 | 같은 묶음 소리는 50ms(3틱). 간격 안에 온 것은 모아서 간격 끝에 한 번(지연 ≤ 50ms) |
| 수 n에 따른 무게 | C층: n이 두 배가 될 때마다 **+2dB, 최대 +8dB**(n ≥ 16), C층 길이 +10%씩 최대 +40%. 미리 섞은 층(A+B+D): +1dB씩 최대 +3dB. n ≥ 8이면 몸통이 두꺼운 변주(별도 파일 2개)로 바꿈 |
| 음높이 | 수로 바꾸지 않는다. 무작위 ±3%(표현 쪽 난수, 코어 RNG 아님) |
| 변주 | 바로 앞 것을 빼고 무작위 |
| 초당 상한 | 명중 묶음 계열마다 8, 처치 묶음 6, 폭발·파쇄 계열마다 4, 시전 계열마다 6, 큰 한 방 4 |
| 목소리 | 묶음 한 번 = 목소리 2개(미리 섞은 것 + C층) |

근거[모형, 부록 A]: 지금 한 판에 같은 틱 명중이 최대 41~92, 처치 최대 10~13. 지금 규칙은 쿨다운 안의 요청을 버려 76마리를 맞혀도 1마리와 같은 소리다.

### 3.5 "치명"에 대해

코어에는 치명타가 없다(`hit` 이벤트에 치명 값이 없음 [읽음]). 소리 때문에 코어를 바꾸지 않는다. 대신 **"큰 한 방"을 표현 쪽에서 판정**한다(읽기 전용):
1. `hit`의 `shatter == true`(지금 큰 숫자가 뜨는 조건과 같음, `combat_juice.gd` 268행), 또는
2. `hit`의 `damage_raw`가 그 기술의 최근 3초 명중 피해 중앙값의 4배 이상, 또는
3. 정예·수호자·우두머리에게 그 적 최대 생명의 10% 이상을 한 번에.

나중에 치명타가 코어 규칙으로 들어오면(design-lead) 그 값으로 바꾼다. 판정 기준은 `audio_map.json`의 `derived.big_hit`에 둔다(5절).

## 5. 한 곳에서 조절 — `audio_map.json`

### 5.1 원칙

1. 이벤트→소리 대응, 층, 음량, 변주, 쿨다운·묶음, 버스, 우선, 덕킹, 음악·환경음 상태, 파생 신호의 문턱을 **데이터 파일 하나**에 둔다: `chapter1/data/audio_map.json`.
2. 재생기는 이 표만 읽는다. 코드에는 "표를 읽고 따르는 규칙"만 있고 소리 이름·음량·이벤트 이름의 목록이 없다. 소리를 바꾸거나 음량을 고칠 때 코드를 건드리지 않는다.
3. 표현은 코어 이벤트와 읽기 전용 상태만 읽는다. 코어 RNG를 쓰지 않는다(골든 무관).
4. 버스도 표에서 만든다(시작 때 `AudioServer`로). 따로 `default_bus_layout.tres`를 손으로 고치지 않는다.

```
│  ├─ Combat    (시전·명중·처치·폭발·발걸음)
│  ├─ Loot      (드랍·줍기·봉인 풀기)
│  ├─ Moment    (큰 순간)
│  └─ Ambience  (구역 층, 마녀 층) — 판이 멈춰도 돈다
├─ UI           ← "효과음"에 묶음. 판이 멈춰도 돈다
├─ Alert        (적 예고, 주인공 피격, 위급) ← "효과음"에 묶음. Combat 덕킹을 받지 않는다
└─ Voice        ← "효과음"에 묶음
```

사용자 조절은 전체·음악·효과음 셋과 음소거. 기본값 전체 80·음악 70·효과음 80. 설정 파일에 저장(10.2 T-A3).

## 7. 큰 순간의 시각표, 존재 신호, 봉인 풀기(1판에서 이어짐)

### 7.1 원칙

- 시각은 **A5 5.2절의 0.1초 단위**. 0.0 = 이벤트가 표현에 닿은 프레임. 파일의 가장 큰 표본은 첫 5ms 안(3.1절).

## 8. 음악(1판에서 이어짐)

- **구조**: 판은 한 곡의 층 셋(B3 잔잔함, B4 무리, B5 수호자·우두머리), 같은 템포·마디 수·조. 다음 마디 경계에서 1~2박 교차. 타이틀 B1, 캐릭터 선택 B2(B1의 얇은 판), 승리 B6, 쓰러짐 B7, 결과 B8.
- **강도 입력**(표현 쪽, 코어 무관): 화면 안 적 25마리 이상 4초 → 무리, 12마리 이하 8초 → 잔잔함, 수호자·우두머리 등장부터 처치까지 → B5. 값은 `audio_map.json`의 `music`.
- **잴 수 있는 방향**: 판 88~96BPM(잔잔함은 반박자 느낌), 타이틀 60~72BPM, 4/4, 단조(에올리안·프리지안), 판 음악의 150Hz 아래 ≤ 35%, 2~6kHz ≤ 15%(효과음 자리), 합창은 모음만, 고리 앞뒤 절반의 LUFS-I 차 ≤ 1LU, 고리 지점 앞뒤 50ms RMS 차 ≤ 1.5dB, Ogg Vorbis 품질 5~6.
- **얻는 길(2판)**: 사람이 작곡한 판매 팩 하나(조사 문서 2안의 itch.io 다크 판타지 팩들)를 1차로. 판매 팩은 층 셋이 따로 오지 않는 경우가 많다 → 층이 없으면 "곡 셋을 강도 단계로 갈아 끼움"으로 낮춘다(같은 팩 안에서 템포·조가 가까운 곡끼리, 그 값은 내려받은 뒤 잼). 생성 AI 음악(Suno Pro 이상, AIVA Pro)은 2차이며 쓰면 스팀 AI 공개. 외주는 출시 전 검토(A-2).
