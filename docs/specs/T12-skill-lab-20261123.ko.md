## 2. 구조 — (가)를 권한다

### 2.1 세 길의 견줌
| 길 | 사용자 말("보고 판단하고 바로 교체")에 닿는가 | 비용·위험 |
|---|---|---|
| **(가) 관리 툴 페이지 + Godot 시험 창** | 닿는다. 창을 한 번 띄워 두면 페이지에서 스킬·적·후보를 바꿀 때마다 창이 따라 바뀐다. 실제 게임 코드가 그린다 | 창과 페이지가 둘(브라우저 옆에 Godot 창). 명령 주고받기를 새로 짠다 |
| (나) Godot 웹 내보내기를 페이지에 박음 | 한 창에 담기지만, 웹 빌드는 렌더러(Compatibility)·셰이더·소리 경로가 데스크톱과 달라 "게임에서 보이는 그대로"가 아니다. 후보 wav를 웹 빌드에 넣는 길도 따로 짜야 한다 | 큼. 셰이더(강림·메테오) 호환 확인, 빌드 시간 |
| (다) 미리 떠 둔 영상·소리 클립 | 보기만 된다. 바꿔 끼우면 다시 떠야 한다 — "바로 교체" 아님 | 작음. 공유용으로는 쓸모(2차의 "녹화"로) |

**SL1(권함): (가).** 페이지가 스킬 목록·설명·수치·후보 목록·낱개 듣기·채택을 맡고, "시험실 열기"가 Godot 시험 창을 띄운다. 그 뒤로는 페이지의 클릭이 창을 움직인다.

쓰는 흐름(클릭 수):
1. 관리 툴 → 「스킬 시험실」(1) → 캐릭터 카드(1) → 스킬 줄(1) → **시험실 열기**(첫 번째만, 창이 5~15초 안에 뜨고 바로 되풀이 시전 시작).
2. 적 배치 단추(1)로 한 마리 ↔ 무리 ↔ 줄 ↔ 우두머리 ↔ 군중. 창이 1초 안에 따라 바뀐다.
3. 소리 칸의 후보 줄에서 **끼우기**(1) → 다음 시전부터 그 후보로 들린다. **지금 것**(1)으로 되돌려 견준다.
4. **채택**(1) → 확인(1) → 저장소의 소리 표·원장에 반영, 창은 다시 읽어 채택된 소리로 운다.

### 2.2 세 쪽과 계약

```
브라우저(skill_lab.js) ──HTTP──▶ 관리 서버(server.py + skill_lab.py) ──파일──▶ Godot 시험 창(chapter1/tests/skill_lab.gd)
        ▲   낱개 듣기(브라우저 재생)          │  채택: tools/dev/audio_adopt.py 실행           │
        └──────────── 상태(JSON) ◀───────────┴──────────── _local/skill-lab/state.json ◀─────┘
```

**(1) 페이지 ↔ 서버**: 2.4절의 HTTP 경로. 서버만 프로세스를 띄우고 파일을 쓴다.

**(2) 서버 ↔ Godot: 파일 두 개(SL2).** 로컬 포트 대신 파일을 권한다 — 포트 충돌·방화벽 물음이 없고, Godot 쪽을 관리 서버 없이도 검사로 몰 수 있고, 무엇이 오갔는지 눈으로 볼 수 있다. 0.1초 간격의 확인이면 사람 손에는 충분하다.

폴더: `--lab-dir=<_local 아래>`(기본 `_local/skill-lab/`). `_local/` 밖이면 거절한다.

`command.json` — 서버가 쓴다(임시 파일에 쓰고 이름 바꾸기):
```json
{
  "protocol": 1,
  "seq": 12,
  "op": "scene",
  "scene": {
    "character": "chapter1.character.arc",
    "skill": "chapter1.skill.arc",
    "form": "base",
    "layout": "pack",
    "count": 8,
    "motion": "approach",
    "durable": false,
    "repeat": true,
    "interval_s": 3.0,
    "speed": 1.0,
    "juice": true
  },
  "audio": { "skill.arc.cast": ["_local/audio/chain-lightning/round2/assets/chapter1/art/audio/chain2/c7_1.wav", "…c7_2.wav", "…c7_3.wav"] }
}
```
- `op`: `scene`(원하는 상태 전체 — `scene`과 `audio`를 통째로 맞춘다. 차이만 적용) · `cast`(지금 한 번 시전) · `reload_audio`(소리 표를 다시 읽음, 채택 뒤) · `shot`(`"shot": "_local/skill-lab/shots/<이름>.png"`) · `quit`.
- `form`: `base` | `evolved`(화염의 진화가 메테오) | `descent`(그 캐릭터 계열의 강림). 2차에 `ring`.
- `layout`: `single`(한 마리, 정면 6 m) | `pack`(무리, 7 m 앞 반지름 2.5 m 안에 `count`마리, 걷는 적·원거리·돌격 섞음) | `line`(줄, 조준 방향으로 5~12 m에 `count`마리 — 관통·연쇄를 보려고) | `elite`(우두머리 하나: `elite`) | `crowd`(화면 사각형에 `count`마리, 기본 40 — 강림용).
- `motion`: `approach`(게임처럼 다가옴) | `hold`(제자리). `durable`: 적이 죽지 않게(맞는 효과만 되풀이해 볼 때).
- `repeat`: 켜면 `interval_s`마다 무대를 다시 세우고 시전한다(날아가는 투사체·떨어지는 운석·강림이 끝난 뒤에 다시 세움). `speed`: 0.25 / 0.5 / 1(`Engine.time_scale`, 소리의 높낮이는 바뀌지 않음을 화면에 적는다). `juice`: 전투 효과(`combat_juice`) 켜고 끄기.
- `audio`: 소리 자리(3.2절) → 파일 목록. 비어 있으면 끼운 후보 없음. 경로는 저장소 기준 상대 경로이며 `_local/` 또는 `chapter1/art/` 아래만, `..` 금지.

`state.json` — Godot가 0.5초마다, 그리고 명령을 적용한 바로 뒤에 쓴다:
```json
{
  "protocol": 1, "pid": 1234, "heartbeat_unix_ms": 1795400000000,
  "applied_seq": 12, "ready": true, "scene": { "...": "적용된 scene 그대로" },
  "run": { "tick": 5400, "mode": "playing", "primary": "chapter1.skill.arc", "zone": 0,
           "enemies_alive": 3, "staged": 8, "unstaged_spawns": 0 },
  "casts": { "count": 5, "last_tick": 5380, "last_skill": "chapter1.skill.arc", "last_form": "base" },
  "audio": { "overrides": { "skill.arc.cast": ["…"] }, "load_errors": [],
             "recent": [ { "tick": 5380, "slot": "skill.arc.cast", "cue": "lightning", "path": "…c7_3.wav" } ] },
  "errors": [], "last_shot": ""
}
```
- 한 폴더에 창 하나: `lab.lock`(pid). 서버는 심장 박동이 2초 안이고 pid가 살아 있으면 새로 띄우지 않고 그 창에 명령만 보낸다.
- 읽는 쪽은 깨진 JSON(쓰는 도중)을 만나면 다음 차례에 다시 읽는다.
- 새 `seq`가 60분 동안 없으면 창이 스스로 닫힌다.

**(3) 후보를 바꿔 끼우는 방법**: 시험 창이 `combat_audio.gd`의 시험용 함수 `audition_set(slot, paths)`를 부른다(3.2절, sound-designer가 만든다). 게임의 소리 경로(`audio_routes.route` → `combat_audio.play`)는 그대로이고, 그 자리에 실릴 파일만 바뀐다. 따라서 창에서 들리는 것 = 채택하면 게임에서 들릴 것(같은 이득·쿨다운·음높이 순환). **후보 파일의 음량은 맞추지 않는다** — 채택은 파일을 그대로 옮기므로, 듣는 것도 그대로여야 한다(음량 맞춤은 2차의 자리별 이득으로).

**(4) 채택이 쓰는 파일**(3.3절의 `tools/dev/audio_adopt.py`가 쓴다. 관리 서버는 이 도구를 부를 뿐이다):
- `chapter1/art/audio/slots/<자리>/<후보키>_<n>.wav`(새 파일, 같은 이름의 다른 내용은 덮지 않음)와 그 `.import`
- `chapter1/data/audio_map.json`의 `adopted` 항목
- `chapter1/art/audio/AUDIO-LEDGER.json`의 행
- `tools/manager/local-picks.json`의 고름 기록(관리 서버가 `picks.py`로)
- 커밋하지 않는다. 디렉터가 전체 회귀 뒤 커밋한다.

### 2.3 지켜야 할 것(모든 담당)
- **코어 불변.** `chapter1/core/`를 고치지 않는다. 시험 창이 코어의 상태를 직접 바꾸는 일(적 세우기, 무적, 쿨다운, 진화, 자연 생성 막기)은 **시험 도구 안에서만**, 한 파일(`chapter1/tests/support/skill_lab_stage.gd`)에 모아 각 줄에 무엇을 왜 건드리는지 적는다. 골든 리플레이는 바뀌지 않아야 한다(`golden_core.gd` 비교 통과).

## 3. 소리 쪽의 계약(sound-designer)

### 3.1 왜 "소리 자리"가 필요한가
지금 소리 이름은 스킬이 나눠 쓴다(`cold` = 냉기 시전 + 파쇄, `impact` = 세 스킬의 명중, `explosion` = 메테오 착지 + 다른 폭발). 스킬마다 바꿔 끼우려면 스킬 단위의 이름이 따로 있어야 한다. 다만 **아무것도 채택하지 않은 상태의 소리는 지금과 한 표본도 달라지면 안 된다.**

### 3.2 `audio_map.json` 스키마 2(SL3)
```json
{
  "schema_version": 2,
  "chain_lightning": { "A": { "…": "그대로" }, "B": { "…": "그대로" } },
  "slots": {
    "skill.ember.cast":    { "parent": "fire" },
    "skill.ember.hit":     { "parent": "impact" },
    "skill.meteor.cast":   { "parent": "fire" },
    "skill.meteor.land":   { "parent": "explosion" },
    "skill.frost.cast":    { "parent": "cold" },
    "skill.frost.hit":     { "parent": "impact" },
    "skill.frost.shatter": { "parent": "cold" },
    "skill.arc.cast":      { "parent": "lightning", "per_targets": 3 },
    "skill.arc.hit":       { "parent": "impact" },
    "descent.ember.call":  { "parent": "" },
    "descent.frost.call":  { "parent": "" },
    "descent.arc.call":    { "parent": "" }
  },
  "adopted": {}
}
```
- 위 표는 최소한이다. 진화한 냉기·번개, 강림의 휩쓸기·끝 같은 자리를 더할지는 sound-designer가 D24의 이벤트(`descent_*`)와 `docs/AUDIO-PLAN.ko.md`를 보고 정한다. 자리 이름은 `<무리>.<대상>.<순간>`.
- `parent`: 채택된 파일이 없을 때 울릴 지금의 소리 이름. `""`이면 채택 전에는 무음(강림은 지금도 무음이므로 달라지는 것이 없다).
- `per_targets`: 번개처럼 맞힌 수에 따라 파일을 고르는 자리. 파일 목록의 `min(맞힌 수, per_targets)`번째. 지금의 `arc_path_1..3`과 같은 뜻.
- `adopted`: `{자리: {"files": ["res://…"], "candidate": "<후보 id>", "date": "YYYY-MM-DD"}}`. 채택된 자리는 `SILENT`의 적용을 받지 않는다(SL5: 번개를 채택하면 일반 실행에서 번개가 울린다).

**경로(`audio_routes.gd`)**: 요청에 `slot` 칸을 더한다(`cue`는 지금 그대로 둔다). 어느 이벤트가 어느 자리인지(시전·명중·파쇄의 `skill_id`, 진화 여부 `evolved`, 메테오 착지 `explosion.meteor`, 강림 이벤트)를 이 파일 한곳에서 정한다.

**재생(`combat_audio.gd`)**: 소리를 고르는 차례 = 시험용 끼움(`audition`) → `adopted` → `parent`의 지금 파일. 쿨다운·이득·음높이는 부모 소리의 것을 쓴다(자리마다 따로 두는 것은 2차). 더할 함수:
```
func audition_set(slot: String, paths: Array) -> Dictionary   # {"ok": bool, "loaded": [...], "errors": [...]}. res:// 또는 저장소 안의 절대 경로
func audition_clear(slot: String = "") -> void                 # 빈 이름이면 전부
func reload_map() -> void                                      # audio_map.json의 adopted를 다시 읽음
var audition_log: Array                                        # audition_set을 한 번이라도 부른 뒤에만 쌓임: {tick, slot, cue, path}, 최대 200
```
부르지 않으면 아무 일도 하지 않는다(일반 실행에 들 비용 없음). 시험 인수 `--chapter1-chain-audio=A|B`는 지금처럼 돈다(이 길 위에서 다시 짜도 되지만 결과는 같아야 함).

**오프라인 도구**: `tools/dev/audio_mix_offline.py`(와 그것을 쓰는 `audio_scene_audition.py`)가 `combat_audio.gd`의 상수를 읽는다. `adopted`를 모르면 채택 뒤의 장면 비교 영상이 옛 소리로 나온다 — `adopted`를 읽게 고치거나, 못 고치면 그 차이를 도구 머리에 적는다.

### 3.3 채택 도구 `tools/dev/audio_adopt.py`(새로)
```
python tools/dev/audio_adopt.py list [--json]                          # 자리, 지금 걸린 것(채택/부모), 찾은 후보
python tools/dev/audio_adopt.py adopt --slot skill.arc.cast --candidate chain-lightning/round2/C7 [--expect-rev <sha256>] [--dry-run] [--no-import]
python tools/dev/audio_adopt.py revert --slot skill.arc.cast [--expect-rev <sha256>] [--dry-run]
```
- `adopt`: 후보 파일을 `chapter1/art/audio/slots/<자리>/`로 복사(같은 이름의 다른 내용이 있으면 거절) → `audio_map.json`의 `adopted`를 원자적으로 고침(기존 들여쓰기·키 순서·줄바꿈 유지, 바뀐 곳만) → `AUDIO-LEDGER.json`에 행(파일·sha256과, 후보 목록 파일의 출처 칸. 출처가 없으면 `"origin": "unverified"` — 지금 개발을 막지 않는다는 사용자 결정, 2026-11-20) → 통합 에셋 원장(`tools/art/asset_ledger.py`)이 소리 파일을 올리는 규칙이 있으면 그대로 → 임포트(`python tools/dev/run_dev.py --import-only`) → `audio_ledger_check.py`. 결과를 JSON 한 줄(`AUDIO_ADOPT {...}`)로: 쓴 파일, 표의 전후, 검사 결과.
- `--expect-rev`가 지금 `audio_map.json`의 sha256과 다르면 아무것도 쓰지 않고 종료 코드 3(서버는 409로).
- `revert`: `adopted`에서 그 자리를 뺀다. 이 도구가 더했고 아직 커밋되지 않은(`git ls-files`에 없는) 파일은 지운다.
- `--root`(검사용): 다른 폴더를 저장소로 보고 돈다.

### 3.4 후보 목록 파일 `lab-candidates.json`(SL6)
납품 폴더마다 하나. 관리 서버와 `audio_adopt.py`가 `_local/audio/**/lab-candidates.json`을 훑는다. 후보 id = `<_local/audio 기준 폴더>/<key>`.
```json
{
  "schema": 1,
  "title": "체인 라이트닝 2차",
  "delivered": "2026-11-23",
  "by": "codex-astra",
  "candidates": [
    {
      "key": "C7",
      "label": "세 접점의 음이 기음·완전5도·옥타브로 솟는 도약",
      "slot": "skill.arc.cast",
      "files": ["assets/chapter1/art/audio/chain2/c7_1.wav", "assets/chapter1/art/audio/chain2/c7_2.wav", "assets/chapter1/art/audio/chain2/c7_3.wav"],
      "ledger": [ { "file": "c7_1.wav", "pack": "…", "source": "…", "license": "…", "processing": "…" } ]
    }
  ]
}
```
경로는 목록 파일 기준 상대. 1차에 sound-designer가 만들 것: 체인 2차(C1~C8, 출처는 `chain-round2.patch`의 원장 행에서), 체인 1차(A·B, 저장소의 `chapter1/art/audio/chain/` — 이 경우 `files`는 저장소 경로).

## 4. 차수

### 4.1 1차 — 사용자가 오늘·내일 써 볼 가장 작은 온전한 것
- 캐릭터 셋(테사·아일린·베로니카), 형태 셋: 주력 `base` · 진화 `evolved`(화염 = 메테오, 냉기·번개의 진화도 같은 길이라 함께) · 강림 `descent`(세 계열). 합 9가지.
- 적 배치 다섯: 한 마리 · 무리 · 줄 · 우두머리 하나 · 군중. 마리 수 막대(1~40). 다가옴/제자리, 죽지 않음.
- 되풀이(간격 1.5~6초), 지금 한 번 시전, 느리게(0.25·0.5·1), 전투 효과 켜고 끄기, 화면 저장.
- 소리: 그 스킬의 자리 표 → 지금 걸린 것과 후보를 **브라우저에서 낱개 듣기**(파형·길이·최대 dBFS·RMS, 브라우저의 Web Audio로 계산 — 서버는 표준 라이브러리만), **창에 끼우기**, **지금 것으로 되돌리기**, **채택**과 **채택 취소**.
- 스킬의 이름·설명·랭크별 수치·진화 수치(`growth_quality37.json`), 강림의 이름·수치(`descent.json`), 글은 `chapter1/i18n/ko.po` — 매번 파일에서 읽는다(`catalog.py`의 함수를 불러 쓴다, 같은 해석을 두 번 짜지 않는다).
- 효과(이펙트)는 1차에 **바꿔 끼울 후보가 없다**: 효과는 코드와 셰이더라 "파일 하나를 바꾸는" 구조가 아니다. 1차는 켜고 끄기·느리게·적 수로 견주는 데까지.

### 4.2 2차
- 판 안 주문(고리, `run_spells`, `--chapter1-trial=spells`), 스킬 랭크 막대(랭크별 모습), 다른 계열의 스킬을 다른 캐릭터가 쓰기(보조 스킬).
- **한 스킬이 다른 스킬에 주는 영향**(사용자 지침 2026-11-19): 두 스킬을 함께 — 예: 냉기로 얼린 뒤 번개. `run_spells.json`의 `pairs`, `skill_trees.json`의 `synergies`를 페이지에 그림으로(T9 5.1에서 옮김).
- 효과 값 조절 막대: vfx-feel이 `view/fx`의 파일들(`meteor_fx.gd`, `descent_fx.gd`, `chapter_effects.gd`)에 흩어진 모습 상수를 파일마다 한 사전(`LOOK`)으로 모으고 시험용 덮어쓰기 함수를 단 뒤에(강림 묶기가 끝난 다음). 채택은 소리와 같은 길(값 → 데이터 파일, 패치).
- 소리 자리별 이득·쿨다운(`audio_map.json`), 음량 맞춰 듣기 선택, 빠른 A/B 전환 단축키, 시험실 화면을 짧은 영상으로 떠서 남기기(디렉터가 사용자에게 보낼 때).
- 레벨업·물약 등 스킬 아닌 소리(`sfx-batch3/candidates-v2`)의 자리.

### 4.3 3차
장비·재화·적 화면(T9 B4 이후), 효과의 그림·셰이더 후보를 자리표(`asset_slots.json`)로 바꿔 끼우기.

## 9. 개정 1 — 원격에서 쓰기(2026-11-23 추가 요구)

### 9.1 지금 상태(확인함)
- 서버는 `127.0.0.1`에만 열린다(`tools/manager/server.py:368` `make_server`).
- `server.py:111-113` `trusted_request`는 Host가 `127.0.0.1:<포트>`·`localhost:<포트>`일 때만 받는다. POST는 Origin도 같은 둘만 받는다. GET은 252행, POST는 321행에서 검사한다. 따라서 터널을 붙여도 지금은 모든 요청이 403이다. 이것은 맞게 막혀 있는 것이다.
- 인증은 없다. 루프백만 받는다는 것이 유일한 경계다.
- 위험한 쓰기·실행 경로가 이미 있다.
  - `/api/balance/run`, `/api/audit/run`은 하위 프로세스를 띄운다.
  - `/api/characters/<id>/open`은 `characters.py:391` `os.startfile`로 PC에서 탐색기를 연다.
  - `/api/characters/<id>/tripo_out`은 파일을 올려받는다.
  - 메모·고름·초안 쓰기도 있다.
  - 시험실이 더하는 것: 창 띄우기, 채택(저장소 파일 쓰기와 임포트).
- 이 PC에 `cloudflared`가 없다(PATH, `~/.cloudflared` 모두 없음). ffmpeg는 있다(8.0.1, WinGet).
- 상위 작업공간 저장소들의 wrangler 설정에서 사용자 도메인(route, zone)을 찾지 못했다. Cloudflare에 올린 도메인이 있는지는 **확인 필요**다.

### 9.2 원격의 길: Cloudflare Tunnel + Cloudflare Access (SL9, 권함)
```
휴대폰 브라우저 ──HTTPS──▶ Cloudflare(Access 로그인) ──Tunnel──▶ 사용자 PC의 cloudflared ──▶ 127.0.0.1:8781(관리 서버) ──▶ Godot(같은 PC)
```
- 서버와 Godot는 사용자 PC에서 그대로 돈다. 무거운 일(Godot, 영상 찍기, 임포트)은 PC가 하고, 인터넷으로는 페이지·JSON·짧은 영상만 나간다. 그래서 "무거워서 안 되려나"는 이 길에서는 걱정하지 않아도 된다.
- 서버는 계속 `127.0.0.1`에만 연다. cloudflared가 같은 PC에서 루프백으로 붙으므로 바깥에 포트를 열지 않는다(공유기 포트 열기 없음).
- **금지**
  - 인증 없는 임시 터널(trycloudflare 등)
  - 서버를 `0.0.0.0`으로 열기
  - 공유기 포트 포워딩
  - 이 도구에는 파일을 쓰고 프로세스를 띄우는 단추가 있으므로, 인증 없이 노출되는 순간 PC를 남에게 넘겨주는 것과 같다.

**사용자가 손으로 할 것**(우리가 대신할 수 없다. 계정·결제·도메인이 걸림)
1. Cloudflare 계정에 도메인이 있는지 확인한다. 없으면 하나를 Cloudflare에 올린다. **확인 필요:** 이름 있는 터널을 공개 호스트 이름(예: `moira.<도메인>`)으로 내보내려면 Cloudflare가 관리하는 도메인이 필요하다고 알고 있으나, 지금 문서로 다시 확인한다.
2. `cloudflared` 설치(`winget install Cloudflare.cloudflared` — 패키지 이름은 **확인 필요**), `cloudflared tunnel login`(브라우저로 계정 승인).
3. Zero Trust 대시보드에서 다음을 만든다.
   - Access 응용(자체 호스팅): 호스트 이름 = 위의 이름
   - 정책: 사용자 본인 이메일 하나만 허용, 로그인은 이메일 일회 코드
   - 세션 길이(권함 24시간)
   - **확인 필요:** Access 무료 한도(사용자 수 상한)와 무료 플랜에서 이메일 일회 코드를 쓸 수 있는지
4. 만든 Access 응용의 **AUD 태그**와 팀 도메인(`<팀>.cloudflareaccess.com`)을 우리 설정 파일(9.3절)에 넣는다. 비밀은 아니지만 저장소에는 올리지 않는다.
5. 터널을 서비스로 등록할지(PC가 켜질 때 함께 뜸), 쓸 때만 켤지 정한다. 권함: 쓸 때만, `tools/manager/remote.ps1`(9.5절) 한 줄로.

**우리가 만드는 것**(manager-tools, 9.6절의 SL-E)
- 설정 파일 `tools/manager/local-remote.json`(git 밖. `.gitignore`에 더하거나 `local-*.json` 규칙이 이미 덮는지 확인)
  ```json
  { "enabled": false,
    "hosts": ["moira.example.com"],
    "access": { "team_domain": "xxx.cloudflareaccess.com", "aud": "<AUD 태그>", "emails": ["사용자 이메일"] },
    "remote_allows": ["view", "skill_lab.scene", "skill_lab.clip", "skill_lab.adopt", "picks", "notes"] }
  ```
  `enabled: false`이거나 파일이 없으면 지금과 한 글자도 다르지 않게 동작한다(루프백만).
- **요청 판정**(`trusted_request`를 대신하는 한 함수)
  - 로컬 요청: Host가 루프백이고, POST의 Origin도 루프백. 지금과 같다.
  - 원격 요청: Host가 `hosts`에 있고, `Cf-Access-Jwt-Assertion` 헤더의 JWT를 검증해야 한다.
    - 서명: 팀의 `https://<team_domain>/cdn-cgi/access/certs` 공개 키, RS256
    - `aud` 포함, `iss` = `https://<team_domain>`, `exp` 안, `email`이 `emails`에 있음
    - 검증에 실패하면 403
    - POST는 Origin이 `https://<그 호스트>`여야 한다.
  - 헤더를 믿는 근거: cloudflared가 루프백으로 붙으므로 바깥에서 헤더를 꾸며 직접 들어올 길이 없다. 그래도 JWT 서명을 검증해 터널 설정 실수(Access 없이 공개)를 막는다. 헤더 이름과 인증서 주소는 Cloudflare 문서로 **확인 필요**(구현 첫 일).
  - 서버는 표준 라이브러리만 쓴다. RS256 검증은 `hashlib` + 정수 연산(PKCS#1 v1.5)으로 짤 수 있다. 외부 패키지(`PyJWT`, `cryptography`)를 들일지는 SL11. 인증서는 1시간 캐시한다. 받기에 실패하면 원격은 모두 거절한다(닫힌 쪽으로 실패).
  - 공유 비밀만 쓰는 길(Access 없이 헤더 비밀)은 권하지 않는다. Access를 붙일 수 없을 때의 임시 수단으로도 쓰지 않는다.
- **원격에서 막는 것**(서버가 거절. 페이지는 단추를 숨기거나 회색으로)
  - `/api/characters/<id>/open`(PC 탐색기 열기 — 원격에서는 뜻이 없고 PC 앞의 사람을 놀라게 함)
  - `/api/characters/<id>/tripo_out`(파일 올려받기)
  - `/api/balance/run`, `/api/audit/run`(긴 하위 프로세스). 원격 허용은 SL10에서 사용자가 정함.
  - 시험실의 **창 띄우기**(`/api/skill-lab/open`). 원격에서는 영상만(9.3절). PC 화면에 갑자기 Godot 창이 뜨지 않게.
  - `/api/skill-lab/shot`(창 화면 저장)
  - `/files/`의 `.py`·`.gd`·`.md` 등 원문 파일(카탈로그의 코드 보기). 원격에서는 그림·소리·영상만.
- **원격에서 허용**(`remote_allows`): 보기 전부, 시험실의 장면 고르기와 영상 찍기, 소리 끼우기 비교(영상으로), 채택(사용자 지시가 "바로 교체"), 고름·메모.
- **기록**: 원격 요청은 `_local/manager/remote-access.log`에 한 줄씩 남긴다(시각, 이메일, 방법, 경로, 결과). 채택은 고름 기록의 `by`를 `"user(remote:<이메일>)"`로 남긴다.
- **휴대폰 화면**: `index.html`과 `app.css`에 좁은 화면 배치를 더한다.
  - 768px 아래에서는 왼쪽 줄을 위쪽 탭으로, 시험실은 한 줄 세로 배치(캐릭터 → 스킬 → 적 배치 → 영상 → 소리 후보)
  - 단추는 44px 이상
  - 영상은 화면 너비에 맞춤, 소리 줄은 ▶ 듣기와 "이 소리로 영상" 두 단추만 크게
  - 다른 화면(원화 시안·캐릭터의 3D 보기 등)은 1차에 "보이기만 하면 됨". 3D 보기는 휴대폰에서 무거우면 정지 그림으로 대신한다.

### 9.3 시험실의 원격 보기: 소리가 든 짧은 영상 (SL12, 1차 범위에 넣음)
브라우저에는 게임 창이 오지 않는다. 원격에서 "보고 판단하고 바로 교체"가 되려면 PC가 장면을 **소리가 든 짧은 영상**으로 찍어 페이지에 올려야 한다. PC 앞에서는 지금까지의 게임 창(2절)도 함께 쓴다.

**찍는 방법: 두 길을 SL-B가 첫 일로 재고 정한다**
| 길 | 소리 | 비용 | 확인할 것 |
|---|---|---|---|
| **(ㄱ) Godot Movie Maker**(`--write-movie <파일>.avi`, 엔진 기능. 고정 프레임으로 그림과 엔진의 소리 출력을 함께 파일로 씀) | **게임 엔진이 실제로 낸 소리**(혼합·목소리 수·쿨다운 모두 실제) | 장면마다 Godot 프로세스 하나(띄우기 + 무대 + 4초 녹화). 녹화는 실시간보다 느릴 수 있음 | **확인 필요(이 저장소에서 써 본 적 없음, `frame_probe.gd`가 경로를 읽기만 함):** 4.5.1의 AVI에 소리가 실제로 들어가는지, 1280×720 4초를 찍는 데 걸리는 시간, `--write-movie`와 `--script` 실행이 함께 되는지 |
| (ㄴ) 프레임 + 이벤트 기록 → 오프라인 섞기(`sfx_capture.gd`가 프레임과 `events.json`, `tools/dev/audio_scene_audition.py`가 후보 소리를 깔아 mp4, 재생 규칙은 `audio_mix_offline.py`가 `combat_audio.gd`에서 읽음) | **모델의 소리**(재생 규칙을 파이썬으로 다시 짠 것) | 그림은 장면마다 한 번, **후보를 바꿀 때는 섞기만**(몇 초) | 이미 있음. 소리 자리·채택(3.2절)을 `audio_mix_offline.py`가 읽어야 함(SL-A 4번) |

- 권함: **(ㄱ)이 4.5.1에서 소리와 함께 되면 (ㄱ)을 기본**으로 한다("게임에서 보이고 들리는 그대로"). 후보를 빠르게 넘겨 듣는 비교에만 (ㄴ)을 "빠른 비교(모델의 소리)"라는 표시를 붙여 쓴다. (ㄱ)이 안 되면 (ㄴ)만 쓰고, 페이지의 영상마다 "모델의 소리" 표시를 단다.
- 영상의 꼴: H.264 mp4 + AAC(휴대폰 브라우저가 바로 튼다). ffmpeg로 바꾼다. 4초(되풀이 한 번 + 꼬리), 1280×720, 30fps로 줄여 내보냄(찍기는 60). 목표 크기는 1~3 MB. **휴대폰 데이터를 생각해 확인 필요:** 실측 크기를 SL-B가 적는다.
- 시간 목표: **누르고 20초 안에 영상이 페이지에 뜬다**(1차 판정선, PC 기준). 못 미치면 실측을 적고, 디렉터와 다시 정한다. 찍는 동안 페이지에 "찍는 중 n초"를 보인다.
- 줄 세우기: 영상 찍기는 한 번에 하나(Godot 자리를 많이 쥐지 않게). 대기열은 최대 5, 넘으면 거절.
- **캐시**: 열쇠 = (캐릭터, 스킬, 형태, 배치, 마리 수, 다가옴/제자리, 죽지 않음, 느리게, 전투 효과, 끼운 소리 파일들의 sha256, 찍는 길(ㄱ/ㄴ)) + **판의 판** = 다음 파일 내용의 sha256.
  - `chapter1/data/audio_map.json`, `combat_tuning.json`, `growth_quality37.json`, `descent.json`
  - `chapter1/presentation/*.gd`, `chapter1/view/fx/**`, `chapter1/view/actors/**`, `chapter1/core/**`
  - 시험 장면 파일
  - 같은 열쇠면 다시 찍지 않는다.
  - 판이 달라진 영상은 지우지 않고 "낡음(소리 표/효과 코드가 바뀜)" 표시를 달아 보여 주고, "다시 찍기" 단추를 둔다.
  - 둘 곳: `_local/skill-lab/clips/<열쇠 해시>.mp4` + `.json`(열쇠, 판, 찍은 시각, 길, 걸린 시간, 크기). 상한 2 GB, 넘으면 오래 안 본 것부터 지운다.
- **명령 계약에 더할 것**(2.2절): 영상 찍기는 떠 있는 창이 아니라 **새 프로세스**로 한다(Movie Maker는 프로세스를 띄울 때 정해짐).
  ```
  python tools/dev/godot.py --timeout-s=120 --fixed-fps 60 --resolution 1280x720 --write-movie _local/skill-lab/clips/tmp/<id>.avi --path . --script res://chapter1/tests/skill_lab.gd -- \
      --chapter1-start --chapter1-profile-off --chapter1-qa-ignore-focus --chapter1-trial=descent --chapter1-descent-cost=1000 --chapter1-seed=11 \
      --chapter1-primary=<주력> --lab-clip=<scene JSON 파일, _local 아래> --lab-clip-seconds=4
  ```
  - `--lab-clip`이 있으면 시험 창은 명령 파일을 읽지 않는다. 그 장면 하나를 세우고, 무대가 선 뒤 바로 한 번 시전하고, `seconds`가 지나면 끝낸다.
  - 무대를 세우는 동안의 프레임은 영상에서 잘라낸다. 시험 창이 시작 프레임 번호를 `state`에 쓰고, ffmpeg가 그 앞을 버린다.
  - `godot.py`가 `--write-movie` 인수를 그대로 넘기는지 **확인 필요**(그 도구는 인수를 그대로 넘긴다고 적혀 있다).
  - 창 없이(`--headless`) Movie Maker가 되는지도 **확인 필요**. 안 되면 창이 잠깐 떴다 닫힌다. 원격일 때 PC 화면에 창이 번쩍이는 것은 받아들이고, 창을 화면 밖 위치에 띄우는 인수(`--position`)를 쓴다.

### 9.4 PC가 꺼져 있을 때 (2차 이후의 선택지, 1차에는 만들지 않음)
- **Cloudflare Pages에 읽기 전용 스냅숏**: 스킬 표(JSON)와 찍어 둔 영상을 정적 사이트로 올린다. 채택·찍기는 안 되고 보기만 된다. Access를 같은 방식으로 붙인다.
  - **확인 필요:** Pages의 파일 하나 크기 상한과 파일 수 상한, 무료 플랜의 배포 횟수 한도, 영상을 R2에 두면 드는 비용. 우리가 아는 값이 지금 맞는지 확인하지 않았으므로 숫자를 적지 않는다.
- **Godot 웹 내보내기를 페이지에 박는 길은 권하지 않는다.** 확인한 것:
  - 이 프로젝트의 렌더러는 `forward_plus`다(`project.godot:23`).
  - Godot 4의 웹 내보내기는 Compatibility 렌더러만 돈다(엔진 문서의 제약으로 알고 있음 — 4.5에서 바뀌었는지는 **확인 필요**). 강림·메테오·예고선 셰이더 13개(`chapter1/view/fx/*.gdshader`)를 그 렌더러에서 따로 맞춰야 하고, 맞춰도 "게임에서 보이는 그대로"가 아니다.
  - 내보내기 설정에는 Windows 프리셋 셋뿐이고 웹 프리셋은 없다.
  - 후보 wav를 웹 빌드 안에서 바꿔 끼우는 길도 따로 짜야 한다.

### 9.5 원격 켜기·끄기
- `tools/manager/remote.ps1`(새): `start`는 관리 서버(없으면) + `cloudflared tunnel run <이름>`을 띄우고, `stop`은 터널만 내린다. `status`는 둘의 상태와 `local-remote.json`의 `enabled`를 보여 준다.
- **터널이 떠 있어도 `enabled: false`면 서버가 원격 요청을 모두 403으로 거절한다.** 두 겹의 스위치다.
- 페이지 머리에 "원격 켜짐 / 꺼짐"과 마지막 원격 접속(이메일, 시각)을 보인다(로컬에서만).

- 첫 일: 9.3절 (ㄱ)의 확인 세 가지를 실측해 보고(소리가 들었는지는 ffprobe의 오디오 스트림과 그 RMS로 판정 — 사람이 듣지 않음을 적는다).
- `--lab-clip`/`--lab-clip-seconds` 실행 방식, 무대 시작 프레임 표시.
- 판정: 세 캐릭터 × `base`·`evolved`·`descent` × `single`·`pack` 18장면을 영상으로. 장면마다 걸린 시간과 크기를 표로 내고, 20초 목표와 견준다.

**SL-C에 더함(관리 툴 페이지): 영상 패널과 캐시**
- `tools/manager/skill_lab_clips.py`(새): 열쇠·판 계산, 대기열(하나씩, 최대 5), 프로세스 실행, ffmpeg 변환(`-c:v libx264 -c:a aac -movflags +faststart`), 낡음 표시, 2 GB 상한.
- 경로: `POST /api/skill-lab/clip {scene, audio, way}` → 작업 id, `GET /api/skill-lab/clip/<id>` → 상태와 영상 주소. 영상은 id로만 내주고 `Range` 요청에 응답한다(휴대폰 브라우저의 영상 재생이 `Range`를 쓴다 — 지금 `send_bytes`가 `Range`를 받는지 **확인 필요**).
- 페이지: 시험실 가운데에 "영상" 칸. PC 앞이면 "창으로 보기 / 영상으로 보기" 둘 다, 원격이면 영상만. 소리 후보 줄에 "이 소리로 영상" 단추, 같은 장면의 영상 둘을 위아래로 놓고 견주기.

**SL-A에 더함**: 4번(`audio_mix_offline.py`가 `slots`·`adopted`·끼움을 읽음)은 이제 (ㄴ) 길의 전제라 필수다.

**SL-D에 더함(qa-perf)**: `skill_lab_smoke.py`에 영상 18장면(시간·크기·오디오 스트림 유무), 캐시 다시 찍지 않음, 소리 표를 바꾼 뒤의 낡음 표시를 더한다. 원격 판정의 검사는 SL-E의 것을 run_all `manager`에 묶는다.

**순서**: A·B·C 병행 → SL-E(원격, C 다음) → D. 영상(B·C의 더함)은 B의 첫 실측 결과로 (ㄱ)/(ㄴ)이 정해진 뒤에 짠다.

**6절(사용자에게 보일 것)에 더함**: 원격 켜는 법(사용자가 할 일 1~5와 `remote.ps1 start`), 휴대폰 캡처 두 장, 영상 하나(아일린 무리).
