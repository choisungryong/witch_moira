## 2. 구조 — (가)를 권한다

### 2.1 세 길의 견줌
| 길 | 사용자 말("보고 판단하고 바로 교체")에 닿는가 | 비용·위험 |
|---|---|---|
| **(가) 관리 툴 페이지 + Godot 시험 창** | 닿는다. 창을 한 번 띄워 두면 페이지에서 스킬·적·후보를 바꿀 때마다 창이 따라 바뀐다. 실제 게임 코드가 그린다 | 창과 페이지가 둘(브라우저 옆에 Godot 창). 명령 주고받기를 새로 짠다 |
| (나) Godot 웹 내보내기를 페이지에 박음 | 한 창에 담기지만, 웹 빌드는 렌더러(Compatibility)·셰이더·소리 경로가 데스크톱과 달라 "게임에서 보이는 그대로"가 아니다. 후보 wav를 웹 빌드에 넣는 길도 따로 짜야 한다 | 큼. 셰이더(강림·메테오) 호환 확인, 빌드 시간 |
| (다) 미리 떠 둔 영상·소리 클립 | 보기만 된다. 바꿔 끼우면 다시 떠야 한다 — "바로 교체" 아님 | 작음. 공유용으로는 쓸모(2차의 "녹화"로) |

**SL1(권함): (가).** 페이지가 스킬 목록·설명·수치·후보 목록·낱개 듣기·채택을 맡고, "시험실 열기"가 Godot 시험 창을 띄운다. 그 뒤로는 페이지의 클릭이 창을 움직인다.

쓰는 흐름(클릭 수):
1. 관리 툴 → 「스킬 시험실」(1) → 캐릭터 카드(1) → 스킬 줄(1) → **시험실 열기**(첫 번째만, 창이 5~15초 안에 뜨고 바로 되풀이 시전 시작).
2. 적 배치 단추(1)로 한 마리 ↔ 무리 ↔ 줄 ↔ 우두머리 ↔ 군중. 창이 1초 안에 따라 바뀐다.
3. 소리 칸의 후보 줄에서 **끼우기**(1) → 다음 시전부터 그 후보로 들린다. **지금 것**(1)으로 되돌려 견준다.
4. **채택**(1) → 확인(1) → 저장소의 소리 표·원장에 반영, 창은 다시 읽어 채택된 소리로 운다.

### 2.2 세 쪽과 계약

```
브라우저(skill_lab.js) ──HTTP──▶ 관리 서버(server.py + skill_lab.py) ──파일──▶ Godot 시험 창(chapter1/tests/skill_lab.gd)
        ▲   낱개 듣기(브라우저 재생)          │  채택: tools/dev/audio_adopt.py 실행           │
        └──────────── 상태(JSON) ◀───────────┴──────────── _local/skill-lab/state.json ◀─────┘
```

**(1) 페이지 ↔ 서버**: 2.4절의 HTTP 경로. 서버만 프로세스를 띄우고 파일을 쓴다.

**(2) 서버 ↔ Godot: 파일 두 개(SL2).** 로컬 포트 대신 파일을 권한다 — 포트 충돌·방화벽 물음이 없고, Godot 쪽을 관리 서버 없이도 검사로 몰 수 있고, 무엇이 오갔는지 눈으로 볼 수 있다. 0.1초 간격의 확인이면 사람 손에는 충분하다.

폴더: `--lab-dir=<_local 아래>`(기본 `_local/skill-lab/`). `_local/` 밖이면 거절한다.

`command.json` — 서버가 쓴다(임시 파일에 쓰고 이름 바꾸기):
```json
{
  "protocol": 1,
  "seq": 12,
  "op": "scene",
  "scene": {
    "character": "chapter1.character.arc",
    "skill": "chapter1.skill.arc",
    "form": "base",
    "layout": "pack",
    "count": 8,
    "motion": "approach",
    "durable": false,
    "repeat": true,
    "interval_s": 3.0,
    "speed": 1.0,
    "juice": true
  },
  "audio": { "skill.arc.cast": ["_local/audio/chain-lightning/round2/assets/chapter1/art/audio/chain2/c7_1.wav", "…c7_2.wav", "…c7_3.wav"] }
}
```
- `op`: `scene`(원하는 상태 전체 — `scene`과 `audio`를 통째로 맞춘다. 차이만 적용) · `cast`(지금 한 번 시전) · `reload_audio`(소리 표를 다시 읽음, 채택 뒤) · `shot`(`"shot": "_local/skill-lab/shots/<이름>.png"`) · `quit`.
- `form`: `base` | `evolved`(화염의 진화가 메테오) | `descent`(그 캐릭터 계열의 강림). 2차에 `ring`.
- `layout`: `single`(한 마리, 정면 6 m) | `pack`(무리, 7 m 앞 반지름 2.5 m 안에 `count`마리, 걷는 적·원거리·돌격 섞음) | `line`(줄, 조준 방향으로 5~12 m에 `count`마리 — 관통·연쇄를 보려고) | `elite`(우두머리 하나: `elite`) | `crowd`(화면 사각형에 `count`마리, 기본 40 — 강림용).
- `motion`: `approach`(게임처럼 다가옴) | `hold`(제자리). `durable`: 적이 죽지 않게(맞는 효과만 되풀이해 볼 때).
- `repeat`: 켜면 `interval_s`마다 무대를 다시 세우고 시전한다(날아가는 투사체·떨어지는 운석·강림이 끝난 뒤에 다시 세움). `speed`: 0.25 / 0.5 / 1(`Engine.time_scale`, 소리의 높낮이는 바뀌지 않음을 화면에 적는다). `juice`: 전투 효과(`combat_juice`) 켜고 끄기.
- `audio`: 소리 자리(3.2절) → 파일 목록. 비어 있으면 끼운 후보 없음. 경로는 저장소 기준 상대 경로이며 `_local/` 또는 `chapter1/art/` 아래만, `..` 금지.

`state.json` — Godot가 0.5초마다, 그리고 명령을 적용한 바로 뒤에 쓴다:
```json
{
  "protocol": 1, "pid": 1234, "heartbeat_unix_ms": 1795400000000,
  "applied_seq": 12, "ready": true, "scene": { "...": "적용된 scene 그대로" },
  "run": { "tick": 5400, "mode": "playing", "primary": "chapter1.skill.arc", "zone": 0,
           "enemies_alive": 3, "staged": 8, "unstaged_spawns": 0 },
  "casts": { "count": 5, "last_tick": 5380, "last_skill": "chapter1.skill.arc", "last_form": "base" },
  "audio": { "overrides": { "skill.arc.cast": ["…"] }, "load_errors": [],
             "recent": [ { "tick": 5380, "slot": "skill.arc.cast", "cue": "lightning", "path": "…c7_3.wav" } ] },
  "errors": [], "last_shot": ""
}
```
- 한 폴더에 창 하나: `lab.lock`(pid). 서버는 심장 박동이 2초 안이고 pid가 살아 있으면 새로 띄우지 않고 그 창에 명령만 보낸다.
- 읽는 쪽은 깨진 JSON(쓰는 도중)을 만나면 다음 차례에 다시 읽는다.
- 새 `seq`가 60분 동안 없으면 창이 스스로 닫힌다.

**(3) 후보를 바꿔 끼우는 방법**: 시험 창이 `combat_audio.gd`의 시험용 함수 `audition_set(slot, paths)`를 부른다(3.2절, sound-designer가 만든다). 게임의 소리 경로(`audio_routes.route` → `combat_audio.play`)는 그대로이고, 그 자리에 실릴 파일만 바뀐다. 따라서 창에서 들리는 것 = 채택하면 게임에서 들릴 것(같은 이득·쿨다운·음높이 순환). **후보 파일의 음량은 맞추지 않는다** — 채택은 파일을 그대로 옮기므로, 듣는 것도 그대로여야 한다(음량 맞춤은 2차의 자리별 이득으로).

**(4) 채택이 쓰는 파일**(3.3절의 `tools/dev/audio_adopt.py`가 쓴다. 관리 서버는 이 도구를 부를 뿐이다):
- `chapter1/art/audio/slots/<자리>/<후보키>_<n>.wav`(새 파일, 같은 이름의 다른 내용은 덮지 않음)와 그 `.import`
- `chapter1/data/audio_map.json`의 `adopted` 항목
- `chapter1/art/audio/AUDIO-LEDGER.json`의 행
- `tools/manager/local-picks.json`의 고름 기록(관리 서버가 `picks.py`로)
- 커밋하지 않는다. 디렉터가 전체 회귀 뒤 커밋한다.

### 2.3 지켜야 할 것(모든 담당)
- **코어 불변.** `chapter1/core/`를 고치지 않는다. 시험 창이 코어의 상태를 직접 바꾸는 일(적 세우기, 무적, 쿨다운, 진화, 자연 생성 막기)은 **시험 도구 안에서만**, 한 파일(`chapter1/tests/support/skill_lab_stage.gd`)에 모아 각 줄에 무엇을 왜 건드리는지 적는다. 골든 리플레이는 바뀌지 않아야 한다(`golden_core.gd` 비교 통과).

## 3. 소리 쪽의 계약(sound-designer)

### 3.1 왜 "소리 자리"가 필요한가
지금 소리 이름은 스킬이 나눠 쓴다(`cold` = 냉기 시전 + 파쇄, `impact` = 세 스킬의 명중, `explosion` = 메테오 착지 + 다른 폭발). 스킬마다 바꿔 끼우려면 스킬 단위의 이름이 따로 있어야 한다. 다만 **아무것도 채택하지 않은 상태의 소리는 지금과 한 표본도 달라지면 안 된다.**

### 3.2 `audio_map.json` 스키마 2(SL3)
```json
{
  "schema_version": 2,
  "chain_lightning": { "A": { "…": "그대로" }, "B": { "…": "그대로" } },
  "slots": {
    "skill.ember.cast":    { "parent": "fire" },
    "skill.ember.hit":     { "parent": "impact" },
    "skill.meteor.cast":   { "parent": "fire" },
    "skill.meteor.land":   { "parent": "explosion" },
    "skill.frost.cast":    { "parent": "cold" },
    "skill.frost.hit":     { "parent": "impact" },
    "skill.frost.shatter": { "parent": "cold" },
    "skill.arc.cast":      { "parent": "lightning", "per_targets": 3 },
    "skill.arc.hit":       { "parent": "impact" },
    "descent.ember.call":  { "parent": "" },
    "descent.frost.call":  { "parent": "" },
    "descent.arc.call":    { "parent": "" }
  },
  "adopted": {}
}
```
- 위 표는 최소한이다. 진화한 냉기·번개, 강림의 휩쓸기·끝 같은 자리를 더할지는 sound-designer가 D24의 이벤트(`descent_*`)와 `docs/AUDIO-PLAN.ko.md`를 보고 정한다. 자리 이름은 `<무리>.<대상>.<순간>`.
- `parent`: 채택된 파일이 없을 때 울릴 지금의 소리 이름. `""`이면 채택 전에는 무음(강림은 지금도 무음이므로 달라지는 것이 없다).
- `per_targets`: 번개처럼 맞힌 수에 따라 파일을 고르는 자리. 파일 목록의 `min(맞힌 수, per_targets)`번째. 지금의 `arc_path_1..3`과 같은 뜻.
- `adopted`: `{자리: {"files": ["res://…"], "candidate": "<후보 id>", "date": "YYYY-MM-DD"}}`. 채택된 자리는 `SILENT`의 적용을 받지 않는다(SL5: 번개를 채택하면 일반 실행에서 번개가 울린다).

**경로(`audio_routes.gd`)**: 요청에 `slot` 칸을 더한다(`cue`는 지금 그대로 둔다). 어느 이벤트가 어느 자리인지(시전·명중·파쇄의 `skill_id`, 진화 여부 `evolved`, 메테오 착지 `explosion.meteor`, 강림 이벤트)를 이 파일 한곳에서 정한다.

**재생(`combat_audio.gd`)**: 소리를 고르는 차례 = 시험용 끼움(`audition`) → `adopted` → `parent`의 지금 파일. 쿨다운·이득·음높이는 부모 소리의 것을 쓴다(자리마다 따로 두는 것은 2차). 더할 함수:
```
func audition_set(slot: String, paths: Array) -> Dictionary   # {"ok": bool, "loaded": [...], "errors": [...]}. res:// 또는 저장소 안의 절대 경로
func audition_clear(slot: String = "") -> void                 # 빈 이름이면 전부
func reload_map() -> void                                      # audio_map.json의 adopted를 다시 읽음
var audition_log: Array                                        # audition_set을 한 번이라도 부른 뒤에만 쌓임: {tick, slot, cue, path}, 최대 200
```
부르지 않으면 아무 일도 하지 않는다(일반 실행에 들 비용 없음). 시험 인수 `--chapter1-chain-audio=A|B`는 지금처럼 돈다(이 길 위에서 다시 짜도 되지만 결과는 같아야 함).

**오프라인 도구**: `tools/dev/audio_mix_offline.py`(와 그것을 쓰는 `audio_scene_audition.py`)가 `combat_audio.gd`의 상수를 읽는다. `adopted`를 모르면 채택 뒤의 장면 비교 영상이 옛 소리로 나온다 — `adopted`를 읽게 고치거나, 못 고치면 그 차이를 도구 머리에 적는다.

### 3.3 채택 도구 `tools/dev/audio_adopt.py`(새로)
```
python tools/dev/audio_adopt.py list [--json]                          # 자리, 지금 걸린 것(채택/부모), 찾은 후보
python tools/dev/audio_adopt.py adopt --slot skill.arc.cast --candidate chain-lightning/round2/C7 [--expect-rev <sha256>] [--dry-run] [--no-import]
python tools/dev/audio_adopt.py revert --slot skill.arc.cast [--expect-rev <sha256>] [--dry-run]
```
- `adopt`: 후보 파일을 `chapter1/art/audio/slots/<자리>/`로 복사(같은 이름의 다른 내용이 있으면 거절) → `audio_map.json`의 `adopted`를 원자적으로 고침(기존 들여쓰기·키 순서·줄바꿈 유지, 바뀐 곳만) → `AUDIO-LEDGER.json`에 행(파일·sha256과, 후보 목록 파일의 출처 칸. 출처가 없으면 `"origin": "unverified"` — 지금 개발을 막지 않는다는 사용자 결정, 2026-11-20) → 통합 에셋 원장(`tools/art/asset_ledger.py`)이 소리 파일을 올리는 규칙이 있으면 그대로 → 임포트(`python tools/dev/run_dev.py --import-only`) → `audio_ledger_check.py`. 결과를 JSON 한 줄(`AUDIO_ADOPT {...}`)로: 쓴 파일, 표의 전후, 검사 결과.
- `--expect-rev`가 지금 `audio_map.json`의 sha256과 다르면 아무것도 쓰지 않고 종료 코드 3(서버는 409로).
- `revert`: `adopted`에서 그 자리를 뺀다. 이 도구가 더했고 아직 커밋되지 않은(`git ls-files`에 없는) 파일은 지운다.
- `--root`(검사용): 다른 폴더를 저장소로 보고 돈다.

### 3.4 후보 목록 파일 `lab-candidates.json`(SL6)
납품 폴더마다 하나. 관리 서버와 `audio_adopt.py`가 `_local/audio/**/lab-candidates.json`을 훑는다. 후보 id = `<_local/audio 기준 폴더>/<key>`.
```json
{
  "schema": 1,
  "title": "체인 라이트닝 2차",
  "delivered": "2026-11-23",
  "by": "codex-astra",
  "candidates": [
    {
      "key": "C7",
      "label": "세 접점의 음이 기음·완전5도·옥타브로 솟는 도약",
      "slot": "skill.arc.cast",
      "files": ["assets/chapter1/art/audio/chain2/c7_1.wav", "assets/chapter1/art/audio/chain2/c7_2.wav", "assets/chapter1/art/audio/chain2/c7_3.wav"],
      "ledger": [ { "file": "c7_1.wav", "pack": "…", "source": "…", "license": "…", "processing": "…" } ]
    }
  ]
}
```
경로는 목록 파일 기준 상대. 1차에 sound-designer가 만들 것: 체인 2차(C1~C8, 출처는 `chain-round2.patch`의 원장 행에서), 체인 1차(A·B, 저장소의 `chapter1/art/audio/chain/` — 이 경우 `files`는 저장소 경로).

## 4. 차수

### 4.1 1차 — 사용자가 오늘·내일 써 볼 가장 작은 온전한 것
- 캐릭터 셋(테사·아일린·베로니카), 형태 셋: 주력 `base` · 진화 `evolved`(화염 = 메테오, 냉기·번개의 진화도 같은 길이라 함께) · 강림 `descent`(세 계열). 합 9가지.
- 적 배치 다섯: 한 마리 · 무리 · 줄 · 우두머리 하나 · 군중. 마리 수 막대(1~40). 다가옴/제자리, 죽지 않음.
- 되풀이(간격 1.5~6초), 지금 한 번 시전, 느리게(0.25·0.5·1), 전투 효과 켜고 끄기, 화면 저장.
- 소리: 그 스킬의 자리 표 → 지금 걸린 것과 후보를 **브라우저에서 낱개 듣기**(파형·길이·최대 dBFS·RMS, 브라우저의 Web Audio로 계산 — 서버는 표준 라이브러리만), **창에 끼우기**, **지금 것으로 되돌리기**, **채택**과 **채택 취소**.
- 스킬의 이름·설명·랭크별 수치·진화 수치(`growth_quality37.json`), 강림의 이름·수치(`descent.json`), 글은 `chapter1/i18n/ko.po` — 매번 파일에서 읽는다(`catalog.py`의 함수를 불러 쓴다, 같은 해석을 두 번 짜지 않는다).
- 효과(이펙트)는 1차에 **바꿔 끼울 후보가 없다**: 효과는 코드와 셰이더라 "파일 하나를 바꾸는" 구조가 아니다. 1차는 켜고 끄기·느리게·적 수로 견주는 데까지.

### 4.2 2차
- 판 안 주문(고리, `run_spells`, `--chapter1-trial=spells`), 스킬 랭크 막대(랭크별 모습), 다른 계열의 스킬을 다른 캐릭터가 쓰기(보조 스킬).
- **한 스킬이 다른 스킬에 주는 영향**(사용자 지침 2026-11-19): 두 스킬을 함께 — 예: 냉기로 얼린 뒤 번개. `run_spells.json`의 `pairs`, `skill_trees.json`의 `synergies`를 페이지에 그림으로(T9 5.1에서 옮김).
- 효과 값 조절 막대: vfx-feel이 `view/fx`의 파일들(`meteor_fx.gd`, `descent_fx.gd`, `chapter_effects.gd`)에 흩어진 모습 상수를 파일마다 한 사전(`LOOK`)으로 모으고 시험용 덮어쓰기 함수를 단 뒤에(강림 묶기가 끝난 다음). 채택은 소리와 같은 길(값 → 데이터 파일, 패치).
- 소리 자리별 이득·쿨다운(`audio_map.json`), 음량 맞춰 듣기 선택, 빠른 A/B 전환 단축키, 시험실 화면을 짧은 영상으로 떠서 남기기(디렉터가 사용자에게 보낼 때).
- 레벨업·물약 등 스킬 아닌 소리(`sfx-batch3/candidates-v2`)의 자리.

### 4.3 3차
장비·재화·적 화면(T9 B4 이후), 효과의 그림·셰이더 후보를 자리표(`asset_slots.json`)로 바꿔 끼우기.

## 7. 위험

| 위험 | 막는 법 |
|---|---|
| 시험 창이 코어 내부 필드를 건드려, 코어가 바뀌면 조용히 깨진다 | 건드리는 줄을 `skill_lab_stage.gd` 한 파일에 모음 + run_all `skill-lab` 검사가 매번 돈다 |
| 무대를 꾸민 탓에 "게임 그대로"가 아닌 곳이 생긴다(적이 시간 경과 체력 보정 없이 섬, 판의 다른 소리가 빠짐) | 표현·소리 코드는 게임 그대로다. 무대의 다른 점은 페이지에 한 줄로 적는다("판의 다른 일은 꺼져 있습니다") |
| 채택이 본 저장소 파일을 바로 고친다 — 다른 담당이 같은 파일을 고치는 중일 수 있다 | `--expect-rev`(sha256)로 낙관적 잠금, 어긋나면 409. git이 되돌림 수단. 커밋은 디렉터. Astra 납품은 `audio_map.json` 패치가 아니라 후보 목록으로(SL7) |
| 채택하지 않은 상태의 게임 소리가 바뀐다 | 소리 요청 기록 비교(SL-A 끝난 기준), `parent` 규칙 |
| 번개를 채택하면 일반 실행에서 번개가 운다(사용자가 2026-11-18에 거슬린다고 해서 무음으로 둔 것) | 의도된 것: 채택은 사용자의 판단이다(SL5). 페이지의 채택 확인 창에 "일반 게임에서 이 소리가 울리게 됩니다" |
| 새 wav의 임포트가 없으면 출하 빌드에 소리가 빠진다 | `audio_adopt.py`가 임포트까지(`repo_lock`이 다른 임포트와 겹치지 않게 함). 실패하면 채택을 되돌리고 알림 |
| 강림의 묶음(vfx-feel)이 진행 중이라 강림 화면이 바뀔 수 있다 | 시험 창은 `call_descent()`만 쓴다. 강림 형태는 vfx-feel 병합 뒤 다시 확인 |
| Godot 창이 포커스를 잃어 멈춤, `godot.py`의 20분 제한 | `--chapter1-qa-ignore-focus`, `--timeout-s=14400`, 60분 무명령 종료 |
| 끼운 소리를 페이지에서 고른 줄과 창이 실제로 쓰는 것이 어긋남 | 창이 `state.audio.overrides`·`recent`를 쓰고 페이지가 그것으로 표시 |
| 동시 Godot 자리(기본 6)를 시험 창이 하나 계속 쥔다 | 60분 무명령 종료, 페이지의 "닫기" |
