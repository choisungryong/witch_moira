# 기술 지시서 T4 — 스팀 배포

2026-11-17, 기술 책임자(tech-lead) 작성. 총괄 디렉터가 배정한다. 각 지시서(T4-B ~ T4-P)는 받는 에이전트에게 그대로 전달할 수 있게 썼다.

사용자 결정(2026-11-17): 글로벌 출시, 배포의 기본은 스팀, 언어팩 적용(T3), 목표 이용 등급은 15세 수준.

**외부 사실 표기.** 이 문서는 웹 조사를 하지 않고 썼다. 스팀·플랫폼의 규격·수수료·정책은 `[기억]`(확신하지만 출시 전 공식 문서로 한 번 더 볼 것)과 `[확인 필요]`(기억이 흐리거나 바뀌었을 수 있음)로 나눠 적는다. 표시 없는 것은 이 저장소에서 직접 확인한 사실이다.

## 디렉터용 요약

1. 지금은 **실행 파일을 만들 수 없다.** `export_presets.cfg` 없음, Godot 사용자 폴더의 내보내기 템플릿 폴더(`%APPDATA%\Godot\export_templates`) 비어 있음. 다만 `C:/Project/rea-tools/godot-4.5.1/templates/`에 Windows용 템플릿 두 개(release·debug, 4.5.1.stable, sha256 기록 있음)가 이미 풀려 있어 내려받기 없이 시작할 수 있다.
2. 그래서 품질 목표 1절의 "실행 빌드 p95"는 한 번도 잴 수 없었다. 첫 일(T4-B)은 내보내기 설정 + 빌드 스크립트 + 빌드 검사이고, 이것이 T2-V(성능 최종 측정)의 조건이기도 하다.
3. 검증용 실행 인수(`--chapter1-pilot`, `--chapter1-profile-off` 등)는 릴리스에서도 그대로 동작한다. 판매본에서는 막고, 측정용 빌드(사용자 정의 기능 태그 `qa`)에서만 켠다.
4. `assert`는 릴리스에서 빠진다. 지금 `assert` 10곳에 부작용은 없다(확인). 다만 빠지면 조용히 넘어가므로 판매본 검사에 릴리스 템플릿 실행을 넣는다.
5. 스팀 연동은 **플랫폼 층 하나**(스팀 없이도 도는 빈 구현 + 스팀 구현)로 감싼다. 코어는 모른다. 후보는 GodotSteam(MIT 라이선스[기억], 4.5.1 대응판은 [확인 필요]).
6. 클라우드 저장: 지금 저장은 매번 `.revision-*.json` 기록본을 새로 만들고 지우지 않는다(`chapter_profile.gd:414·423`). 그대로 자동 클라우드에 올리면 파일이 끝없이 는다. 클라우드 대상은 본 파일과 가리키는 파일로 한정하고, 기록본 보존 개수 규칙이 필요하다.
7. 스팀 덱: 패드 입력이 없다(키보드·마우스 직접 키 코드, InputMap 없음). 화면은 16:10(1280×800)이고 지금 기준 창은 16:9 1600×900이라 위아래 띠가 생긴다. 프레임 시간이 개발 컴퓨터에서도 미달이라(p95 40~56ms) 덱은 T2가 끝나야 판단할 수 있다.
8. 의상 컬렉션(수영복)과 아이의 죽음을 다루는 서사가 있다. 스팀 콘텐츠 설문에 정직하게 표시해야 하고, 15세 수준을 지키는 점검표는 art-lead·narrative-lead 몫. AI 생성 그림 사용은 스팀에 알려야 하는 항목이 있다[확인 필요 — 세부].
9. 스팀웍스 가입·앱 등록비·세금·은행 정보는 **사용자만** 할 수 있다. 에이전트는 대신하지 않는다.
10. 순서: T4-B(빌드) → T4-Q(빌드 검사) → T2-V(실행 빌드로 측정) → T4-P(플랫폼 층·스팀) ∥ T4-I(패드 입력, 큰 일) ∥ T3 → T4-D(덱 대응) → 상점 자료·데모 → 넥스트 페스트.

## 2. Windows 실행 파일 만드는 길

### 2.1 템플릿

두 길이 있다.

| 길 | 방법 | 장점 | 단점 |
|---|---|---|---|
| (가) 사용자 정의 템플릿 경로 | `export_presets.cfg`의 `custom_template/release`, `custom_template/debug`에 `C:/Project/rea-tools/godot-4.5.1/templates/windows_*.exe`를 적는다 | 사용자 폴더를 건드리지 않는다. 내려받기 없음 | 컴퓨터마다 경로가 다르다. 빌드 스크립트가 경로를 확인하고, 없으면 분명한 오류로 멈춘다 |
| (나) 표준 설치 | `export_templates.tpz`에서 `templates/version.txt`와 Windows 두 파일만 `%APPDATA%\Godot\export_templates\4.5.1.stable\`로 푼다 | Godot 기본 동작 | 저장소 밖(사용자 폴더)에 쓴다. 게임 저장 폴더는 아니지만 디렉터 승인 필요 |

권고: **(가)**. 경로는 빌드 스크립트의 환경 변수 `MOIRA_TEMPLATES`(기본값 위 경로)로 받고, 스크립트가 `version.txt`=`4.5.1.stable`과 `acquisition-evidence.json`의 sha256을 확인한 뒤 `export_presets.cfg`의 사본을 `_local/build/`에 만들어 경로를 채워 쓴다(저장소의 `export_presets.cfg`에는 컴퓨터 경로를 넣지 않는다). Godot가 다른 경로의 프리셋 파일을 받는지 확인 필요하면 스크립트가 빌드 직전 저장소 루트의 파일에 경로를 써 넣고 끝나면 되돌리는 방식도 허용한다(되돌림 실패 시 빌드 실패로 처리).

### 2.2 프리셋

| 프리셋 | 템플릿 | 기능 태그 | 용도 |
|---|---|---|---|
| `Windows Store` | release | 없음 | 판매본·데모. 검증 인수 꺼짐 |
| `Windows QA` | release | 사용자 정의 기능 `qa` | 실행 빌드 측정(T2-V, 품질 목표 1절). 검증 인수 켜짐 |
| `Windows Debug` | debug | `qa` | 오류 추적 |

공통 설정
- `exclude_filter`: `chapter1/tests/*`, `*.md`, `chapter1/art/**/README*`, 옛 층 셰이더·스크립트는 옛 층 정리(T1 4) 뒤 제외. `.gdignore` 폴더(`docs/`, `tools/`, `art-archive/`, `_local/`)는 이미 들어가지 않는다(확인 필요: 실제 pck 목록으로).
- `embed_pck`: 하나로(실행 파일 1개). 스팀은 폴더 단위 업로드라 둘 다 되지만, 하나가 다루기 쉽다.
- 아이콘(`.ico`, 16~256 여러 크기)과 파일 버전·회사 이름·제품 이름. Godot 4.5에서 Windows 실행 파일 자원 수정에 외부 도구(rcedit)가 필요한지 [확인 필요].
- 코드 서명: 스팀 배포에는 필수가 아니다[기억]. 서명하지 않으면 스팀 밖에서 받은 실행 파일은 Windows SmartScreen 경고가 날 수 있다. itch.io 등을 낼 때 다시 본다.
- 출력 위치: `_local/build/<날짜-커밋>/<프리셋>/WitchMoira.exe`. 저장소에 올리지 않는다. 스팀에 올릴 묶음은 같은 폴더의 `steam/` 아래에 만든다.

### 2.3 빌드 명령

```powershell
# 가져오기(필요할 때)
python tools/dev/run_dev.py --import-only
# 내보내기(스크립트가 감쌀 명령)
godot --headless --path . --export-release "Windows QA" _local/build/<stamp>/qa/WitchMoira.exe
godot --headless --path . --export-release "Windows Store" _local/build/<stamp>/store/WitchMoira.exe
```

`tools/dev/build.py --preset store|qa|debug`가 위를 감싸고: 템플릿 확인 → 가져오기 → 내보내기 → 결과 크기·sha256·커밋·Godot 판 번호를 `build.json`에 기록 → pck 파일 목록 덤프(테스트·문서가 들어갔는지 확인).

### 2.4 검증용 인수의 릴리스 처리

- `chapter_one.gd`에서 인수를 읽기 전에 `var qa_allowed := OS.is_debug_build() or OS.has_feature("qa")`를 두고, `qa_allowed`가 거짓이면 `--chapter1-pilot`, `-profile-off`, `-qa-ignore-focus`, `-seed=`, `-primary=`, `-quit-after=`, `-capture-dir=`, `-qa-input-log=`, `-frame-probe-dir=`, `-frame-probe-quit`, `-start`를 무시한다. `--chapter1-no-juice`는 접근성 설정이 생기면 그 설정으로 옮기고 인수는 같은 규칙.
- F1 진단 화면도 `qa_allowed`일 때만.
- 판매본에서 이 인수를 줘도 아무 일이 없는지 빌드 검사(T4-Q)가 확인한다.
- 이유: 스팀은 실행 인수를 사용자가 넣을 수 있다. `--chapter1-pilot`이 판매본에서 켜지면 자동 플레이, `--chapter1-capture-dir`는 파일 쓰기다.

### 2.5 `assert` 제거의 영향

- Godot는 릴리스 빌드에서 `assert`를 실행하지 않는다[기억]. 지금 10곳은 모두 부작용 없는 검사라 동작은 같다.
- 다만 검사가 없어진 자리에서 이상 상태가 조용히 넘어간다(예: `chapter_items.gd:48`의 빈 목록 뒤 무작위 선택). 판매본 검사(T4-Q)가 릴리스 템플릿으로 한 판을 끝까지 돌리고 로그 오류 0을 본다.
- 규칙 유지: `assert()` 안에 부작용을 넣지 않는다(CLAUDE.md). T4-Q의 정적 검사가 `assert(` 안의 대입·함수 호출 중 이름이 `set_`, `add_`, `append`, `erase`, `_persist`, `save`로 시작하는 것을 잡는다(거친 검사).

### 2.6 실행 빌드 p95 측정

- `Windows QA` 빌드로 `QUALITY-TARGETS` 1절의 측정을 한다: `WitchMoira.exe --resolution 1920x1080 -- --chapter1-start --chapter1-pilot --chapter1-profile-off --chapter1-qa-ignore-focus --chapter1-seed=11 --chapter1-frame-probe-dir=_local/perf/build-<stamp> --chapter1-frame-probe-quit` (실행 파일 기준 상대 경로가 아니라 절대 경로로 넘기도록 측정기가 확인).
- 편집기 실행과 실행 빌드의 차이를 한 번 기록한다(같은 시드 3회씩). T2-V의 최종 숫자는 실행 빌드 숫자로 한다(T2 지시서와 디렉터 결정 S-D2).

### 3.4 도전 과제

- 정의는 스팀웍스 관리 화면에서 한다[기억]. 아이콘(달성·미달성 두 장) 필요[기억, 규격 64×64 [확인 필요]].
- 판정은 앱 층에서 프로필의 영구 기록(완료 판 수, 마녀별 첫 처치, 깊이)을 읽어 한다. 판 안의 순간 판정(예: "한 판에 정예 10")은 코어 이벤트를 앱이 세서 판 끝에 한 번 부른다. 코어에 도전 과제 코드를 넣지 않는다.
- 이미 달성한 조건을 가진 옛 저장에 대해서는 시작 때 한 번 다시 맞춰 준다(동기화).
- 목록은 design-lead가 명세로(이 문서 범위 밖). 이름·설명은 스팀 관리 화면에서 언어별로 넣는다(T3의 키와 별개 — 용어집만 공유).

### 3.5 클라우드 저장

- 길 둘: (가) **자동 클라우드**(코드 없이 스팀웍스 설정에서 경로·파일 패턴 지정)[기억], (나) 원격 저장 API(GodotSteam). 권고 (가).
- 대상: 루트 `WinAppDataRoaming`, 하위 폴더 `WitchMoira`, 패턴 `chapter-one-profile-v*.json`(본 파일들)과 `chapter-one-profile-active.json`. **`*.revision-*.json`, `*.next-*.json`은 넣지 않는다**(패턴이 겹치지 않게 파일 이름 규칙을 먼저 확인. 지금 `chapter-one-profile-v3.revision-….json`은 `chapter-one-profile-v*.json`에 걸린다 → 자동 클라우드 패턴 문법으로 제외가 되는지 [확인 필요]. 안 되면 기록본을 하위 폴더 `revisions/`로 옮기는 저장 변경이 필요하다 — T4-C에서 D5 규칙(원본 불변)과 함께 설계).
- 기록본 보존: 지금은 지우지 않는다. 판매본에서는 수백 판 뒤 수백 개 파일이 쌓인다. **보존 개수 규칙**(예: 최근 20개 + 하루 1개씩 7일)을 D5 저장 안전 규칙과 함께 정한다(디렉터 결정 S-D3). 지우는 코드는 사용자 저장을 지우는 일이므로 검사를 격리 경로에서 충분히 한 뒤에만.
- 충돌: 두 컴퓨터에서 따로 진행하면 스팀이 어느 쪽을 쓸지 묻는다[기억]. 프로필의 `revision`이 있으므로 게임 안에서 따로 고르게 할 필요는 없다.
- 언어·화면 설정(`settings.cfg`, T3 2.8)은 컴퓨터마다 다를 수 있으니 클라우드에 넣지 않는다(언어는 스팀 설정을 따라가므로 문제없다).
- 스키마 4(D6 S)가 파일 이름을 `-v4`로 바꾸므로 패턴이 그것을 덮는지 확인.

### 3.8 콘텐츠 설문, 성인 콘텐츠, 15세 수준

- 스팀은 앱마다 콘텐츠 설문을 받는다. 항목에 폭력·유혈, 노출·성적 콘텐츠, 일반 성인 콘텐츠 등이 있고, 답에 따라 상점 노출(사용자 필터)이 달라진다[기억]. 문항 구성 [확인 필요].
- 우리에게 걸리는 것:
  - **의상 컬렉션의 수영복**(A3 2.2판 14절). A3의 선 (ㄱ) 성인 (ㄴ) 불투명·맨몸 없음 (ㄷ) 성행위 연상 없음을 지키면 "성인 전용 성적 콘텐츠"에는 해당하지 않을 것으로 보지만, "일부 노출 또는 성적 콘텐츠" 항목에 표시할지는 **[확인 필요]**. 감추지 말고 설문에 정직하게 답하는 것을 원칙으로 한다(나중에 신고·재검토되면 페이지가 내려갈 수 있다[기억, 일반론]).
  - **폭력**: 해골 적을 대량으로 처치. 유혈 표현 정도에 따라 표시.
  - **서사**: 아이의 죽음(화형·감옥·제물)을 다룬다(STORY-REVIEW 26행). 15세 수준에서 직접 묘사를 피한다는 기존 권고를 유지.
- 15세 수준 점검표는 art-lead(그림)·narrative-lead(글)가 A3-U20 결정에 맞춰 만든다. 이 문서는 기술 쪽에서 **상점 자료(캡슐·스크린샷·트레일러)에도 같은 점검표를 적용**하는 것만 정한다 — 상점 자료는 설문과 별개로 모든 이용자에게 보이므로 게임 안보다 보수적으로 고른다(권고).
- 한국 등급 분류의 15세 기준과 스팀 설문은 서로 다른 제도다. 한국 등급 절차는 3.1의 [확인 필요].

### 3.9 AI 생성 그림의 공개

- 지금 원화(세 주인공 `characters/*_witch_v02.png`)와 아이콘 시안은 이미지 생성 도구(Codex 내장 이미지 생성 등)로 만든다.
- 스팀은 AI 생성 콘텐츠를 쓰는 게임에 콘텐츠 설문에서 그 사용을 설명하게 하고(미리 만든 콘텐츠 / 실행 중 생성하는 콘텐츠 구분), 그 설명 일부가 상점 페이지에 표시된다고 기억한다. **[확인 필요]** — 2024년 초에 생긴 규정으로 기억하며, 이후 바뀌었을 수 있다.
- 함께 확인할 것: (1) 생성 도구의 이용 약관이 상업 배포를 허락하는지(DECISIONS I6), (2) 생성물에 타인의 저작물·상표가 들어가지 않았다는 점검 기록, (3) 실행 중 생성은 하지 않는다는 점(우리는 해당 없음).
- 기술 쪽 할 일: 원화·아이콘마다 출처(생성 도구, 날짜, 프롬프트 파일, 사람이 고친 정도)를 적는 표를 유지한다. `chapter1/art/characters/ATTRIBUTION.ko.md`가 이미 있으니 같은 형식으로 아이콘·의상까지 넓힌다(asset-producer). 설문에 답할 근거가 된다.

### 3.10 데모와 넥스트 페스트

- 데모는 본편과 연결된 **별도 앱**(무료)으로 낸다[기억]. 빌드는 같은 코드에 기능 태그 `demo`로 제한(첫 마녀만, 깊이 1만, 판 수 제한 없음 등 — design-lead가 범위 결정). 데모 저장은 본편과 폴더를 나눌지 결정(S-D4. 권고: 나눈다, `WitchMoiraDemo`. 본편으로 옮기기는 하지 않는다 — 단순하게).
- 넥스트 페스트는 1년에 세 번(대략 2월·6월·10월) 열리고, 아직 출시 전인 게임이 데모를 내고 참가한다. 한 게임은 한 번만 참가할 수 있다[기억]. 등록 마감이 행사 몇 주 전이다 [확인 필요].
- 데모에도 T3 1차 언어, 덱 대응(가능하면), 크래시 없음이 필요하다.

## 4. 지시서

공통 규칙
- 별도 작업 폴더에서 일한다. 커밋·푸시는 하지 않는다.
- 빌드 결과물은 `_local/build/` 아래에만. 저장소에 올리지 않는다.
- 사용자 저장(`%APPDATA%\WitchMoira`)을 읽거나 쓰지 않는다. 빌드 실행 검사는 `--chapter1-profile-off`(QA 빌드) 또는 격리 경로. **판매본(`Windows Store`) 실행 검사는 저장을 끌 수 없으므로 실행 전 `APPDATA`를 `_local/build/<stamp>/appdata/`로 바꾼 환경에서 띄운다**(사용자 저장 폴더를 건드리지 않는다는 것을 실행 뒤 그 격리 폴더에 파일이 생긴 것으로 보인다).
- Godot 창 실행은 다른 Godot 측정·캡처가 돌지 않을 때 한 번에 하나.
- 외부 내려받기(GodotSteam, 스팀웍스 SDK, 패드 아이콘)는 디렉터·사용자 승인 뒤.
