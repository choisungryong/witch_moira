# 역할별 도구 수요 검토 (2026-11-19)

총괄 디렉터 정리. 사용자 지시: "각 에이전트마다 필요한 도구를 만들고 활용할 수 있게 하는 게 좋을 것 같다. 모든 에이전트들한테 그런 케이스가 있는지 검토해서 보고하게 하라."

배경: 균형 측정을 실제 코어의 한 판 전체로 재다가(120판에 약 1시간) 계산 모델 `tools/dev/balance_sim.py`를 만들었더니 360판이 9초가 됐다.

조사 방법: 15개 역할이 각자 읽기 전용으로 조사했다(Godot·회귀·생성 실행 없음). 아래의 시간 절감은 로그와 파일 구조에서 셈한 **추정**이고 실제로 잰 값이 아니다. `content-balance`와 `manager-tools`는 진행 중인 작업의 보고에 붙여 오기로 했다(이 문서를 쓸 때 미도착). 역할별 요약 원문은 `_local/tool-review/SUMMARY.txt`.

## 3. 이미 있는데 안 쓰고 있던 것

- `golden_core.gd -- --case=<키>`: 코어를 고치는 동안에는 사례 하나만 돌린다.
- `hud_dump.gd --until=<틱>`: 앞 구간만 볼 때 한 판 8~11분이 1~3분이 된다. 검수 스크립트들이 쓰지 않았다.
- `hud_dump.gd --dump`의 Control 사각형: 배치 점검의 재료가 이미 있다.
- `skill_tree_preview.gd`: 코어 없이 화면만 띄우는 선례.
- `run_all.py --only`, `--quick`, `--json`.
- `audio_mix_offline.py --stats`, `audio_measure.py --compare-s1`.

## 5. 의견이 갈린 곳

- **순간 이동 캡처.** 이펙트는 가장 원했고, 화면·연출 관리는 권하지 않았다(바닥 자국이나 효과 누적 같은 표현 상태가 실제 플레이와 달라져 검수 근거로 쓸 수 없다). 정리: 작업 중 **빠른 점검용**으로 만들고, **검수는 실제 한 판 캡처**로 한다. 도구의 출력에 그 구분을 적는다.
- **스스로 접은 후보.** 이펙트는 "기준작 화면과의 자동 대조"를(기준은 사람이 본다), 에셋 제작은 "유료 생성 호출 감싸개"를(자동 결제 길이 될 수 있다) 만들지 않기로 했다.

## 6. 권고 순서

1. **T1 회귀 빠르게** — 모든 역할이 커밋마다 기다리는 시간. 판 안 스킬 구성 구현이 `run_all.py`를 고치는 중이라 그것이 끝난 직후.
2. **짧은 시험장**(`sim_power.gd`, 명세에 이미 있음) — 시뮬레이터의 가설 상수를 실측으로 고정. 같은 시점.
3. **T2 캡처 전후 비교 + T3 배치 점검** — 화면 작업(화면·효과 지시서의 묶음들)이 시작되기 전에.
4. **기획의 목표 판정표와 선택의 갈림 측정** — 수치를 맞추는 단계(시뮬레이터 2차 뒤)에.
5. **낱말 검사기** — 새 스킬·카드·퀘스트 이름을 짓기 전에.
6. **G1 에셋 출처 원장** — 유료 생성 전에.
7. 나머지(T4·T5·T6, 사람 플레이 기록, 장면 렌더러, 초상 파생 그림 등)는 해당 작업이 시작될 때.

## 7. 공통 원칙(모든 도구에)

- 도구의 답을 사실로 적지 않는다. 모델·수치 판정은 근거일 뿐이고, 재미와 미감은 사용자 플레이로만 채운다. 출력에 "무엇을 보지 않았는가"를 찍는다.
- 일회용 스크립트를 `_local/`에 다시 쓰지 않는다. 두 번 쓴 것은 `tools/`나 `chapter1/tests/`로 올린다.
- 비용이 나가는 길(유료 생성, 결제)을 도구가 자동으로 밟지 않는다.
- 소리 재료는 로컬에서 신호 측정만 한다. 다른 AI 모델의 입력으로 넘기지 않는다.
- 성능 측정과 병렬 실행을 같은 시간에 돌리지 않는다.
