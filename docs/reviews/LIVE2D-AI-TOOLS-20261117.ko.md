# 그림 한 장 → Live2D 자동화 도구 조사 (2026-11-17)

조사 방법: 웹 검색과 공식 페이지 읽기만 했다. 가입, 결제, 내려받기, 생성은 하지 않았다. 외부 서비스에 그림이나 프로젝트 정보를 보내지 않았다.
모든 항목의 확인 날짜는 2026-11-17이다.

표기:
- **[공식]** 그 회사·저자의 페이지를 직접 읽었다.
- **[2차]** 제3자 글이나 검색 요약이다. 틀릴 수 있다.
- **확인 못 함** 찾지 못했거나 페이지가 열리지 않았다.

**어떤 도구의 결과물도 직접 보지 않았다.** 아래의 품질 서술은 전부 문서와 남의 평에서 온 것이고, 우리 원화(반실사 회화풍 전신, 1024×1536)로 시험한 결과가 아니다.

---

## 1. 요약

**그림 한 장을 넣으면 게임에 바로 쓸 수 있는 진짜 Live2D 모델(.moc3)이 나오는, 지금 돈 내고 쓸 수 있는 서비스는 찾지 못했다.** 기획자가 기억하는 것에 가장 가까운 것은 연구 단계의 결과물들이다. 2026년 7월 논문 「Bunraku」가 "그림 한 장 → 겹 분리 → 메시 → 움직임"을 끝까지 자동으로 한다고 발표했지만, 공개 저장소에는 설명 파일 하나뿐이고 코드와 모델은 올라와 있지 않다. 알리바바의 「CartoonAlive」(2025)는 초상 한 장에서 Live2D 모델을 만든다고 하지만 얼굴과 머리카락만 다루고 미리 만든 틀 모델에 끼워 맞추는 방식이다. 실제로 쓸 수 있는 수준까지 온 것은 **앞 단계인 "겹 분리"** 뿐이다(「See-through」, 공개 코드, PSD 출력). 리깅(메시·변형·매개변수)은 여전히 사람이 Cubism Editor에서 한다. Live2D사의 자동 기능도 "이미 겹이 나뉜 PSD"를 전제로 한 보조 기능이다. Sunra와 Higgsfield에는 Live2D를 만드는 기능이 없고, 둘 다 "그림 → 영상" 쪽이다.

## 4. Sunra에서 찾은 것

- **Live2D 생성, 겹 분리, "인물 그림 살리기" 전용 모델은 보이지 않는다.** 공개 목록과 문서에서 확인한 범위 안에서다.
- 확인한 모델 이름
  - 플랫폼 목록 첫 화면 [공식] https://platform.sunra.ai/models : Nano Banana 2.1, Seedream 5.0 Pro, Seedance 2.5, Kling v3 Pro, Eleven v3 등. "More" 뒤의 전체 목록과 기능 설명은 읽히지 않았다.
  - 문서의 고정 주소 목록 [공식] https://docs.sunra.ai/multimodal/canonical-model-endpoints.md : `kling/kling-v3-4k`(글→영상, **그림→영상**), `kling/kling-v3-omni-4k`(+참조→영상), `google/veo3-1`·`-fast`·`-lite`, `bytedance/seedance-2.0`·`-fast`, `openai/gpt-image-2`(그림 편집 포함), `midjourney/v7`·`v8.1`.
  - 그림→영상 문서 [공식] https://docs.sunra.ai/multimodal/image-to-video.md : `kling/kling-v2-master/image-to-video`(입력 `start_image`, `duration` 등), `minimax/i2v-01/image-to-video`(6초).
- **끝 장면(마지막 프레임) 지정**: Sunra 문서에서는 확인 못 함. 반복 영상에는 "시작과 끝이 같은 그림"이 중요하므로 실제 모델 화면에서 확인해야 한다.
- 값 [공식] https://sunra.ai/pricing : 요금제(연 결제 기준) Basic 월 9달러·1,200크레딧, Pro 월 17달러·3,500크레딧, Creator 월 63달러·17,000크레딧. 충전은 1달러 = 100크레딧. API는 달러 선불 잔액. **모델별 값은 이 페이지에 없다**("만든 곳의 값 그대로"라고만 적혀 있다) → 영상 한 편의 값은 확인 못 함. 생성 전에 화면에 크레딧이 표시된다고 한다.
- 상업 이용 [공식] https://sunra.ai/terms (2026-10-28 개정): 결과물의 소유권을 주장하지 않으며 "상업 목적을 포함한 합법적 목적"에 쓸 수 있다. 요금제에 따른 결과물 권리 차이는 없다. 비슷한 결과가 다른 사용자에게도 나올 수 있어 독점성과 저작권 보호는 보장하지 않는다.

## 5. Higgsfield에서 찾은 것

- **Live2D 생성이나 겹 분리 기능은 찾지 못했다.** 그림→영상 서비스다(Kling, Seedance 등 여러 모델을 묶어 제공).
- **반복되는 "숨 쉬는 초상" 영상**: 시작·끝 프레임(Start & End Frame) 기능이 있고, Higgsfield 안내 글이 "같은 그림을 시작과 끝에 둘 다 넣는" 방법을 반복 영상 방법으로 든다 [공식 블로그, 검색 요약으로 확인] https://higgsfield.ai/blog/Kling-Start-End-Frames . Kling 3.0이 시작·끝 프레임을 받는다고 한다 [2차]. 반복 이음매의 품질에 대한 평은 찾지 못했다.
- 값: **공식 요금 페이지는 내용이 그림으로 되어 있어 읽히지 않았다**(https://higgsfield.ai/pricing). 제3자 글들은 서로 다르다 [2차]: 입문 요금제 월 9~19달러(크레딧 120~270), 위 단계 월 47~59달러(1,000~1,200크레딧), Kling 3.0 5초(720p)에 7~10크레딧쯤. 시작·끝 프레임이 어느 요금제부터 되는지도 글마다 다르다. 생성 단추에 실제 크레딧이 표시된다고 한다.
- 상업 이용 [공식 도움말] https://higgsfield.ai/creator-hub/help-center/account-and-privacy/who-owns-my-generations-and-can-i-use-them-commercially (2026-09-12 수정): 결과물 소유권을 주장하지 않고 상업 이용을 제한하지 않는다. 요금제와 무관하다. 다만 무료 쪽은 워터마크가 박힌다. **올린 그림과 결과물을 Higgsfield가 자기 모델 학습에 쓸 수 있다**(기업 요금제만 제외). 약관 원문 페이지는 주소를 찾지 못해 직접 읽지 못했다(추측한 주소는 404).
- 주의: 우리 원화를 올리면 학습에 쓰일 수 있다는 점은 Sunra보다 불리하다.

## 6. 대안 경로의 사실 확인

### (가) 그림 → 짧은 반복 영상을 메뉴에 넣기

- Godot 4.5의 기본 영상 재생은 **Ogg Theora(.ogv)만** 된다. H.264/H.265는 특허 때문에 없고 WebM은 4.0에서 빠졌다. [공식] https://docs.godotengine.org/en/4.5/tutorials/animation/playing_videos.html
- 반복 재생은 `VideoStreamPlayer`의 Loop 속성으로 된다. 영상 지연 보정 값이 0이 아니면 이음매가 어긋날 수 있다. [공식] 같은 페이지
- **투명 배경(알파) 영상은 기본 지원이 없다.** 공식 문서가 안내하는 방법은 크로마키 셰이더(특정 색을 지움)뿐이다. [공식] 같은 페이지
- Theora는 CPU로 푼다. 공식 권고는 데스크톱 1080p 이하, 30fps, `ffmpeg -q:v 6 -g:v 64`. [공식] 같은 페이지
- 알파가 있는 WebM을 재생하는 Godot 4용 확장: `gdwebm`이 있으나 VP8/VP9는 "앞으로 할 기능"에 있다고 한다 [2차]. 쓸 수 있는 것을 확인 못 함.
- 파일 크기: 측정하지 않았다. 세로 전신 5초 반복 영상은 Theora 품질 6에서 수 MB일 것으로 **추정**한다(확인 필요).
- 실무상 길: 캐릭터를 단색 배경 위에 두고 영상을 만든 뒤 크로마키로 빼거나, 메뉴 배경까지 포함한 불투명 영상으로 쓴다. 회화풍 원화는 머리카락 가장자리에서 크로마키 테두리가 남기 쉽다(일반적인 한계, 직접 보지 않았다).
- 참고: Cubism 5.3은 투명 배경 WebM 내보내기가 있지만 Godot는 WebM을 재생하지 못한다.

### (나) Live2D Cubism SDK 배포 조건과 Godot 연동

- **배포 라이선스** [공식] https://www.live2d.com/en/sdk/license/ , https://www.live2d.com/en/sdk/license/purchase_plan01/
  - 개인과 **소규모 사업자(최근 연 매출 1,000만 엔 미만)는 계약과 요금이 면제**된다. "확장형 응용 프로그램"(아바타 시스템 등)은 예외다. 일반 게임은 해당하지 않는다.
  - 콘솔·PC 일회 구매형(F 요금제): 중규모(1억 엔 미만) 60만 엔 일시불 또는 판매 1개당 40엔, 대규모 360만 엔 또는 1개당 40엔(최소 3만 개). 할인 조건으로 Live2D 로고 표시와 쇼케이스 게재가 붙는다.
  - 계약 대상이면 출시 한 달 전까지 계약을 마쳐야 한다. 매출이 1,000만 엔에 닿으면 지위가 바뀐다. 매출 큰 회사의 자회사는 소규모로 인정되지 않을 수 있다 [2차 요약, help.live2d.com].
  - Cubism Editor(제작 도구)의 요금은 이번에 확인하지 않았다 → 확인 못 함.
- **Godot 4 연동: 공식이 없다. 비공식 `GDCubism`이 있다.**
  - 저장소 [공식] https://github.com/MizunagiKB/gd_cubism · 문서 https://mizunagikb.github.io/gd_cubism/gd_cubism/0.9/en/index.html
  - 스스로 "비공식 GDExtension"이라 하고, Live2D사에 문의하지 말라고 적었다. GDScript와 C#에서 쓴다.
  - 라이선스: GDCubism 자체는 MIT. 빌드할 때 Cubism Core(Live2D 독점 라이선스)와 Cubism Native Framework(Live2D 공개 소프트웨어 라이선스)가 묶이므로 배포할 때는 Live2D 조건을 따라야 한다. [공식] https://mizunagikb.github.io/gd_cubism/gd_cubism/0.9/en/license.html
  - 대응 판: "Godot 4.3 이상". **4.5를 이름으로 든 문장은 없다 → 4.5.1 동작은 확인 못 함.** 윈도우 x86_64 지원.
  - 최신 릴리스 v0.9.1(3월 27일, 연도는 페이지에 안 보임. 0.9에서 그리기 방식이 직접 그리기로 바뀌었다). 커밋 411개. 미리 빌드된 바이너리가 붙어 있는지, 마지막 커밋 날짜는 확인 못 함. Cubism SDK for Native를 따로 받아 직접 빌드해야 할 가능성이 있다.

## 7. 이 게임에 권하는 길

유료 항목은 전부 **사용자 승인 뒤에만** 결제·생성한다. 원화를 외부 서비스에 올리는 일도 승인 대상으로 본다.

### 길 A — Godot 안에서 직접 움직이기(겹 몇 장 + 셰이더·트윈)

- 내용: 원화를 서너 겹(몸, 머리카락, 옷자락, 손에 든 것 정도)으로만 나누고 Godot의 2D 메시 변형이나 셰이더로 숨, 머리카락·옷 흔들림, 눈 깜빡임을 준다. Live2D도 영상도 쓰지 않는다.
- 비용: 0원(로컬 작업). 겹 분리를 See-through로 시도하면 설치 시간만 든다.
- 사람 손: 겹 나누기와 가려진 곳 채우기(캐릭터당 반나절~하루 추정), 움직임 조정.
- Godot에 넣기: `view/` 쪽 표현 코드만. 외부 라이브러리와 라이선스 계약이 없다. 투명 배경이 그대로 되고 해상도 손실이 없다.
- 위험: 고개 돌리기 같은 큰 움직임은 못 한다. See-through가 반실사 화풍에서 쓸 만한 겹을 줄지 모른다(8GB에서 도는지도 미확인). 안 되면 손으로 나눈다.

### 길 B — 그림→영상으로 반복 영상을 만들어 넣기

- 내용: 원화를 시작·끝 프레임으로 둘 다 넣어 3~5초 반복 영상을 만들고, Theora로 바꿔 `VideoStreamPlayer`로 튼다.
- 비용: Sunra는 이미 쓰는 계정의 크레딧으로 가능하다(모델별 값은 생성 화면에서 확인해야 한다. 캐릭터 셋에 재시도를 넉넉히 잡아도 수 달러~십수 달러로 **추정**). Higgsfield는 입문 요금제 월 9~19달러쯤 [2차].
- 사람 손: 가장 적다. 프롬프트와 고르기, 변환.
- Godot에 넣기: 기본 기능만으로 된다. 단 **투명 배경이 안 되므로** 배경 포함 영상으로 쓰거나 크로마키를 쓴다.
- 위험: 영상 모델이 얼굴과 붓 자국을 바꿔 버릴 수 있다(원화와 달라 보임). 반복 이음매가 튈 수 있다. 1024×1536 원화보다 흐려질 수 있다. Higgsfield는 올린 그림이 학습에 쓰일 수 있다. 캐릭터 선택 화면에서 셋을 동시에 틀면 CPU 디코딩 부담이 있다.

### 길 C — 진짜 Live2D(겹 분리 + 손 리깅 + GDCubism)

- 내용: See-through나 Live2D 소재 분리 플러그인으로 PSD를 만들고, Cubism Editor에서 리깅(자동 변형기·자동 메시 활용)한 뒤 GDCubism으로 Godot에 넣는다. 리깅을 외주로 맡길 수도 있다.
- 비용: SDK 배포는 연 매출 1,000만 엔 미만이면 무료. Cubism Editor 요금과 외주 단가는 이번에 확인하지 않았다.
- 사람 손: 가장 많다. 리깅을 배우거나 맡겨야 한다.
- Godot에 넣기: 비공식 확장을 빌드해 넣는다. 4.5.1 대응이 확인되지 않았고 유지가 한 사람에게 달려 있다.
- 위험: 연동이 깨지면 출시가 막힌다. 매출이 기준을 넘으면 계약과 요금이 생긴다. Bunraku의 코드가 공개되면 사정이 바뀔 수 있으니 그때 다시 본다.

### 권고

먼저 **길 A를 캐릭터 한 명으로 시험**한다(돈이 들지 않고, 실패해도 만든 겹은 길 C의 재료가 된다). 더 큰 움직임이 필요하다는 판단이 서면 **길 B를 한 편만** 만들어 원화와 나란히 놓고 비교한다. 길 C는 지금 권하지 않는다.

## 8. 사용자가 정할 것

1. **어느 길로 갈까.** 선택지: A(직접 움직이기) / B(반복 영상) / C(Live2D). 권고: A부터, 필요하면 B 한 편 비교.
2. **원화를 외부 서비스에 올려도 되는가.** See-through 온라인 시연, Sunra, Higgsfield 모두 해당한다. 권고: 로컬 실행을 먼저 시도하고, 올린다면 학습에 쓰지 않는 쪽(Sunra)을 먼저 쓴다.
3. **길 B를 한다면 어느 서비스.** 권고: 이미 쓰는 Sunra에서 Kling 계열 그림→영상을 한 편(값은 생성 화면에 표시되는 크레딧을 보고 승인받는다). Higgsfield는 새 구독이 필요하다.
4. **움직임의 범위.** 숨·흔들림·깜빡임이면 A로 충분하다. 고개 돌리기·표정 변화까지 원하면 B나 C가 필요하다.
5. **8GB 그래픽카드에 See-through를 설치해 볼지.** 내려받기 용량과 가중치 라이선스를 먼저 확인한 뒤 진행한다.

## 9. 확인하지 못한 것

- 모든 도구의 실제 결과물 품질(하나도 직접 보지 않았다). 특히 반실사 회화풍 전신 그림에서의 결과.
- Bunraku: 코드·모델 공개 일정, .moc3/.cmo3 출력 여부, 라이선스.
- CartoonAlive 저장소의 공개 범위와 라이선스.
- See-through: 모델 가중치의 라이선스(상업 이용), 윈도우 설치 가능 여부, 8GB에서의 실제 동작과 시간.
- Qwen-Image-Layered: 모델 카드의 라이선스, 8GB 동작, 캐릭터 부위 분리 품질.
- Live2D: 소재 분리 플러그인 페이지 본문, 5.4의 공식 기능 목록, Cubism Editor 요금, 자동 메시 생성기 본문.
- Sunra: 전체 모델 목록("More" 뒤), 모델별 값, 끝 프레임 지정 지원, 겹 분리 모델 유무(공개 화면에서는 안 보였다).
- Higgsfield: 공식 요금(페이지가 그림이라 읽히지 않음), 약관 원문, 시작·끝 프레임이 되는 요금제, 반복 이음매 품질.
- Godot: 알파 영상을 재생하는 4.5용 확장의 유무, 반복 영상의 실제 파일 크기와 CPU 부담.
- GDCubism: Godot 4.5.1 동작, 미리 빌드된 바이너리 유무, 마지막 커밋 날짜, 필요한 Cubism SDK 판.
- Inochi2D: Godot 바인딩의 대응 판과 윈도우 빌드, 최근 릴리스.
- Spine: 자동 가중치 등 자동화 기능의 출시 여부, spine-godot의 4.5.1 문제 해결 여부.
- anysplit, PNGAL, Komiko 등 제3자 겹 분리 서비스의 값과 약관(광고성 자료뿐이라 다루지 않았다).
