## 1. 무엇이 걸렸나

- [보고] 시뮬레이터 10,000판(모든 판을 승리로 셈, 시드 하나): 운 3000 전설 +12.2%(K 4000) / +18.4%(15000) / +24.9%(40000) / +23.6%(100000). 운 1000은 넷 다 +6% 아래(최대 +5.2%).
- [코드] 일반 몹 등급 가중치의 전설이 30이다. `w*(10000+L*K/(L+K))/10000`을 정수로 내리면 운 1000에서 K와 무관하게 32(+6.7%)에 갇히고, 운 3000에서는 35/37/38 세 칸만 있다. 40000과 100000이 뒤집힌 것도 이 칸과 굴림 잡음이다.
- [코드] `_weighted`는 가중치 합 안에서 `randi_range` 한 번을 쓴다. 가중치 전체를 같은 배수로 키워도 난수를 쓰는 횟수는 같고, 비율은 그대로다.
- 따라서 운 1000 조건을 막는 것은 K가 아니라 **가중치의 눈금**이다. 조건을 내리면 결과에 맞춰 목표를 옮기는 것이 된다.

## 2. 결정

## 3. 배정문

### GS-LK1 운 가중의 눈금 (gameplay-systems, 작업 트리 새로 `wt-luck-scale`, main `98b8ae4`에서)

고칠 파일:
1. `chapter1/core/loot.gd` `quality_weights`: 위 LKB1 그대로. 상수 `LUCK_WEIGHT_SCALE := 100`. 운 가지 안에서만 복사본을 만들고(사당만 걸린 복사본이면 그것을) 모든 등급에 곱한 뒤 공식을 적용한다. 122~124행 주석을 새 계산으로 고친다. `roll_class`·`_weighted`·`luck` 블록 검증은 고치지 않는다.
2. `chapter1/tests/test_loot.gd`: LK2(운 0·꺼짐·mods 없음이 데이터 사전과 글자까지 같음)는 **그대로 통과해야 한다**. LK3의 `luck_expected`를 새 계산으로 고치고, "일반·마법 그대로" 검사를 "일반·마법은 정확히 100배"로 바꾼다. 하나를 더한다: 일반 등급, K 4000·15000·40000에서 운 1000의 전설 가중이 3000×(10000+1000K/(1000+K))/10000과 같고 3200보다 크다. LK4~LK6은 고치지 않고 통과해야 한다(LK6의 기대 분포는 `quality_weights`에서 읽으므로 비율이 맞으면 통과).
3. `chapter1/tests/sim_loot.gd`: `--seed=N`(기본 4141). 인수가 없으면 `LOOT_SIM` 출력은 글자까지 그대로. `LOOT_LUCK_PROBE`의 `weights_on`이 100배 눈금이 되는 것은 정상이다(머리 주석에 한 줄).

명령(작업 트리에서):
```
python tools/dev/run_all.py --only loot
python tools/dev/godot.py --headless --path . --script res://chapter1/tests/golden_core.gd -- --both
python tools/dev/godot.py --headless --path . --script res://chapter1/tests/sim_loot.gd -- --runs=10000
python tools/dev/godot.py --headless --path . --script res://chapter1/tests/sim_loot.gd -- --runs=10000 --affix-rolls=on
```
판정:
- `test_loot` 전부 통과.
- 골든 `--both`: `mismatches`가 `luck-on` 건(보통·글 뺀 것 각각)뿐이면 정상. **그 밖의 건이 하나라도 바뀌면 멈추고 보고한다**(꺼진 경로를 건드렸다는 뜻이다). `--update`는 하지 않는다(CB-LK2 뒤 한 번).
- `LOOT_SIM` 두 줄이 main과 글자 단위로 같다(`cmp`). 다르면 멈춘다.
보고: `_local/luck-scale/REPORT.txt`, 패치 `loot-scale.patch`.

### CB-LK2 K 확정 (content-balance, GS-LK1을 받은 같은 작업 트리, `loot.json`의 `luck.k.legendary`만)

1. K 40000에서 운 0·1000·3000 × 시드 4141·4142·4143, 각 10,000판(옵션 굴림 켬):
```
python tools/dev/godot.py --headless --path . --script res://chapter1/tests/sim_loot.gd -- --runs=10000 --affix-rolls=on --luck=1000 --seed=4142
```
2. 표: 시드별과 합친 30,000판의 판당 전설·고유·희귀, 같은 시드의 운 0 대비 증가율. "시뮬레이터 10,000판 × 시드 3, 모든 판을 승리로 셈(모델의 답)"이라고 적는다.
3. 판정(합친 값): 운 3000 전설 +18~30%, 운 1000 전설 +6% 이상, 운 3000 고유 ≤ 0.28. 희귀 +12% 넘으면 표시. 통과하면 40000으로 둔다. 운 1000이 못 넘으면 25000·100000을 같은 방법으로 재어 가장 작은 통과 K를 적는다. 셋 다 못 넘으면 값을 넣지 말고 멈춘다(design-lead).
4. 확정 K를 넣은 뒤: `golden_core.gd -- --both` → `mismatches`가 `luck-on`(보통·글 뺀 것)뿐인지 확인 → 새 해시와 "눈금 100배 + K 4000→확정 값" 두 까닭을 보고에 적고 그 건만 `--update`. 다른 건이 바뀌면 멈춘다. `sim_loot --runs=10000`·`--runs=10000 --affix-rolls=on`의 `LOOT_SIM`이 main과 글자 단위로 같은지 다시 확인. `python tools/dev/run_all.py --quick` 통과.
5. 보고: `_local/luck-k2/REPORT.txt`, 패치 `luck-k2.patch`(GS-LK1 패치와 따로). `luck.enabled`는 false.
