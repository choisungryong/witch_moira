## 2. 뼈대를 메시에서 계산하기

쓴 것은 (가) 메시 자체의 측정과 (나) 키 대비 몸 비율이다. 손으로 찍은 좌표는 없다.

- 측정: 키(꼭대기 높이), 양손 끝(가장 먼 정점 군의 무게중심), 장화(바닥 판의 좌우 발 중심과 발끝), 몸통·머리 중심선.
- 비율: 어깨 높이 0.805, 골반 0.575, 무릎 0.30, 발목 0.054 등 8등신 비율. 팔꿈치·손목은 어깨→손 끝 직선의 0.40·0.71 지점(A자세에서 팔이 곧다는 가정).
- 뼈 이름은 게임이 기대는 이름 그대로(`origin`, `pelvis_cr`, `spine_cr_01~03`, `neck_cr`, `head_cr`, `shoulder/upper_arm/forearm/hand_cr_l/r`, `thigh/shin/tarsal/toe_cr_l/r`)에 지팡이 자리용 빈 뼈 `finger_middle.01.r`(손 뼈의 자식, 가중치 없음)을 더해 24개. 손가락 뼈 30개는 뺐다(화면에서 4픽셀).
- 배운 것 하나: 몸통 중심선을 "중앙값"이나 "앞뒤 한가운데"로 재면 망토와 안감 때문에 뒤로 치우쳐 뼈가 몸 밖으로 나온다. **앞쪽 표면(2번째 백분위)에 몸 두께의 절반을 더하는 방식**으로 바꾸자 뼈가 몸 안에 들어왔다(옆모습 렌더를 직접 봄).
- 한계: 긴 겉옷이 다리를 가려 **다리 안쪽은 재지 못한다.** 엉덩이 너비는 발 너비의 절반이라는 비율에 의존한다. 이 조건은 바지·치마 차림의 마녀에서는 완화된다(다리가 보이므로).

## 4. 동작을 코드로

**방법 (가) 코드로 키를 찍는 절차식 동작** — 했다. 직접 짠 2-뼈 IK(다리), 팔은 방향 지정(위팔·아래팔), 척추는 축 회전. 프레임마다 모든 뼈의 포즈를 계산해 30fps로 찍었다.

| 클립 | 내용 | 직접 본 결과(Blender 6프레임 시트, 앞·옆) |
|---|---|---|
| idle 1.2초 | 호흡, 체중 이동, 두 발 고정 | 읽힘. 정지 자세로 자연스러움 |
| run 0.6초 | 디딤 발이 땅 속도로 뒤로 감. 한 주기 거리는 게임의 `HERO_STRIDE 2.15`÷배율 1.32=1.63m에 맞춤 | 달리기로 읽힘. 옷자락이 벌어지고 일부 면이 찢겨 보임 |
| cast 0.6초 | 0~0.15 준비(팔 올림), 0.32 정점(팔 앞으로), 0.6 복귀. 게임은 0.15~0.6 구간을 씀 | 팔을 벌려 올리는 몸짓. 시전답지만 단조로움 |
| hit 0.3초 | 상체 젖힘, 팔 튕김 | 읽힘 |
| death 0.9초 | 무릎이 꺾이고 뒤로 쓰러져 누움. 바닥 아래로 내려가는 정점이 없게 높이 보정 | 누운 최종 자세가 위에서 내려다본 화면에 알맞음 |
| dodge 0.5초 | 몸을 낮춘 큰 걸음 도약 자세 | 읽힘. 게임이 회피에 이 클립을 아직 쓰지 않음 |

검사(스크립트): 달리기 IK 과신장 0프레임(고친 뒤), 발이 바닥 아래로 내려간 최대 깊이 약 0.8cm(원래 장화 두께에서 오는 값), 사망은 0.0.

**발 미끄러짐**: 설계한 디딤 구간에서 발목의 앞뒤 속도와 땅 속도의 차이가 평균 약 0.2~0.27m/s(땅 속도 2.7m/s의 7~10%), 최대 0.8~0.9m/s(약 30%). 원인은 30fps 키 사이의 보간. 60fps로 찍으면 줄어들 것이나 시험하지 않았다. 발뒤꿈치→발끝 굴림은 모델하지 않았다.

**방법 (나) 기존 glb 동작을 새 뼈대로 옮기기(리타깃)** — **미실시.** 설계는 해 두었다(같은 이름의 뼈는 월드 축 회전 차이를 그대로 복사, 골반 이동 복사). 하지 않은 이유는 시간이다. 그리고 `3D-GEN-TOOLS` 3.5절이 이미 권하지 않는다(CC BY-SA 동일조건 문제). 자체 제작 동작이 된다는 것이 위에서 입증되었으므로 이 길은 필요하지 않다.

한계(정직하게): 이 동작들은 사람이 손맛을 다듬은 동작이 아니다. 시전의 무게 이동, 달리기의 팔 휘두름, 회피의 속도감 같은 것은 사람의 평가와 다듬기가 필요하다. 미감은 미평가.

## 5. 게임 연결 (직접 봄)

방법: `chapter_actors.gd`는 `load(MODEL)`로 경로를 직접 부르고(`asset_slots`의 모델 자리를 아직 쓰지 않는다), 자리표 덮어쓰기 인수로는 이 모델을 바꿀 수 없었다. 대신 `hud_dump.gd`를 상속한 시험 스크립트(`_local/` 아래)가 실행 때 glb를 `GLTFDocument`로 읽어 `Resource.take_over_path`로 제품의 경로와 임포트 변환 경로 두 곳에 올렸다. **제품 파일은 하나도 바뀌지 않는다.** 한 판은 `python tools/dev/godot.py --fixed-fps 60 --resolution 1920x1080 ... --chapter1-pilot --chapter1-profile-off --chapter1-qa-ignore-focus --chapter1-seed=11 --primary=chapter1.skill.frost`.

- 처음에는 소스 경로만 바꿨더니 바뀌지 않았다(뼈 53 그대로). 임포트 변환 경로(`.godot/imported/..scn`)도 같이 올려야 한다. 이 요령이 `asset_slots`의 "개발용 덮어쓰기"를 이 모델에 확장하는 근거가 된다(T7이 모델 호출부를 자리표로 옮기면 인수 하나로 된다).
- 결과: `RIGGED_HERO_READY {"bones":24, clips:[cast,death,dodge,hit,idle,run], "upper_body_bones":14}`. 달리기·시전·피격이 나온다. 지금 모델과 같은 시드·같은 시점 125장씩을 짝지어 직접 비교했다(달리기·시전·피격 각 6장 이상).
  - 방향: 지금 모델과 같은 쪽을 본다. 정면 방향 문제 없음.
  - 지팡이: 오른손 부근에 붙어 따라온다. 시전 때 손을 뚫는 것은 보이지 않음.
  - 재질: `StandardMaterial3D`로 임포트되고 림 빛이 지금처럼 들어간다.
  - 뒤틀린 관절·찢어진 메시: 108픽셀 규모에서는 눈에 띄지 않는다. Blender 가까이 렌더에서는 달리기·회피 때 옷자락이 찢겨 보인다.

### 7.3 부품 시트(`d-top` 등)의 쓰임

`d-top`: 상의 하나를 앞·옆·뒤와 확대 한 장으로 그렸다. **모델러·텍스처 참고로는 매우 좋다**(뒤의 끈, 이음매, 장식이 보임). **그림→3D 생성의 입력으로는 권하지 않는다.** 몸 없이 허공에 뜬 옷을 생성하면 속이 빈 껍질이 나오고 몸에 맞지 않는다. 부품 시트는 (가) 생성한 몸의 텍스처를 손볼 때의 참고, (나) 외주 모델러에게 줄 자료, (다) 뼈에 붙는 소품을 따로 생성할 때의 입력으로 둔다.
