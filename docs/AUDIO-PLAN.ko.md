## 2. 첫 일 — 끝남

`audio-lead`의 재고 조사와 방향 문서는 `docs/specs/S1-audio-direction.ko.md`로 나왔다(1판 2026-11-17, 2판 같은 날 늦은 밤). 2판의 요지:

1. **재료**: 사람이 녹음·설계한 전문 소리 팩. 한 팩 또는 서로 어울리는 소수(효과음 2 + 음악 1 이하)로 한 벌. 배치한 효과음의 70% 이상이 한 계열 팩에서. 팩 고르는 기준(녹음 사양, 범주별 최소 개수, 변주, 라이선스, 값)은 S1 2절. 후보 조사는 `docs/reviews/AUDIO-SOURCES-20261117.ko.md`.
2. **타격감**: 명중·처치·큰 한 방·폭발·주인공 피격·큰 순간을 층(어택·몸통·무게·계열 꼬리·부서짐)으로 쌓고, 층마다 대역·길이·시간 차·음량을 값으로 정함. 화면의 멈춤·흔들림·섬광과 같은 프레임. 군중 묶음은 맞힌 수에 따라 무게 층을 키움(S1 3절).
3. **배치표**: 타이틀부터 결과 화면까지 순간마다 소리·걸이·버스·우선·변주·덕킹, 무음 포함(S1 4절).
4. **한 곳에서 조절**: `chapter1/data/audio_map.json` 하나, 재생기는 그 표만 읽음. 관리 툴에서 보고 듣고 고침(S1 5절).
5. 믹스·버스·묶음·시각표·존재 신호·음악 구조는 1판에서 이어짐(S1 6~8절).

## 3. 소리 목록

S1 2판 4절의 배치표가 대신한다. 옛 초안 표는 지웠다. 군중 전투의 규칙도 S1 3.4절(같은 틱은 한 번, 최소 간격 50ms, 맞힌 수가 두 배가 될 때마다 무게 층 +2dB 최대 +8dB, 음높이는 수로 바꾸지 않음).

## 4. 음악

- **구조(초안)**: 판의 음악은 한 곡을 강도 단계(잔잔함 / 무리 / 수호자·우두머리)로 나눠 겹치거나 갈아 끼운다. 구역이 바뀌어도 끊기지 않게 박자 단위로 넘긴다. 타이틀과 캐릭터 선택은 같은 주제의 조용한 판.
- **분위기**: 고딕 다크 판타지, 무너진 수도원. 악기와 템포, 조성은 `audio-lead`가 잴 수 있는 말로 정한다(예: 템포 범위, 저음 지속음의 대역, 합창·현·종의 쓰임). "웅장하게" 같은 말로 끝내지 않는다.
- **만드는 길**(6절 A-2, 2판에서 고침): 사람이 작곡한 판매 팩(itch.io 다크 판타지 팩, $5~$30, 조사 문서)을 먼저. 사람 작곡이라 스팀 AI 공개가 필요 없다. 생성 AI(Suno Pro 이상, AIVA Pro)는 2차이며 쓰면 AI 공개. 출시 전에 외주를 검토한다. 구조·템포·대역의 값은 S1 8절.
- 다른 작품의 선율을 본뜨거나 실존 음악가의 이름을 생성 지시에 쓰지 않는다.

## 5. 듣는 사람은 사용자뿐이다

에이전트는 소리를 들을 수 없다. 그래서 검증을 두 갈래로 나눈다.

| 갈래 | 누가 | 무엇을 |
|---|---|---|
| 잴 수 있는 것 | `sound-designer`가 재고 `audio-lead`가 검수 | 길이, 최대·평균 음량, 잘림, 무음, 대역, 반복 이음매, 동시 발음 수, 이벤트 연결, 프레임 시간, 파일 크기 |
| 귀로만 아는 것 | 사용자 | 어울리는가, 타격감이 있는가, 세 계열이 갈리는가, 거슬리는 소리가 있는가, 오래 들어도 피곤하지 않은가, 음악이 판의 흐름과 맞는가 |

사용자가 듣는 방법:
1. **시청용 묶음(작게)**: `sound-designer`가 `_local/audio/audition/<날짜>-H<번호>/`에 완성형 소리 열두 개 안팎과 군중 혼합 하나를 만든다. 질문은 셋 이하("이 방향이 맞는가, 가장 좋은 것과 나쁜 것"). 비교용 실험 파일과 긴 질문지는 만들지 않는다. 사용자는 다른 기기에서도 듣는다(WAV와 m4a). 첫 묶음 H1은 S1 9.2절.
2. **전투 영상**: 자동 조작 한 판을 소리와 함께 녹화해 보낸다(가능한지 확인이 필요하다. 지금 캡처 도구는 화면만 뜬다).
3. **플레이**: 관리 툴 「플레이 기록」에 소리 질문을 더한다(`manager-tools`).

사용자의 청취 기록이 없는 소리는 "미평가"다. 통과로 적지 않는다.

## 7. 순서

1. `audio-lead`: 재고 조사와 방향 문서 — 끝남(S1 1판·2판).
2. 사용자: 팩 1안 또는 2안의 승인(내려받기·결제), 음악 팩 승인.
3. `sound-designer` SD1: 데이터 표(`audio_map.json`)와 재생기 정리. 소리는 아직 바꾸지 않고, 옛 22개를 임시로 꽂아 지금과 같은 재생 수가 나오는지로 검증. 팩 승인을 기다리지 않고 시작할 수 있다.
4. `sound-designer` SD2: 승인된 팩으로 타격 묶음(세 계열의 시전·명중·처치, 주인공 피격, 레벨업, 전설 득템 + 군중 10초) → 사용자 청취 H1(질문 셋).
5. H1이 "맞다"면: 큰 순간·화면(마녀 층과 존재 신호 포함) → 득템·봉인 풀기 → 전투 전체(성능 최종 측정과 A5 반영 뒤) → 환경음 → 음악.
6. `tech-lead`는 S1 2판 10.5절(T-A1~A11)로 구조를 검수하고, `manager-tools`는 S1 5.4절(M-A1~M-A6)로 관리 툴에서 표를 보고 듣고 고치게 한다.
7. 출시 문서(T4)에 음악과 효과음의 출처·권리 원장, 스팀의 AI 생성 콘텐츠 공개(사람 녹음 팩만 쓰면 해당 없음)를 더한다.

## 8. 확인하지 못한 것

- 후보 팩의 소리(들은 사람이 없다)와 EULA 원문(조사 문서도 본문을 읽지 못함).
- 실제 게임 출력의 음량. 소리를 담는 도구가 없어 파일 값과 재생기 이득으로 추정만 했다.
- 재생 빈도는 실제 코어에 재생 규칙을 옮긴 모형으로 셌다. 실제 재생기가 멈춤 중 화면 소리를 내는지, 은총 고르기의 `equip` 두 번 요청이 같은 틱인지는 실행으로 보지 않았다.
- 생성 도구와 일부 팩의 값·약관 가운데 조사 문서가 "확인 못 함"으로 둔 것.
- 소리가 든 전투 영상을 녹화할 방법(Godot Movie Maker 후보, 실행하지 않음).
- 참고작의 소리.
