## 3. 재설계

### 3.1 구조 — 평탄화와 모듈화

목표 배치:

```
chapter1/
  core/    combat_run · chapter_run · skill_tree · ultimate · save   (이벤트 발행만)
  data/    enemies · skills · items · zones · encounters · trees/* · fx_recipes   (JSON + 로더 검증)
  view/
    world/  actors/  hud/  camera/  audio/
    fx/     fx_director.gd · fx_recipes · pools(파티클·조명·데칼·숫자) · shaders/
  app/     chapter_one.gd(입력·조립) · settings
  tests/   run_all.gd(단일 진입) · golden/
  legacy/  평탄화 전 체인(동등성 확인 뒤 사용자 승인으로 제거)
```

핵심 변경 네 가지:

1. **체인 평탄화.** 체인마다 최종 유효 동작만 남긴 본체로 합성하고, 고정 시드 골든(코어는 스냅샷 해시, 뷰는 프레젠터 카운터·인스턴스 변환 해시·고정 틱 캡처)으로 동등성을 확인한다. 순서는 Core → Effects → Actors → HUD → World → Input. 버전은 파일 이름 대신 git 태그와 빌드 매니페스트가 맡는다.
2. **이벤트 라우터.** 코어 이벤트를 한 곳에서 한 번 읽어 FX·Actors·오디오·HUD·카메라 구독자에게 나눠 준다. 이벤트 스키마를 문서로 고정하고(type, seq, tick, position, skill_id, tier, 대상) 궁극기·장판 이벤트를 여기에 추가한다.
3. **FX 레시피.** `(이벤트, 스킬, 등급)` → 층 목록(섬광 조명, 코어, 충격파, GPU 파티클, 데칼, 카메라 임펄스, 히트스톱 요청, 소리 큐)을 데이터로 정의한다. `fx_director`가 우선순위 예산(전조 > 플레이어 > 궁극기 > 진화 주문 > 일반 명중 > 잔해)으로 실행한다. 새 속성·궁극기는 레시피 추가로 끝난다.
4. **데이터 추출.** S5의 상수를 `data/`로 옮기고 로더에서 범위·ID를 검증한다. 추출 전후 코어 해시가 같아야 한다.

### 3.4 관리 툴 — 구조 변경과 함께 움직인다

관리 툴은 지금 구조(버전 파일, 코드 속 상수, `plans/` 경로)에 맞물려 있어서 3.1을 따로 진행하면 깨진다. 같은 변경 안에서 함께 고친다.

1. **빌드 매니페스트 기반 선택.** 후보별 사양을 `catalog.py`가 아니라 각 빌드의 `build.json`이 스스로 선언한다(필수 파일, 검증 문서, 성능 세션, 변경 요약). 새 후보를 내도 도구 코드를 고치지 않는다.
2. **빌드 보기와 작업 트리 보기 분리.** "배포 49"는 그 빌드의 동결 소스 기준으로, "작업 중"은 현재 소스 기준으로 따로 보여 준다(T2 해소).
3. **데이터 직접 읽기.** 3.1의 데이터 추출 뒤에는 정규식 파싱을 없애고 `chapter1/data/*.json`을 읽는다. 적 수치·구역·사건·트리·궁극기·FX 레시피가 같은 방식으로 등록된다(T5·T6·T7·T9 해소).
4. **평탄화 반영.** 체인이 사라지면 `implementation` 82건이 역할별 본체 몇 건으로 줄어든다. 요소 중심 화면이 된다(T4).
5. **경로 설정화.** 미리보기·검증 근거 경로를 설정 파일로 빼서 `plans/`·`builds/` 보관 이동이 가능해지게 한다(T8).
6. **디렉터 현황판.** 이 문서의 마일스톤과 종료 조건, 사용자 플레이 기록(고정 질문 5개), 밸런스 시뮬레이션 표, FX 레시피별 캡처 갤러리를 추가한다. 관리 범위는 사용자 확정대로 현황·미리보기·출처·메모이며 게임 수치 편집은 넣지 않는다.

2026-11-15부터 3단 체계다. 총괄 디렉터는 주 세션(Fable 5.2), 중간 관리는 Opus 5.5의 `tech-lead`(기술)·`design-lead`(기획)·`art-lead`(화면)이고 구현하지 않고 지시서 작성과 검수만 한다. 아래 표의 개발 에이전트 10개는 모두 Sonnet 5.5다(2026-11-16 갱신: `character-artist`, `environment-artist` 추가, 관리 툴 경로 정정). 하위 에이전트끼리는 서로 부를 수 없어서, 관리자의 지시서는 디렉터를 거쳐 개발 에이전트에 배정된다.

## 6. 작업 방식 조정

- 후보 번호를 파일 이름에 넣지 않는다. 변경은 본체 수정 + git 커밋, 배포 후보만 태그와 매니페스트를 만든다.
- 증거의 무게를 변경의 위험에 맞춘다. 저장·판정·입력은 전체 회귀, 미술·이펙트는 캡처와 프레임 시간.
- 마일스톤 종료의 기준은 검사 통과 수가 아니라 사용자 플레이 기록이다.
