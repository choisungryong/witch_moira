# 구멍을 막는 절차 (2026-11-19 초안)

총괄 디렉터 작성. 사용자 지시: "앞으로 개발하는 데 구멍이 없도록 잘 체크할 수 있는 절차를 구상해 봐. 아니면 주기적으로 전체 점검할 수 있는 과정을 넣든지."

이 문서는 **초안**이다. 사용자가 받아들이면 `CLAUDE.md`의 "먼저 읽을 것"에 한 줄로 걸고, 2절의 자동 점검을 도구로 만든다.

## 0. 지금까지 구멍이 난 자리(이 절차가 막으려는 것)

2026-11-19 하루에 드러난 것만 적는다. 절차는 이 유형들에서 나왔다.

| 유형 | 실제 사례 |
|---|---|
| **가. 지시가 명세에 안 실림** | 스킬 구성·장비 옵션의 재설계, 효과의 만듦새가 어느 명세에도 없었다(사용자가 묻고서야 드러남) |
| **나. 모델·추정을 사실처럼 씀** | 시뮬레이터는 터뜨림 몫 76%, 실제 코어는 2~8%. 리듬을 켠 판의 패배를 "너무 어렵다"로 전했는데 체력이 이중으로 곱해진 조건이었다 |
| **다. 임시 도구가 정식 행세** | 디렉터의 소리 비교 영상이 게임과 다른 믹스 규칙을 썼다. 일회용 스크립트가 `_local/`에 수백 개 |
| **라. 기록이 실물과 어긋남** | 에셋 출처 원장 파일이 없다. 모델 원본 기록이 가리키는 파일이 없다. 소리 2개가 원장에 없다. `CLAUDE.md`의 저장 절이 스키마 3(코드는 4) |
| **마. 같은 값이 여러 곳에** | 목표 상수가 다섯 곳에 따로 있고 어긋났다. 결정 번호가 중복됐다. 이벤트→소리 대응표가 세 벌 |
| **바. 읽지 않은 것을 넘김** | 디렉터가 명세 본문을 읽지 않고 보고문만으로 다음 작업을 배정한 적이 있다 |
| **사. 보지 않은 화면** | 화면 작업을 캡처 없이 받거나, 좁은 창에서 겹치는 것을 넓은 창만 보고 넘김 |
| **아. 꺼진 장치가 쌓임** | 리듬, 스킬 구성이 꺼진 값으로 들어와 있다. 켠 경로에는 골든이 없고 화면은 새 이벤트를 모른다 |

## 1. 작업 하나가 지나는 문(게이트)

작업 묶음 하나는 아래 다섯 문을 차례로 지난다. 문마다 **남기는 것**이 있고, 없으면 다음으로 가지 않는다.

| 문 | 누가 | 확인하는 것 | 남기는 것 |
|---|---|---|---|
| **① 지시 → 장부** | 디렉터 | 사용자의 말을 원문 그대로 적고, 어느 명세의 어느 절이 받는지 적는다. 받을 절이 없으면 "명세 없음"으로 올린다 | 지시 장부의 한 줄(3절) |
| **② 명세** | 관리자 | 결정마다 다섯 사상 중 무엇을 키우는지, 본 것/가설/미확인의 구분, 재는 법(어느 도구의 어느 값), 사용자가 정할 것, 저장·골든·화면에 미치는 것 | 명세의 절. 디렉터는 **구현을 배정하는 절을 직접 읽는다** |
| **③ 구현** | 개발 | 작업 폴더에서, 패치와 보고서로. 꺼진 값에서 골든 불변. 실제로 돌린 명령과 결과 줄. 못 넣은 것과 스스로 정한 것 | 패치, 보고서 |
| **④ 검수** | 디렉터(큰 묶음은 관리자) | 패치를 훑는다(건드리면 안 되는 파일, 사용자 폴더 접근). 본 저장소에서 다시 돌린다. 화면이 걸리면 캡처를 **직접 본다**(두 해상도). 모델의 답과 실측을 구분해 적는다 | 회귀 로그, 캡처, 인계 메모 한 줄 |
| **⑤ 닫기** | 디렉터 | 커밋. 지시 장부의 상태를 바꾼다. **켜기 전에 남은 일**을 켜는 장부(4절)에 올린다. 사용자에게 "한 것 / 못 본 것 / 정할 것"으로 전한다 | 커밋, 장부 갱신 |

문 ④에서 지키는 말의 규칙:
- "통과"는 실제로 돌린 것에만 쓴다. 회귀를 일부만 돌렸으면 "빠른 회귀 통과"라고 쓴다.
- 시뮬레이터·계산의 값은 "모델의 답"이라고 붙인다. 시드 하나, 판 몇 개의 결과에는 판 수를 붙인다.
- 화면은 "직접 봄 / 캡처만 있음 / 보지 않음" 셋 중 하나를 적는다. 재미와 미감은 "사용자 플레이로"만 채운다.

## 2. 자동 점검 — `tools/dev/audit.py`(만들 것)

사람이 기억으로 지키던 것을 명령 하나로 돌린다. 회귀(`run_all.py`)가 "게임이 깨졌는가"를 본다면, 이것은 "기록과 약속이 어긋났는가"를 본다. 대부분 지금 만들고 있는 도구들을 묶는 것이다.

| 점검 | 막는 유형 | 쓰는 도구(상태) |
|---|---|---|
| 에셋 출처 원장에 없는 파일, 해시 불일치 | 라 | `tools/art/asset_ledger.py check`(제작 중) |
| 모델 출처 기록의 빈 칸 | 라 | `tools/art/asset_intake.py --scan`(제작 중) |
| 소리 원장에 없는 파일 | 라 | `tools/dev/audio_ledger_check.py`(제작 중) |
| 금지 낱말, 이름 규칙 | 마 | `tools/dev/wording_lint.py`(제작 중) |
| 결정 번호 중복, 다음 빈 번호 | 마 | `tools/dev/decision_ledger.py`(제작 중) |
| 목표 상수가 목표 파일과 다른 곳 | 마 | `tools/dev/judge_targets.py --check-constants`(제작 중) |
| 참조되지 않는 파일, 남은 옛 층 메서드 수 | 다 | `tools/dev/refactor_map.py`(제작 중) |
| 명세의 첫 값과 데이터 파일이 다른 곳 | 가·마 | 명세↔데이터 대조기(아직 없음) |
| `_local/`에만 있고 두 번 이상 쓰인 스크립트 | 다 | 새로: 이름이 비슷한 일회용 스크립트 묶음을 센다 |
| 꺼진 스위치 목록과 켜기 전 남은 일 | 아 | 새로: 데이터 파일의 `enabled:false`와 4절 장부를 대조 |
| `CLAUDE.md`·`README`가 말하는 파일·수치가 실제와 맞는가 | 라 | 새로: 문서에 적힌 경로가 있는지, 스키마 번호 등 몇 가지 사실 |
| 지시 장부에서 "명세 없음"·"검증 없음"으로 남은 줄 | 가 | 새로: 3절 장부를 읽는다 |
| 사람 평가 "미평가" 항목 수 | 나·사 | `judge_targets.py`(제작 중) + 플레이 기록 |

출력은 한 장: 점검 / 결과(이상 없음·N건·못 봄) / 지난번과의 차이. 종료 코드는 "새로 생긴 구멍"이 있을 때만 실패로 한다(기준선 방식 — 이미 아는 구멍은 장부에 번호를 달아 두고 줄어드는지만 본다).

## 3. 지시 장부 — `docs/DIRECTIVES-LEDGER.ko.md`(만들 것)

사용자의 지시가 어디까지 갔는지를 한 표로 둔다. 인계 메모는 시간순이라 "이 지시가 지금 어디 있나"를 찾기 어렵다.

| 번호 | 날짜 | 사용자 지시(원문 요지) | 받은 명세·절 | 작업 묶음 | 검증(무엇으로, 결과) | 상태 |
|---|---|---|---|---|---|---|
| 예 | 11-19 | 시너지 조합이 가장 효율이 좋게, 하나만도 막 찍기도 안 되게 | D12 P4·P7·B0.9 | KS(들어감, 꺼짐), 수치(안 됨) | 실측: 하나만 쌓기가 우세 — **미달** | 진행 |

상태는 `명세 없음 → 명세 → 구현(꺼짐) → 켬 → 실측 통과 → 사용자 확인` 가운데 하나. "사용자 확인"은 사용자가 플레이하거나 보고 좋다고 한 것만.

## 4. 켜는 장부 — 꺼진 장치가 쌓이지 않게

꺼진 값으로 들어온 장치마다 한 줄: 스위치(파일·키) / 들어온 커밋 / 켜기 전에 남은 일(수치, 화면이 알아야 할 이벤트, 골든 사례, 저장, 소리) / 켜는 조건 / 담당. 지시 장부와 같은 문서의 둘째 표로 둔다. 지금 올릴 것: `rhythm.enabled`, `rhythm.trial.enabled`, `run_spells.enabled`, `--chapter1-vat-walker`.

## 5. 주기 점검

| 언제 | 무엇을 | 누가 | 걸리는 시간 |
|---|---|---|---|
| **커밋마다** | 회귀(바뀐 것에 맞게: 문서만이면 빠른 회귀, 코어·데이터면 전체) | 디렉터 | 0.5~15분 |
| **작업 묶음을 닫을 때마다** | 1절의 문 ⑤, `audit.py` | 디렉터 | 수 분 |
| **날마다 첫 일** | `audit.py` 전체, 지시 장부에서 멈춘 줄, 켜는 장부, 답을 기다리는 사용자 결정 목록 → 사용자에게 "오늘의 상태 한 장" | 디렉터 | 10분 |
| **주마다(또는 큰 묶음이 끝날 때)** | **전체 점검**: 관리자 다섯이 각자 자기 영역을 읽기 전용으로 감사한다 — 명세와 구현의 어긋남, 낡은 문서, 쌓인 임시 스크립트, 안 쓰는 도구, 빠진 기록. 2026-11-19의 도구 검토와 같은 방식(15개 역할, 읽기만, 몇 분). 디렉터가 한 문서로 묶어 `docs/reviews/AUDIT-<날짜>.ko.md`에 | 관리자 → 디렉터 | 30분 |
| **켜기 전(스위치마다)** | 켜는 장부의 남은 일이 0인지, 켠 경로의 골든 사례, 화면 캡처, 실측 목표 판정, 사용자 플레이 | 디렉터 → 사용자 | 묶음마다 |

주마다의 전체 점검에서 관리자에게 묻는 것은 고정한다:
1. 네 영역에서 명세가 말하는 것과 코드·데이터가 다른 곳.
2. 문서가 낡은 곳(현재 상태로 읽으면 틀리는 곳).
3. 지난 점검 뒤에 `_local/`에 새로 쓴 일회용 스크립트와, 정식으로 올릴 것.
4. 이미 있는데 안 쓴 도구.
5. 측정 없이 통과로 넘어간 것, 사람이 보지 않은 화면·소리.
6. 다음 주에 구멍이 날 것 같은 자리 하나.

## 6. 사용자가 정할 것

1. 이 절차를 받아들이는가. 받아들이면 `CLAUDE.md` "먼저 읽을 것"에 이 문서를 걸고 "반드시 지킬 것"에 문 ④의 말의 규칙 세 줄을 넣는다.
2. 주기 점검을 **사람이 부를 때**만 돌릴지, **정해진 때에 자동으로**(예: 날마다 아침, 주마다) 돌려 결과를 한 장으로 받을지.
3. 전체 점검의 주기: 주마다 / 큰 묶음이 끝날 때마다 / 둘 다.
