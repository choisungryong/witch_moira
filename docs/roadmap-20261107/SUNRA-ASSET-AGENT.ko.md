# Sunra 전담 에셋 에이전트 운영안

작성일: 2026-11-14. 사용자는 Sunra를 이미지·3D·PV 영상·스프라이트·효과 제작에 활용하고 이를 담당하는 전담 에이전트를 요청했다. 이 문서는 연결 전 제작 준비다. 로그인·설치·업로드·유료 생성·크레딧 소비는 실행하지 않았다. 현재 Sunra 호출 도구는 노출되지 않았다.

## 역할과 작업 경계

전담 에셋 에이전트는 같은 채팅에서 부모 에이전트의 제작 요청을 받아 사양화·모델 확인·제작 요청·결과 검수·파일 정리·인계를 맡는다. 독립된 사용자 채팅이나 영구 백그라운드 서비스가 생겼다는 뜻은 아니다. 연결 후에도 게임 코어와 사용자 저장을 직접 수정하지 않는다.

부모 게임 개발 에이전트는 캐릭터 영구 성장·분기 트리·필살기 스택·피해 판정·발동 타이밍·컷인 상태기·실제 게임 통합을 맡는다. 에셋 에이전트는 요청된 제작물의 품질과 출처를 책임지고 부모에게 전달한다. 게임 수치나 판정을 영상 내용에 맞춰 임의로 변경하지 않는다.

현재 우선순위는 게임성·기능이다. 기존 주인공 모델과 초상은 유지한다. 첫 제작은 냉기 필살기의 시각 문법과 재사용 효과 재료다. 새로운 주인공 모델 제작과 음향은 후순위다.

## 공식 확인 사항과 미확인 사항

| 항목 | 확인 결과 |
|---|---|
| 연결 방식 | 공식 MCP 주소는 `https://mcp.sunra.ai`이며 브라우저 인증을 안내한다. 공식 Codex 안내는 CLI 설치·로그인 후 계정·잔액·도구 확인을 제시한다. 이 문서 작성 중에는 실행하지 않았다. |
| 제작 범위 | Sunra 공식 MCP 안내는 이미지·영상·음향·텍스처가 있는 GLB 모델 생성을 설명한다. |
| 기본 이미지 선호 | 사용자 지정 선호는 `gpt-image 2.6`. 지원과 실제 모델 ID는 미확인이다. 확인한 공개 MCP/모델 페이지에는 GPT Image 2.5·2가 표시됐다. 임의로 다른 모델로 바꾸거나 기본 설정 완료라고 보고하지 않는다. |
| 3D 출력 | 공식 안내에 Meshy 6/7·Tripo H3.1이 있다. Tripo H3.1 모델 설명은 기본 삼각형 GLB와 선택 FBX 출력을 설명하며 리그·애니메이션은 제공하지 않는다고 명시한다. Meshy7의 선택 리그·애니메이션은 해당 출력이 실제 반환됐는지 별도 검수한다. |
| 스프라이트 | 이미지나 영상의 제작 가능성이 곧 정렬된 스프라이트 시트·알파·프레임 일관성을 보장하지는 않는다. 모델별 출력 사양을 확인하고 게임용 후처리를 별도 수행한다. |
| 비용 | MCP/CLI가 쓰는 Creative 크레딧과 개발용 API 달러 잔액은 별도다. 사용자가 Sunra의 가격 이점을 보고 선택한 의도는 반영하되 모든 모델·설정에서 Higgsfield보다 싸다고 단정하지 않는다. |

공식 근거:

- [Sunra MCP 안내](https://sunra.ai/mcp): 제작 범위·연결·계정/잔액/도구 확인 안내.
- [Sunra 모델 목록](https://sunra.ai/models): 공개 모델 이름 확인용. 실제 계정에서 호출 가능한 ID를 대신하지 않는다.
- [Tripo H3.1 공식 모델 설명](https://platform.sunra.ai/models/tripo/tripo-h3.1): GLB/FBX·리그/애니메이션 범위.
- [Meshy7 공식 모델 설명](https://platform.sunra.ai/models/meshy/meshy-v7/text-to-3d): 기본 모델과 선택 리그/애니메이션 출력 구분.
- [Sunra 이용 약관](https://sunra.ai/terms): Creative/API 결제 구분 및 제작물 사용 조건 확인용.
- [Sunra 가격표](https://sunra.ai/pricing): 실제 작업 직전의 가격 확인용.

## 연결 후 첫 확인 절차

1. 실제 도구 목록에서 Sunra의 계정·잔액·모델/도구 조회 기능을 확인한다. 도구 이름과 요청 필드는 실제 반환 스키마를 사용하며 추측하지 않는다.
2. 연결 계정과 비용 지불 주체를 확인한다. 팀 결제가 있다면 사용자가 선택한 주체를 유지한다. 제작마다 임의로 지불 주체를 변경하지 않는다.
3. `gpt-image 2.6`에 대응하는 정확한 모델 ID·버전·지원 입력/출력·해상도·알파·이미지 편집·참조 이미지 제한을 조회한다. 조회 불가나 미지원이면 대체 모델 선택 전에 부모에게 보고한다.
4. 영상은 이미지 참조·첫/끝 프레임·길이·해상도·프레임률·음향·알파 제공 여부를 확인한다. 3D는 GLB/텍스처·면수 조절·리그·동작 출력 지원을 구분한다.
5. 작업의 모델·설정·개수별 예상 크레딧과 승인된 한도를 기록한다. 비용 한도와 생성 허용이 정해지기 전 유료 요청을 보내지 않는다.
6. 허용된 첫 샘플 하나를 제출하고 작업 ID를 보존한다. 대기 중인 요청은 같은 ID로 조회하며 관측 시간 초과만으로 중복 생성하지 않는다.

## 제작 요청부터 인계까지

| 단계 | 수행 내용 | 완료 근거 |
|---|---|---|
| 제작 요청 | 목적·게임 화면·역할·산출물·참조·금지 변경·모델·비용 한도를 묶는다. | 부모가 검토 가능한 제작 브리프와 작업 ID |
| 원본 보존 | 프롬프트·모델 ID/버전·설정·참조 해시·생성 ID·원본 링크와 파일을 보존한다. | 제작 이력과 원본 파일 해시 |
| 미술 검수 | 스타일·주인공 일관성·실루엣·움직임·불필요한 글자·깜박임·화면 가림을 검사한다. | 채택/수정/기각 이유와 비교 이미지 |
| 게임용 변환 | 필요 해상도·알파·루프·프레임 분리·시트 정렬·형식 변환을 수행한다. 원본은 덮어쓰지 않는다. | 파생 파일과 변환 명령/버전·해시 |
| 부모 인계 | 논리 이벤트·시작/정점/종료 시점·크기·피벗·색 공간·혼합 방식을 명시한다. | 인계 명세와 승인된 파일 목록 |
| 게임 검수 | 부모가 720p/1080p 실제 전투·간소화·스킵·성능을 확인한다. | 실제 장면과 결과 기록 |

정지 이미지의 미술 통과, 영상 재생 통과, 실제 게임 통합 통과를 서로 다른 상태로 기록한다. 출처·검수 전 항목을 관리 툴에서 사용 중/완료로 표시하지 않는다. 생성물의 상업 사용 조건은 해당 모델·요청 시점 기준으로 기록한다.

기존 제품·사용자 저장·검증 원시는 보존한다. 재료는 별도 제작 폴더에 두고 채택된 파생물만 게임 런타임에 넣는다. 대량 원본·캐시를 패키지에 포함하지 않는다. 실제 폴더 생성과 저장 용량 한도는 첫 작업 전에 부모가 정한다.

## 첫 제작 브리프 — 냉기 필살기 한 묶음

목표: 어두운 석재 회랑의 성인 마녀가 빙결 인장을 펼치고 서리 파동을 해방하는 냉기 필살기의 시각 문법을 만든다. 현재 캐릭터 얼굴·의상·모델을 바꾸지 않는다. 전투 판정과 스택 수치는 제작 범위에 포함하지 않는다.

첫 묶음은 한 개의 키 비주얼을 검수한 뒤 같은 디자인으로 후속 재료를 만든다. 한 번에 여러 PV를 대량 생성하지 않는다.

| 산출물 | 요청 사양 초안 | 쓰임 |
|---|---|---|
| 키 비주얼 1장 | 16:9, 어두운 회랑·청백색 냉기·절제된 금빛 인장, 기존 주인공과 일관된 실루엣. 모델은 사용자 선호를 실제 조회 후 적용. | 연출 방향 승인 |
| 시전 콘셉트 영상 1개 | 인장 준비→힘 집중→서리 파동 해방→잔광 소멸을 읽을 수 있는 짧은 장면. 음향은 생성하지 않는 설정을 우선 확인. | PV 방향·타이밍 참고 |
| 인장 재료 | 정면 원형 문양, 중심 피벗, 가장자리 잘림 없음. 투명 배경 지원을 확인한 뒤 요청. 글자·가짜 UI 제외. | 지면/시전 효과 |
| 파문·파쇄 재료 | 중심에서 확산하는 파문과 얼음 균열을 분리. 알파가 없으면 후처리 대상으로 기록. | 실제 게임 입자·시트 후보 |
| 고정 서리 지대 재료 | 중심 피벗의 원형 경계·서리 흐름·내부 균열을 분리한다. 경계는 얇고 반복 텍스처는 이음새가 없게 제작한다. 루프 전후 프레임·알파·타일링을 검수한다. | 냉기 제어 분기의 지속 지역 효과 |

게임 시전 컷인의 첫 시안 길이는 기존 계획의 약0.8~1.2초다. 서비스 영상의 최소 생성 길이가 더 길면 원본을 유지하고 사용 구간만 파생한다. 생성 PV가 현재 게임 모델의 실제 시전 동작을 증명하는 자료가 되지는 않는다. 실제 모델 컷인과 생성 PV 중 무엇을 최종 사용했는지 명시한다.

게임 측 인계 메모: 부모가 냉기 분기 코어의 전투 검사13개 통과를 보고했다. 서리 지대는 고정 위치에 생성되며 `frost_field52` 이벤트를 보내지만 시각 효과 소비기는 아직 연결되지 않았다. 제작물은 해당 이벤트의 중심·반경·만료 시점에 맞춰 표시하는 반복 재료로 인계한다. 자산이 적 감속이나 피해를 직접 발생시키지 않는다. 게임 코어 검사 통과를 자산 검수 완료로 표시하지 않는다.

고정 서리 지대용 추가 프롬프트 틀:

> 위에서 내려다본 원형 냉기 마법 지대의 효과 재료. 중심 피벗과 원형 경계를 유지하고, 얇은 청백색 경계선 안에서 차가운 서리 흐름과 작은 얼음 균열이 천천히 순환한다. 주인공과 적 실루엣을 읽을 수 있도록 내부는 성기고 대비가 낮다. 지면 바탕이나 캐릭터, 글자, UI를 포함하지 않는다. 경계·흐름·균열을 분리된 재료로 만들고 반복 재생 시 시작과 끝이 자연스럽게 이어지도록 한다. 투명 배경과 프레임 사양은 실제 모델 지원을 확인한 요청 명세를 따른다.

재사용 프롬프트 틀:

> 어두운 고딕 석재 회랑을 배경으로, 제공된 기존 성인 마녀의 얼굴·의상·실루엣을 유지한다. 마녀가 손과 지팡이로 청백색 빙결 인장을 펼치고 힘을 모아 서리 파동을 해방한다. 준비 자세, 힘이 모이는 순간, 방출, 잔광 소멸이 구분되어야 한다. 냉기의 주요 형태는 선명한 얼음 균열과 얇은 파문이다. 전장을 읽을 수 있도록 주인공 실루엣을 보존하고 과도한 흰색 화면 덮기, 반복 섬광, 임의의 글자·로고·게임 UI를 넣지 않는다. 카메라·길이·배경·알파 사양은 요청별 명세를 따른다.

이 틀의 참조 이미지는 업로드 허용 후에만 전송한다. 아직 참조 이미지나 프로젝트 파일을 Sunra에 올리지 않았다.

## 제작 기록 필드

모든 채택 후보에 다음을 남긴다.

- 자산 ID, 작업 ID, 요청자, 담당 에이전트, 상태, 연결된 캐릭터/기술/분기/작업 항목.
- 제공자, 정확한 모델 ID와 버전, 도구/CLI 버전, 프롬프트 원문, 설정, 시드 지원 여부, 참조 파일 해시.
- 생성 요청 ID, 지불 주체, 예상 크레딧, 승인 한도, 실제 사용 크레딧, 환불/실패 여부, 시작·종료 시각.
- 원본 결과 링크, 원본 파일·해시·용량, 파생 파일·변환 이력·해시.
- 모델/요청 시점 사용 조건 링크, 출처 메모, 미술 검수 결과, 기술 검수 결과, 실제 게임 검수 결과.
- 이미지 해상도·알파·색 공간, 영상 길이·프레임률·음향·루프, 스프라이트 프레임 수·행열·피벗·프레임 시간.
- 3D의 면수·재질/텍스처·스케일·축·리그·스킨·동작 클립. 미제공 항목은 없는 상태로 기록한다.

## 다음 작업

부모가 게임 코어 구현을 계속하는 동안 에셋 담당은 연결 상태·모델 목록·비용 확인이 가능해질 때까지 이 브리프와 인계 규격을 유지한다. 연결 확인 후 첫 키 비주얼 하나를 제작하는 구체적 요청으로 넘어간다. 지금 완료된 것은 역할 분리와 제작 준비 문서이며, Sunra 연결·에셋 생성·게임 적용 완료가 아니다.
