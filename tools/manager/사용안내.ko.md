# 마녀 모이라 제작실 사용 안내

게임에 지금 무엇이 들어 있는지 한눈에 보고, 항목마다 내 메모를 남기는 도구입니다. 게임 수치와 플레이 저장은 바꾸지 않습니다.

## 여는 방법

1. 터미널을 `C:\Project\witch-moira`에서 열고 아래를 실행합니다. 서버는 이 컴퓨터에서만 열립니다(127.0.0.1).

   ```
   C:/Users/twins/AppData/Local/Programs/Python/Python310/python.exe tools/manager/server.py --port 8781
   ```
2. 브라우저에서 http://127.0.0.1:8781/ 을 엽니다.
3. 끝낼 때는 터미널에서 Ctrl+C를 누릅니다.

8781번이 이미 쓰이고 있으면(옛 제작실이 떠 있는 경우 등) `--port 8791`처럼 다른 번호로 열고 주소도 맞춥니다.

## 화면

- 왼쪽: 분류. 한 판의 기술과 은총 / 영구 성장 / 전투 수치 / 장비 / 구역과 의식 / 주인공 원화 / 3D 모델 / 그림·아이콘 / 소리 / 코드 구성 / 문서 / 품질 목표.
- 가운데: 항목 목록. 검색, 내 메모 상태, 「게임에서 쓰임」으로 거를 수 있습니다.
- 오른쪽: 고른 항목의 내용. 수치 표, 미리보기(그림, 소리 재생, 3D 모델), 출처 문서, 내 메모.
- 영구 성장 효과 문구는 게임 화면과 같은 표기입니다.

## 「게임에서 쓰이나」 읽는 법

그림·소리·모델에 붙습니다. 게임의 시작 장면에서 파일 경로를 글자로 따라가 본 결과입니다.

- 코드가 파일을 직접 가리킴: 확실히 읽힘.
- 코드가 폴더와 이름을 조합해 읽음: 폴더째 읽는 곳이며 파일 이름이 코드에 나옴.
- 읽는 폴더 안에 있으나 이름 확인 못 함: 읽힐 수도, 보관용일 수도 있음.
- 실행 경로에서 참조를 찾지 못함: 쓰지 않는다는 확정은 아닙니다. 모델에 포함됐거나 원본 보관용일 수 있습니다.

## 메모 남기기

항목을 고르고 오른쪽 아래 「내 메모」에서 상태, 우선순위, 메모를 적고 「메모 저장」을 누릅니다.

- 「완료(메모)」는 내 표시이며 품질 검수를 통과했다는 뜻이 아닙니다.
- 메모는 `tools/manager/local-state.json`에 저장되고 git에는 올라가지 않습니다. 이 파일은 지우거나 덮어쓰지 마세요.
- 다른 창에서 먼저 저장했으면 「다른 곳에서 먼저 저장되었습니다」가 뜹니다. 쓰던 메모는 그대로 있으니 확인하고 다시 저장하면 됩니다.

## 균형 실험실

왼쪽 「균형 실험실」을 누르면 열립니다. 균형 시뮬레이터(`tools/dev/balance_sim.py`)에 스킬 값과 적(리듬) 값을 바꿔 넣고 결과를 바로 봅니다. **모델의 답이며 게임의 답이 아닙니다.** 서열(어느 찍는 방식이 더 센가)과 값을 바꿨을 때의 방향은 믿어도 되지만, 정확한 승률과 초 단위 시각은 믿지 마세요. 마지막 확인은 실제 게임 코어로 합니다.

- 왼쪽에서 고릅니다: 주문 묶음 파일, 프리셋, 스킬별 값, 적 값, 모델 상수, 찍는 방식, 마녀, 판 수, 장비 묶음. 숫자 칸을 고치면 줄이 노랗게 바뀌고 「원래」 값이 옆에 남습니다. ↺은 되돌리기입니다.
- 「실행」을 누르면 몇 초~수십 초 걸립니다(찍는 방식 12 × 마녀 3 × 10판이 약 15초). 동시에 하나만 돌고, 150초를 넘기면 멈춥니다.
- 오른쪽 맨 위 큰 줄이 서열 판정입니다. 아래에 찍는 방식 × 마녀 승률(칸 색이 초록이면 목표 범위 안, 주황이면 밖), 시너지와 하나만 쌓기의 차, 종류별 평균, 마디별 힘 ÷ 위협, 죽는 마디와 원인, 정체 수가 나옵니다. ▲▼은 직전 실행과의 차입니다.
- 「실험으로 저장」은 바꾼 값과 결과 요약을 `_local/balance-lab/experiments/`에 남깁니다. 둘을 골라 「나란히 견주기」를 누르면 값과 승률의 차를 볼 수 있습니다. 「값 불러오기」는 그 실험의 값을 왼쪽에 되돌립니다.
- 「내보내기」는 `--set` 묶음 JSON을 `_local/balance-lab/exports/`에 쓰고 내려받게 합니다. **게임 데이터 파일은 이 화면이 절대 고치지 않습니다.** 마음에 드는 값은 이 파일을 총괄에게 넘겨 데이터 반영을 따로 맡기세요.
- 이름을 모르는 값을 시뮬레이터가 새로 내놓으면 「그 밖에 시뮬레이터가 내놓은 값」에 그대로 보입니다. 모델 상수의 출처(fit 실측에 맞춤 / spec 명세 / hypo 가설 / guess 추정)는 왼쪽 4번에 적혀 있습니다.

## 캐릭터

왼쪽 「캐릭터」를 누르면 열립니다. 게임을 띄우지 않고 주인공 몸의 걸음을 두 칸에 나란히 돌려 보고, 걸음 값을 고르는 화면입니다. 3D는 이 폴더에 들어 있는 three.js로 그리며 인터넷을 쓰지 않습니다.

- 주인공 몸 파일은 저장소에 올라가지 않아서(`chapter1/art/actors/hero/`는 git 밖) 몸 파일이 없는 작업 폴더에서는 줄이 「몸 없음」으로 나옵니다.
- 칸마다 클립(run, walk 등)과 **동작 배율**을 고릅니다. 배율은 클립을 원래 속도의 몇 배로 돌리는가입니다. 이동 속도 막대는 두 칸에 같이 적용됩니다. 바닥이 그 속도로 뒤로 흐르고, 디딘 발이 남기는 점이 한 곳에 모이면 미끄러지지 않는 것이고 길게 끌리면 미끄러지는 것입니다.
- 수치 띠: 동작 배율, 주기 길이, 보폭 계약 값, **계산 미끄러짐**(공식, 모델의 답), **측정 미끄러짐**(이 화면 안에서 발끝 뼈로 잰 값, 디딤 구간의 땅 기준 속도 RMS), 미끄럼 없는 배율. 지면 속도는 몸 보고서(`model.pack-report.json`)의 값이며 ±6% 어긋날 수 있습니다. 게임 안에서 잰 값이 아닙니다.
- 「미끄럼 없는 배율로」는 지금 이동 속도에서 발이 미끄러지지 않는 배율로 막대를 옮깁니다. 「게임 지금 값」은 자리표에 적힌 달리기 값입니다.
- 이동 속도는 게임 값(`chapter1/core/combat_core.gd`의 `BASE_SPEED`, 글로 읽음)과 다르게 움직여도 됩니다. 다르면 「제안으로만 저장됩니다」가 뜨고, 게임 속도는 전투 균형이라 이 화면으로는 바뀌지 않습니다.
- 카메라: 「게임 19.5」는 게임 코드의 값, 「게임 14」는 사용자 결정을 기다리는 후보입니다. 「1080p 크기」를 켜면 1080 높이 화면에서 주인공이 차지할 화소 높이를 보입니다. 「자유」는 돌려 보기입니다. 「겉모습 반영(근사)」은 `hero.json`의 look을 흉내 낸 것이라 게임과 색이 같지 않습니다.
- 「고르기」: 칸마다 이걸로 / 아님 / 보류와 한 줄 말을 정하고 「저장」을 누르면 `tools/manager/local-picks.json`에 쌓입니다(git 밖, 지우거나 덮어쓰지 마세요). 디렉터가 `python tools/manager/picks.py list --open`으로 읽고, 고른 값은 에이전트가 `tools/art/motion_apply.py`로 게임 자리표에 옮깁니다. 저장해도 게임에는 바로 들어가지 않습니다.
- 「이 화면 주소 복사」로 지금 상태(클립, 배율, 이동 속도, 카메라)를 담은 주소를 얻습니다. 예: `#character/frost?a=run&b=walk@1.3&v=5.8&cam=19.5`.
- 자리표의 `pose.run_time_scale`은 이름과 달리 배율이 아니라 **걸음 한 주기의 길이(초)** 입니다. 게임의 동작 배율은 이동 속도 × 주기 길이 ÷ `pose.stride_world_m`으로 나옵니다.

### 3D 만들기(수동)

캐릭터 화면 아래쪽의 접힌 칸 「3D 만들기(수동)」입니다. Tripo에서 사람이 손으로 모델을 만들 때, 보낼 그림을 찾고 받은 모델을 넣어 두고 돌려 보는 곳입니다. 이 화면은 Tripo에 아무것도 보내지 않습니다.

- **보낼 그림**: 작업 폴더의 `pipeline/<캐릭터>/tripo_in/` 안 `.png`를 작게 보입니다. 파일 이름과 화소 크기가 같이 나옵니다. 「내려받기」는 브라우저 저장, 「경로 복사」는 파일 경로를 클립보드로, 「폴더 열기」는 이 컴퓨터의 탐색기로 폴더를 엽니다(폴더가 없으면 만들지 않고 「없음」이라고 답합니다). 폴더가 비어 있으면 시트 한 장을 나누는 명령(`tools/art/sheet_split.py … --names front,left,back --square`)이 보입니다. 화면이 그 명령을 실행하지는 않습니다.
- **받은 모델 넣기**: Tripo에서 내보낸 `.glb`를 점선 칸에 끌어다 놓거나 눌러서 고릅니다. `pipeline/<캐릭터>/tripo_out/<날짜-시각>_<이름>.glb`로 저장되고(이름은 영문·숫자·`-`·`_`만 남김), 같은 이름이 있어도 덮어쓰지 않으며, glb가 아닌 파일(머리 4글자 `glTF` 검사)과 300 MB를 넘는 파일은 거절합니다. 목록에는 크기, 받은 때, glb 머리에서 읽은 삼각형 수·질감·뼈대 유무가 나옵니다. 이 칸에는 지우기 단추가 없습니다. 지우는 것은 탐색기에서 합니다. 저장소 안(`chapter1/` 등)에는 아무것도 쓰지 않습니다.
- **돌려 보기**: 목록의 「돌려 보기」는 그 모델을 동작 없이 선 자세로, 바닥 격자 위에서 돌려 보게 합니다. 높이를 2로 맞춰 보이므로 실제 크기가 아닙니다. 바로 가는 주소에 `&tripo=<파일 이름>`을 붙이면 그 모델을 바로 엽니다.
- **몸이 아직 없는 캐릭터(화염·번개)**: 「캐릭터 줄」에서 고를 수 있습니다. 게임 안의 몸이 없어서 걸음 비교·동작 고르기 칸은 「게임 안의 몸이 아직 없습니다」라는 안내로 대신하고, 이 「3D 만들기(수동)」 칸(보낼 그림, 받은 모델 넣기, 폴더 열기, 돌려 보기)은 그대로 씁니다. 돌려 보기는 받은 glb 파일만으로 됩니다.
- 작업 폴더는 환경 변수 `MOIRA_WORK_ROOT`, 없으면 `D:/Project/witch-moira-work`입니다. 찾지 못하면 「작업 폴더를 찾지 못함」이 뜹니다.
- 손으로 하는 순서(접힘, 화면에도 같은 글): 여러 면으로 만들기에서 front·back·left 칸에 그림을 넣고 오른쪽 칸은 비움 → 쿼드, 면 수 20000~25000, 비공개 → 내보내기 전에 돌려서 확인(땋은 머리가 목덜미에서 시작하는가, 등에 머리 덩어리가 없는가, 치마·다리 사이가 막히지 않았는가, 머리핀이 한쪽에 하나인가, 팔이 몸통에 붙지 않았는가) → 텍스처를 입힌 뒤 GLB로 내보내 여기에 넣기, 리깅은 아직 하지 않음 → 좌우가 뒤집혀 나오면 옆 그림을 오른쪽 칸으로 옮겨 다시.

## 스킬 시험실

왼쪽 「스킬 시험실」을 누르면 열립니다. 캐릭터를 고르고 스킬(주력·진화·강림)을 쓰는 모습과 소리를 보고 듣고, 마음에 드는 효과음을 바로 채택하는 화면입니다. 게임 창은 게임 코드 그대로이고, 판의 다른 일(자연 생성, 구역 이동, 봉인, 레벨업 창)만 꺼져 있습니다.

**쓰는 법 세 줄**

1. 캐릭터 카드에서 주력 / 진화 / 강림 단추를 누르고 「시험실 열기」를 누릅니다(처음 한 번, 15~40초). 게임 창이 옆에 뜨고 화면 위 점이 「연결됨」이 됩니다.
2. 적 배치(한 마리·무리·줄·우두머리·군중), 마리 수, 다가옴/제자리, 죽지 않음, 되풀이, 느리게, 전투 효과를 바꾸면 곧바로 창이 따라 바뀝니다. 「지금 시전」은 한 번 더 쏩니다.
3. 오른쪽 소리 칸에서 ▶로 브라우저에서 듣고, 「끼우기」를 누르면 게임 창이 그 후보 소리로 울립니다(저장소는 안 바뀜). 마음에 들면 「채택」 → 확인 창의 쓸 파일을 읽고 확인합니다. 채택은 저장소 파일을 고치므로 **커밋은 회귀를 돌린 뒤 따로** 합니다. 잘못 골랐으면 「채택 취소」.

**영상으로 보기**(PC 앞이 아닐 때, 창을 띄우지 않고)

- 「지금 소리로 영상 찍기」 또는 후보 줄의 「이 소리로 영상」을 누르면 PC가 그 장면을 소리가 든 4초 영상(mp4)으로 찍어 화면 아래에 올립니다. 영상 A(지금 소리)와 B(고른 후보)를 나란히 두고 번갈아 들어 봅니다.
- 한 편에 보통 20~40초 걸립니다(이 PC에서 잰 값이며 약속이 아닙니다). 한 번에 한 편씩 찍고 대기는 최대 5개입니다. 화면에 「대기 중 — 앞에 n개」, 「찍는 중 n초」와 진행 막대가 나옵니다.
- 같은 장면·같은 소리는 다시 찍지 않고 찍어 둔 것을 씁니다. 소리 표나 효과 코드가 바뀐 뒤에는 옛 영상에 「낡음」이 붙고 「다시 찍기」를 누를 수 있습니다. 영상은 `_local/skill-lab/clips/`에 2 GB까지 쌓입니다.
- 영상에는 게임의 화면 표시(체력 구슬, 스킬 줄)가 그대로 들어갑니다. 소리는 게임 엔진이 실제로 낸 소리입니다. 영상 찍기가 실패하면(드물게 Godot가 죽음) 한 번 저절로 다시 하고, 그래도 안 되면 까닭이 화면에 나옵니다(전체 출력은 `_local/skill-lab/clips/last-shoot.log`).

**알아 둘 점**

- 소리 후보는 `_local/audio/**/lab-candidates.json`을 모두 읽습니다. 소리 표에 자리가 있는 후보는 끼우기·채택이 되고, 「자리 없음」 후보(드랍·전투·UI 소리 등)는 듣기만 됩니다(묶음별로 접혀 있음).
- 번개 시전 자리는 지금 일반 실행에서 무음입니다. 채택하면 울리기 시작하므로 확인 창이 그렇게 알려 줍니다.
- 「느리게」는 게임 속도를 늦추고 소리의 높낮이는 바꾸지 않습니다. 0.25배는 움직임이 끊겨 보일 수 있습니다.
- 3D 주인공 모델 체크를 바꾸면 창을 다시 띄웁니다.
- 시험 창은 60분 동안 명령이 없으면 스스로 닫힙니다. 「닫기」로 닫아도 됩니다.
- 그림 자리(화면 그림을 넣을 곳): ① 창과 이어진 페이지 전체, ② 소리 후보 줄과 채택 확인 창, ③ 영상 A·B 나란히. 캡처는 `_local/shots/skill-lab-live/`.

## 원격 접속(휴대폰·밖에서 쓰기)

집 밖에서 휴대폰이나 노트북 브라우저로 이 제작실을 보려면 **Cloudflare Tunnel + Cloudflare Access**를 씁니다. 서버와 Godot는 계속 이 PC에서 돌고, 인터넷으로는 화면·JSON·짧은 영상만 나갑니다. 서버는 끝까지 `127.0.0.1`에만 열려 있고 공유기 포트는 열지 않습니다.

**지킬 것**: 인증 없는 임시 터널(`trycloudflare.com` 주소만 받는 것), 서버를 `0.0.0.0`으로 여는 것, 공유기 포트 열기는 하지 않습니다. 이 도구에는 파일을 쓰고 프로그램을 띄우는 단추가 있어서, 인증 없이 인터넷에 열리면 PC를 남에게 넘기는 것과 같습니다.

### 공식 문서로 확인한 것(2026-11-23, developers.cloudflare.com)

| 물음 | 확인한 답 |
|---|---|
| 이름 있는 터널로 내 주소(`moira.<도메인>`)를 내보내는 데 Cloudflare에 올린 도메인이 꼭 필요한가 | **필요합니다.** 「터널 만들기(대시보드)」 문서는 응용을 내보내기 전에 "add a website to Cloudflare"를 요구하고, 「자체 호스팅 응용 공개」 문서의 사전 조건이 "An active domain on Cloudflare"입니다. 도메인이 없으면 Cloudflare에서 사거나(비용은 확인 못 함) 가진 도메인을 Cloudflare에 추가해야 합니다. |
| 도메인 없이 되는 길은 | Quick Tunnel(`cloudflared tunnel --url http://localhost:8781 --allowed-mail 내이메일`)은 계정·도메인 없이 임시 주소를 주고 이메일 일회 코드를 요구합니다(문서 확인). 하지만 이 길의 요청에 Access 토큰 머리글(`Cf-Access-Jwt-Assertion`)이 붙는지 문서에 없어 **확인 못 함**입니다. 이 서버는 그 토큰이 없으면 원격 요청을 거절하므로, 이 길은 지원하지 않습니다. 주소도 켤 때마다 바뀝니다. |
| Access 무료 한도와 이메일 일회 코드 | 무료 플랜(Zero Trust Free)이 있고 결제 정보 입력은 필요하지만 청구되지 않는다고 문서에 있습니다. 이메일 일회 코드(One-time PIN)는 지원됩니다. **무료 플랜의 사용자 수 상한은 확인 못 함**(계정 한도 문서에 없고 요금 페이지는 스크립트로 그려져 읽지 못함). 본인 한 명이라 걸릴 가능성은 낮습니다. |
| 일회 코드는 자동으로 켜지나 | **아닙니다.** 새 Zero Trust 조직은 기본 로그인이 「Cloudflare 계정 로그인」이고, 일회 코드는 자동으로 더해지지 않습니다. Integrations → Identity providers → Add new identity provider → One-time PIN으로 직접 더합니다. 코드는 한 번만 쓸 수 있고 10분 뒤 만료되며, 메일 보안 도구가 링크를 먼저 눌러 "이미 사용됨"이 뜨면 새 코드를 요청합니다. |
| cloudflared의 winget 패키지 이름 | `Cloudflare.cloudflared`. 이 PC에서 `winget search cloudflared`로 이름만 확인했습니다(설치하지 않음). Windows에서는 자동 업데이트가 되지 않아 가끔 손으로 올려야 합니다(문서). |
| Access가 붙이는 머리글과 인증서 주소 | 머리글 `Cf-Access-Jwt-Assertion`(브라우저 쿠키 `CF_Authorization`도 있으나 문서는 머리글을 권함). 공개 키는 `https://<팀 이름>.cloudflareaccess.com/cdn-cgi/access/certs`의 `keys`(JWK, RSA, RS256). 토큰의 `kid`로 키를 고릅니다. 키는 6주마다 돌고 이전 키는 7일 더 유효합니다. 확인할 값: `iss` = `https://<팀 이름>.cloudflareaccess.com`, `aud`에 응용의 AUD 태그, `exp`가 미래, `nbf`가 미래가 아님. 이 서버가 이것을 모두 검사합니다. |
| cloudflared가 원본에 보내는 Host | 원본 매개변수 `httpHostHeader`의 기본값이 빈 값(덮어쓰지 않음)이라, 서버가 받는 Host는 공개 이름(`moira.<도메인>`)입니다. 이 칸을 건드리지 마세요. |

### 사용자가 할 일의 차례(우리가 대신 못 함: 계정·결제·도메인이 걸림)

1. **도메인 준비**: Cloudflare 계정(2단계 인증 켜기)에 도메인이 있어야 합니다. 없으면 Cloudflare에서 사거나 가진 도메인을 Cloudflare에 추가하고 이름 서버를 바꿉니다. 이 도메인 아래 `moira.<도메인>` 같은 이름을 쓸 것입니다.
2. **Zero Trust 조직 만들기**: Cloudflare 대시보드 → Zero Trust → 팀 이름(`<팀>.cloudflareaccess.com`의 앞부분)을 정하고 Free 플랜을 고릅니다.
3. **일회 코드 켜기**: Zero Trust → Integrations → Identity providers → Add new identity provider → One-time PIN.
4. **터널 만들기**(대시보드 방식): Networking → Tunnels → Create a tunnel. 이름은 `moira-manager` 같은 것으로. 화면이 보여 주는 **토큰**을 이 PC의 `tools/manager/local-remote.token` 파일에 한 줄로 저장합니다(git 밖에 있는 파일 이름입니다. 토큰은 비밀입니다).
5. **cloudflared 설치**: PowerShell에서
   ```
   winget install --id Cloudflare.cloudflared
   cloudflared --version
   ```
6. **공개 주소 연결**: 방금 만든 터널의 Routes → Add route → Published application. 서브도메인 `moira`, 도메인 선택, 서비스 URL은 `http://127.0.0.1:8781`(서버를 다른 포트로 열면 그 포트). 「HTTP Host Header」 칸은 비워 둡니다.
7. **Access 응용 만들기**: Zero Trust → Access controls → Applications → Create new application → Self-hosted and private → Add public hostname(`moira.<도메인>`). 정책은 **Allow, 내 이메일 하나만**(로그인 방법은 One-time PIN). 세션 길이는 24시간을 권합니다. 만든 뒤 응용의 **AUD 태그**(Additional settings)를 복사합니다.
8. **설정 파일 만들기**: `tools/manager/local-remote.json`(git 밖. 예시는 아래)에 호스트 이름, 팀 도메인, AUD 태그, 내 이메일을 넣습니다. 처음에는 `"enabled": false`로 두고 8781 서버를 다시 켭니다.
9. **켜기**: `enabled`를 `true`로 고치고(서버를 다시 켤 필요 없음) 터널을 켭니다.
   ```
   powershell -File tools/manager/remote.ps1 status
   powershell -File tools/manager/remote.ps1 start
   ```
   끄려면 `powershell -File tools/manager/remote.ps1 stop`(터널만 내립니다. 서버는 그대로). 두 겹의 스위치입니다: 터널이 떠 있어도 `enabled`가 `false`면 서버가 원격 요청을 모두 403으로 거절합니다.
10. 휴대폰 브라우저에서 `https://moira.<도메인>`을 엽니다. 이메일 일회 코드를 받아 입력하면 들어옵니다.

`tools/manager/local-remote.json` 예시(값은 자기 것으로. 이 파일과 `local-remote.token`은 git에 올라가지 않습니다):

```json
{
  "enabled": false,
  "hosts": ["moira.<도메인>"],
  "access": { "team_domain": "<팀 이름>.cloudflareaccess.com", "aud": "<AUD 태그>", "emails": ["내 이메일"] },
  "remote_allows": ["view", "skill_lab.scene", "skill_lab.clip", "skill_lab.adopt", "picks", "notes"],
  "tunnel": { "token_file": "tools/manager/local-remote.token" }
}
```

### 원격에서 되는 것과 안 되는 것

- 되는 것(`remote_allows`로 줄일 수 있음): 보기 전부, 스킬 시험실의 장면 고르기·영상 찍기·채택(영상은 PC가 찍어 올립니다), 고름과 메모.
- 원격에서 **언제나 막히는 것**: PC 탐색기 열기, 파일 올려받기(3D 만들기), 균형 실험실·점검 실행, 시험 창 띄우기와 창 화면 저장, 코드·문서 원문 보기(그림·소리·영상·3D 모델 파일만 보임), 원격 설정 화면. 모르는 경로는 원격에서 모두 거절합니다.
- 서버는 요청마다 Access 토큰의 서명, 응용(`aud`), 발급자(`iss`), 만료, 이메일을 검사하고 하나라도 틀리면 거절합니다. 인증서를 받지 못해도 거절합니다.
- 원격 접속은 `_local/manager/remote-access.log`에 한 줄씩 남습니다(시각, 이메일, 방법, 경로, 결과. 토큰은 남기지 않음). 원격에서 한 채택의 고름 기록에는 `user(remote:<이메일>)`가 적힙니다.
- PC 앞 화면 머리에 「원격 켜짐/꺼짐」과 마지막 원격 접속(이메일, 시각)이 나옵니다(PC 앞에서만 보임).
- PC가 꺼져 있으면 접속되지 않습니다.
- 확인 못 한 것: 실제 Cloudflare와의 연결(이 도구는 Cloudflare에 접속하지 않고 가짜 토큰으로만 검사했습니다). 처음 연결한 날 한 번 직접 확인하세요.
