# 마녀 모이라 제작실 사용 안내

게임에 지금 무엇이 들어 있는지 한눈에 보고, 항목마다 내 메모를 남기는 도구입니다. 게임 수치와 플레이 저장은 바꾸지 않습니다.

## 여는 방법

1. 터미널을 `C:\Project\witch-moira`에서 열고 아래를 실행합니다. 서버는 이 컴퓨터에서만 열립니다(127.0.0.1).

   ```
   C:/Users/twins/AppData/Local/Programs/Python/Python310/python.exe tools/manager/server.py --port 8781
   ```
2. 브라우저에서 http://127.0.0.1:8781/ 을 엽니다.
3. 끝낼 때는 터미널에서 Ctrl+C를 누릅니다.

8781번이 이미 쓰이고 있으면(옛 제작실이 떠 있는 경우 등) `--port 8791`처럼 다른 번호로 열고 주소도 맞춥니다.

## 화면

- 왼쪽: 분류. 한 판의 기술과 은총 / 영구 성장 / 전투 수치 / 장비 / 구역과 의식 / 주인공 원화 / 3D 모델 / 그림·아이콘 / 소리 / 코드 구성 / 문서 / 품질 목표.
- 가운데: 항목 목록. 검색, 내 메모 상태, 「게임에서 쓰임」으로 거를 수 있습니다.
- 오른쪽: 고른 항목의 내용. 수치 표, 미리보기(그림, 소리 재생, 3D 모델), 출처 문서, 내 메모.
- 영구 성장 효과 문구는 게임 화면과 같은 표기입니다.

## 「게임에서 쓰이나」 읽는 법

그림·소리·모델에 붙습니다. 게임의 시작 장면에서 파일 경로를 글자로 따라가 본 결과입니다.

- 코드가 파일을 직접 가리킴: 확실히 읽힘.
- 코드가 폴더와 이름을 조합해 읽음: 폴더째 읽는 곳이며 파일 이름이 코드에 나옴.
- 읽는 폴더 안에 있으나 이름 확인 못 함: 읽힐 수도, 보관용일 수도 있음.
- 실행 경로에서 참조를 찾지 못함: 쓰지 않는다는 확정은 아닙니다. 모델에 포함됐거나 원본 보관용일 수 있습니다.

## 메모 남기기

항목을 고르고 오른쪽 아래 「내 메모」에서 상태, 우선순위, 메모를 적고 「메모 저장」을 누릅니다.

- 「완료(메모)」는 내 표시이며 품질 검수를 통과했다는 뜻이 아닙니다.
- 메모는 `tools/manager/local-state.json`에 저장되고 git에는 올라가지 않습니다. 이 파일은 지우거나 덮어쓰지 마세요.
- 다른 창에서 먼저 저장했으면 「다른 곳에서 먼저 저장되었습니다」가 뜹니다. 쓰던 메모는 그대로 있으니 확인하고 다시 저장하면 됩니다.

## 균형 실험실

왼쪽 「균형 실험실」을 누르면 열립니다. 균형 시뮬레이터(`tools/dev/balance_sim.py`)에 스킬 값과 적(리듬) 값을 바꿔 넣고 결과를 바로 봅니다. **모델의 답이며 게임의 답이 아닙니다.** 서열(어느 찍는 방식이 더 센가)과 값을 바꿨을 때의 방향은 믿어도 되지만, 정확한 승률과 초 단위 시각은 믿지 마세요. 마지막 확인은 실제 게임 코어로 합니다.

- 왼쪽에서 고릅니다: 주문 묶음 파일, 프리셋, 스킬별 값, 적 값, 모델 상수, 찍는 방식, 마녀, 판 수, 장비 묶음. 숫자 칸을 고치면 줄이 노랗게 바뀌고 「원래」 값이 옆에 남습니다. ↺은 되돌리기입니다.
- 「실행」을 누르면 몇 초~수십 초 걸립니다(찍는 방식 12 × 마녀 3 × 10판이 약 15초). 동시에 하나만 돌고, 150초를 넘기면 멈춥니다.
- 오른쪽 맨 위 큰 줄이 서열 판정입니다. 아래에 찍는 방식 × 마녀 승률(칸 색이 초록이면 목표 범위 안, 주황이면 밖), 시너지와 하나만 쌓기의 차, 종류별 평균, 마디별 힘 ÷ 위협, 죽는 마디와 원인, 정체 수가 나옵니다. ▲▼은 직전 실행과의 차입니다.
- 「실험으로 저장」은 바꾼 값과 결과 요약을 `_local/balance-lab/experiments/`에 남깁니다. 둘을 골라 「나란히 견주기」를 누르면 값과 승률의 차를 볼 수 있습니다. 「값 불러오기」는 그 실험의 값을 왼쪽에 되돌립니다.
- 「내보내기」는 `--set` 묶음 JSON을 `_local/balance-lab/exports/`에 쓰고 내려받게 합니다. **게임 데이터 파일은 이 화면이 절대 고치지 않습니다.** 마음에 드는 값은 이 파일을 총괄에게 넘겨 데이터 반영을 따로 맡기세요.
- 이름을 모르는 값을 시뮬레이터가 새로 내놓으면 「그 밖에 시뮬레이터가 내놓은 값」에 그대로 보입니다. 모델 상수의 출처(fit 실측에 맞춤 / spec 명세 / hypo 가설 / guess 추정)는 왼쪽 4번에 적혀 있습니다.

## 캐릭터

왼쪽 「캐릭터」를 누르면 열립니다. 게임을 띄우지 않고 주인공 몸의 걸음을 두 칸에 나란히 돌려 보고, 걸음 값을 고르는 화면입니다. 3D는 이 폴더에 들어 있는 three.js로 그리며 인터넷을 쓰지 않습니다.

- 주인공 몸 파일은 저장소에 올라가지 않아서(`chapter1/art/actors/hero/`는 git 밖) 몸 파일이 없는 작업 폴더에서는 줄이 「몸 없음」으로 나옵니다.
- 칸마다 클립(run, walk 등)과 **동작 배율**을 고릅니다. 배율은 클립을 원래 속도의 몇 배로 돌리는가입니다. 이동 속도 막대는 두 칸에 같이 적용됩니다. 바닥이 그 속도로 뒤로 흐르고, 디딘 발이 남기는 점이 한 곳에 모이면 미끄러지지 않는 것이고 길게 끌리면 미끄러지는 것입니다.
- 수치 띠: 동작 배율, 주기 길이, 보폭 계약 값, **계산 미끄러짐**(공식, 모델의 답), **측정 미끄러짐**(이 화면 안에서 발끝 뼈로 잰 값, 디딤 구간의 땅 기준 속도 RMS), 미끄럼 없는 배율. 지면 속도는 몸 보고서(`model.pack-report.json`)의 값이며 ±6% 어긋날 수 있습니다. 게임 안에서 잰 값이 아닙니다.
- 「미끄럼 없는 배율로」는 지금 이동 속도에서 발이 미끄러지지 않는 배율로 막대를 옮깁니다. 「게임 지금 값」은 자리표에 적힌 달리기 값입니다.
- 이동 속도는 게임 값(`chapter1/core/combat_core.gd`의 `BASE_SPEED`, 글로 읽음)과 다르게 움직여도 됩니다. 다르면 「제안으로만 저장됩니다」가 뜨고, 게임 속도는 전투 균형이라 이 화면으로는 바뀌지 않습니다.
- 카메라: 「게임 19.5」는 게임 코드의 값, 「게임 14」는 사용자 결정을 기다리는 후보입니다. 「1080p 크기」를 켜면 1080 높이 화면에서 주인공이 차지할 화소 높이를 보입니다. 「자유」는 돌려 보기입니다. 「겉모습 반영(근사)」은 `hero.json`의 look을 흉내 낸 것이라 게임과 색이 같지 않습니다.
- 「고르기」: 칸마다 이걸로 / 아님 / 보류와 한 줄 말을 정하고 「저장」을 누르면 `tools/manager/local-picks.json`에 쌓입니다(git 밖, 지우거나 덮어쓰지 마세요). 디렉터가 `python tools/manager/picks.py list --open`으로 읽고, 고른 값은 에이전트가 `tools/art/motion_apply.py`로 게임 자리표에 옮깁니다. 저장해도 게임에는 바로 들어가지 않습니다.
- 「이 화면 주소 복사」로 지금 상태(클립, 배율, 이동 속도, 카메라)를 담은 주소를 얻습니다. 예: `#character/frost?a=run&b=walk@1.3&v=5.8&cam=19.5`.
- 자리표의 `pose.run_time_scale`은 이름과 달리 배율이 아니라 **걸음 한 주기의 길이(초)** 입니다. 게임의 동작 배율은 이동 속도 × 주기 길이 ÷ `pose.stride_world_m`으로 나옵니다.

### 3D 만들기(수동)

캐릭터 화면 아래쪽의 접힌 칸 「3D 만들기(수동)」입니다. Tripo에서 사람이 손으로 모델을 만들 때, 보낼 그림을 찾고 받은 모델을 넣어 두고 돌려 보는 곳입니다. 이 화면은 Tripo에 아무것도 보내지 않습니다.

- **보낼 그림**: 작업 폴더의 `pipeline/<캐릭터>/tripo_in/` 안 `.png`를 작게 보입니다. 파일 이름과 화소 크기가 같이 나옵니다. 「내려받기」는 브라우저 저장, 「경로 복사」는 파일 경로를 클립보드로, 「폴더 열기」는 이 컴퓨터의 탐색기로 폴더를 엽니다(폴더가 없으면 만들지 않고 「없음」이라고 답합니다). 폴더가 비어 있으면 시트 한 장을 나누는 명령(`tools/art/sheet_split.py … --names front,left,back --square`)이 보입니다. 화면이 그 명령을 실행하지는 않습니다.
- **받은 모델 넣기**: Tripo에서 내보낸 `.glb`를 점선 칸에 끌어다 놓거나 눌러서 고릅니다. `pipeline/<캐릭터>/tripo_out/<날짜-시각>_<이름>.glb`로 저장되고(이름은 영문·숫자·`-`·`_`만 남김), 같은 이름이 있어도 덮어쓰지 않으며, glb가 아닌 파일(머리 4글자 `glTF` 검사)과 300 MB를 넘는 파일은 거절합니다. 목록에는 크기, 받은 때, glb 머리에서 읽은 삼각형 수·질감·뼈대 유무가 나옵니다. 이 칸에는 지우기 단추가 없습니다. 지우는 것은 탐색기에서 합니다. 저장소 안(`chapter1/` 등)에는 아무것도 쓰지 않습니다.
- **돌려 보기**: 목록의 「돌려 보기」는 그 모델을 동작 없이 선 자세로, 바닥 격자 위에서 돌려 보게 합니다. 높이를 2로 맞춰 보이므로 실제 크기가 아닙니다. 바로 가는 주소에 `&tripo=<파일 이름>`을 붙이면 그 모델을 바로 엽니다.
- 작업 폴더는 환경 변수 `MOIRA_WORK_ROOT`, 없으면 `D:/Project/witch-moira-work`입니다. 찾지 못하면 「작업 폴더를 찾지 못함」이 뜹니다.
- 손으로 하는 순서(접힘, 화면에도 같은 글): 여러 면으로 만들기에서 front·back·left 칸에 그림을 넣고 오른쪽 칸은 비움 → 쿼드, 면 수 20000~25000, 비공개 → 내보내기 전에 돌려서 확인(땋은 머리가 목덜미에서 시작하는가, 등에 머리 덩어리가 없는가, 치마·다리 사이가 막히지 않았는가, 머리핀이 한쪽에 하나인가, 팔이 몸통에 붙지 않았는가) → 텍스처를 입힌 뒤 GLB로 내보내 여기에 넣기, 리깅은 아직 하지 않음 → 좌우가 뒤집혀 나오면 옆 그림을 오른쪽 칸으로 옮겨 다시.

## 게임 파일을 고친 뒤

왼쪽 아래 「게임 폴더 다시 읽기」를 누르면 서버를 다시 켜지 않아도 새 내용이 반영됩니다.

## 알아 둘 점

- 품질 목표는 `docs/QUALITY-TARGETS.ko.md`에 적힌 값을 그대로 보여 줍니다. 이 도구가 직접 잰 값이 아닙니다.
- 예전 제작실 메모는 항목 번호가 달라 옮기지 않았습니다. 참고용 사본이 `_local/manager-old-local-state.json`에 있습니다.
- 3D 모델은 「3D 모델 불러오기」를 눌러야 뜹니다. 인터넷 연결은 쓰지 않습니다.
